  1. STEP 1 · START HERE

    Open Policy Agent. (OPA) Intro & Deep Dive

    Sebastian Spaink, Johan Fylling

    Why this stop

    0:53 Spaink describes the problem OPA targets: policy scattered across enforcement points owned by different teams, so nobody can easily answer what the policy is.

    More moments to jump to

    8:42 Fylling shows the new or keyword for inline disjunction, while still recommending helper rules to keep large logical expressions maintainable.

    12:33 Fylling explains the pitfall where a not expression over an undefined input value stopped the whole rule, and how the compiler now wraps negations in closures.

    17:14 Fylling says a Rego v2 import enables the new syntax per module, ahead of an OPA 2.0 release the team plans for next year.

    All five moments and talk notes →

  2. STEP 2 · NEXT

    RBAC as a Platform Capability: Applying Platform Engineering to Kubernetes Access

    Sean Corcoran, Erin Walter

    Why this stop

    9:07 The speakers distinguish the resource that declares namespace configuration from the resource that declares who should have access and what permissions they receive.

    More moments to jump to

    6:08 The speakers describe how chained pull requests repeated validations and then waited for a scheduled job to apply each change.

    11:38 The speakers walk through how the controller resolves a namespace reference and creates the corresponding role binding in the target cluster.

    19:07 The speakers describe dry-run reconciliation that writes the generated manifest to resource status so they can inspect it before applying it downstream.

    All five moments and talk notes →

  3. STEP 3 · NEXT

    Why Your Monitoring Stack is a Security Risk

    Vinayak Goyal, Graham Helton

    Why this stop

    4:15 The speakers warn that a role granted for a simple health check can also authorize far more sensitive kubelet operations.

    More moments to jump to

    1:09 The speakers explain that the kubelet first establishes the caller's identity and then asks the Kubernetes API server whether the caller may access the requested resource.

    9:30 The speakers say API server audit logs may show the authorization check for direct kubelet traffic without showing the underlying action.

    16:33 The speakers recommend reviewing roles for unnecessary proxy access, adopting narrower permissions or updated vendor charts, and considering network policies as another layer.

    All five moments and talk notes →

  4. STEP 4 · GO DEEPER

    Falco Never Flies Alone: Runtime Security as an Ecosystem

    Leonardo Grasso, Alessandro Cannarella

    Why this stop

    16:35 Cannarella says Falco Operator 0.5 pulls artifacts from the registry once, serves them to every node, and checks rules against the Falco version before installing.

    More moments to jump to

    0:51 Grasso explains how Falco taps the Linux kernel with an eBPF probe or kernel module, enriches events with plugins, and matches them against YAML rules.

    3:22 Grasso lists core cleanups such as removing the legacy BPF probe and gVisor support, new list operators in the rule language, and an experimental GPU hijacking rule.

    19:55 Cannarella announces Falcosidekick version 3, rewritten with per-output pipelines, live config reloads, API and UI configuration, and a single binary.

    All five moments and talk notes →
