  1. STEP 1 · START HERE

    Choose Your Own Adventure: The Saga of Serving LLM Inference

    Whitney Lee, Viktor Farcic

    Why this stop

    11:38 Lee explains how quantizing model weights can make a model fit on a GPU or leave more memory for the cache used by active conversations.

    More moments to jump to

    3:16 Farcic starts deploying both the audience's configuration and the opposite choices so the two inference setups can be compared.

    16:41 Lee compares replicating the whole model on multiple GPUs with sharding it across GPUs and explains why separate replica caches affect routing.

    24:06 Lee explains how speculative decoding drafts several tokens ahead and how the model checks the guesses before accepting them.

    All five moments and talk notes →

  2. STEP 2 · NEXT

    llm-d 1.0 Production-Grade Inference for Cloud-Native AI

    Carlos Costa, Robert Shaw

    Why this stop

    1:44 The speakers frame inference scaling as an orchestration problem involving cache reuse, independent scaling of prefill and decode, and workloads spread across multiple pods.

    More moments to jump to

    3:11 The speakers explain that llm-d builds on Kubernetes interfaces, using an inference gateway for cache-aware routing and LeaderWorkerSet for multi-pod workloads.

    13:19 The speakers describe llm-d version 1 as adding a stable API, priority and fairness for competing tenants, and a highly available router with coordinated prefill and decode rollouts.

    17:21 In the recorded demo, the speakers report nearly doubling throughput after enabling cache-aware routing, then show how enabling flow control splits traffic into three queues.

    All five moments and talk notes →

  3. STEP 3 · NEXT

    Cache Me If You Can: LLM Inference with llm-d (with fun drawings)

    Alexa Griffith

    Why this stop

    4:10 Griffith walks one request through llm-d's filter, score, and pick sequence, explaining how the router estimates which pods already hold a matching prefix.

    More moments to jump to

    8:43 Griffith says offloading the key-value cache to CPU memory can avoid recomputing it for long-lived requests, at the cost of slower access.

    9:13 Griffith describes splitting prompt processing from token generation and notes that the two stages then have to transfer cached state.

    14:07 Griffith explains how priority bands choose which class goes first and how separate fairness and ordering policies govern work within a band.

    All five moments and talk notes →

  4. STEP 4 · GO DEEPER

    Observability for LLM Inference on Kubernetes

    Oscar Castillo, Jeffry Hernández

    Why this stop

    13:59 The speakers use a Grafana dashboard to show why a busy GPU reading can be misleading when the inference server's KV cache is far from full.

    More moments to jump to

    1:43 The speakers distinguish prefill from iterative decode and introduce time to first token and time per output token as ways to observe those stages.

    4:52 The speakers compare their client-side timing with the provider dashboard and explain why network hops and client processing can make the end-to-end delay longer.

    17:04 The speakers inspect a failed trace from an empty model response and show how a trace ID can connect the request to logs from Envoy and the inference scheduler.

    All five moments and talk notes →
