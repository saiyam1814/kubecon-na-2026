    New Traffic, New Rules: Standardizing AI-Aware Networking in Kubernetes

    Nir Rozenbaum, Keith Mattix

    Nir Rozenbaum and Keith Mattix present the proposals the Kubernetes AI Gateway Working Group has been developing for Gateway API: pre-routing filters for payload processing, a Backend resource, an endpoint selector, gateway routability and a multi-stage route. They explain the AI traffic cases behind each one, such as routing on the model name in the request body and calling external model providers, and say next steps include external processing, token-based rate limiting and consolidating AI networking efforts in SIG Network.

    30 min slot · Level not listed · Session

    Networking and connectivityAI inference and serving

    Watch this if: you build or operate gateways for inference or agent traffic and want to know which Gateway API additions the AI Gateway Working Group is proposing.

    1. 4:09 Nir Rozenbaum introduces pre-routing filters, an ordered list of filters that run before a route is selected, which he says is already experimental and lets a gateway promote the model name from the request body to a header for body-based routing.
    2. 7:46 Keith Mattix argues that the Kubernetes Service resource does two jobs, a producer-oriented front end with a DNS name and cluster IP and a consumer-oriented bag of endpoints, and that AI traffic to external model providers has made the limits more urgent.
    3. 12:56 He describes the Backend resource, now experimental in Gateway API, which holds an in-cluster endpoint selector or an external hostname plus TLS and protocol settings, and says it is not a full replacement for Service.
