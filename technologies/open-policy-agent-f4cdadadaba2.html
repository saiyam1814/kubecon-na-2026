    Compliance Drift on Kubernetes: Building Proof Infrastructure for AI Agents in Regulated Industries

    Saideep Navakoti

    Saideep Navakoti presents ACRA, a Kubernetes proof workflow intended to detect changes in AI-agent behavior and make the resulting investigations auditable. He shows how the demo displays investigation tickets and describes how auditors could query evidence drawn from traces.

    25 min slot · Intermediate · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You need to show auditors what an AI agent was approved to do and what it actually did.

    1. 7:55 Navakoti explains that Kyverno checks pod admission and OpenTelemetry records traces, but argues that neither alone tells an operator whether an agent's behavior has drifted.
    2. 9:32 He introduces ACRA's API server, controller, and gate, then explains how its contract evaluator checks agent behavior against a declared baseline.
    3. 12:21 He shows a demo UI that calls the API to display investigation tickets, after describing how a drift event produces evidence from collected traces.
    4. 20:04 He frames drift as a reason to re-approve an agent rather than silently fix it, and walks through how a custom Kubernetes controller reports the agent's state.
    5. 21:32 He describes evidence an auditor can query for a specific task or incident, including a telemetry graph rather than a manually maintained spreadsheet.

    From Black-Box to Auditable AI-Grid: A Deterministic Governance Layer with Hybrid Cloud

    Fatih E. Nar, Andrew Hendrickson

    The speakers outline a governance layer for AI recommendations in communication networks that makes the decision process auditable without requiring identical model wording. They describe how versioned evidence, policy gates, and energy measurements could feed into decisions about network operations.

    30 min slot · Beginner · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you need to explain what evidence and policy allowed an AI-assisted decision in a regulated network.

    1. 4:58 Hendrickson says fixing the input, rule version, and evidence snapshot should make it possible to reconstruct the rules, evidence, and citations behind a decision.
    2. 10:33 Nar distinguishes using AI to improve network operations from using network infrastructure to host new AI workloads.
    3. 14:35 Nar walks through classifying intent, retrieving evidence, constraining reasoning with rules, synthesizing a result, and blocking an action if there is no supporting citation.
    4. 20:19 Nar cites Open Policy Agent and Kyverno for policy and describes using Git to keep track of models, rules, and standards.
    5. 24:19 Nar proposes using Kepler to measure power at host, platform, and workload levels so operators can weigh power use against service commitments.

    Open Policy Agent. (OPA) Intro & Deep Dive

    Sebastian Spaink, Johan Fylling

    Sebastian Spaink and Johan Fylling introduce Open Policy Agent as a general-purpose policy engine and Rego as its declarative policy language. They then cover this year's Rego changes, new Java and Swift evaluators built on OPA's intermediate representation, runtime improvements, and updates from Gatekeeper, opa-java-wasm and Conftest.

    30 min slot · Level not listed · Session

    Security, identity and policy

    Watch this if: you write Rego policies and want to know about the new and, or and not semantics and the coming Rego v2.

    1. 0:53 Spaink describes the problem OPA targets: policy scattered across enforcement points owned by different teams, so nobody can easily answer what the policy is.
    2. 8:42 Fylling shows the new or keyword for inline disjunction, while still recommending helper rules to keep large logical expressions maintainable.
    3. 12:33 Fylling explains the pitfall where a not expression over an undefined input value stopped the whole rule, and how the compiler now wraps negations in closures.
    4. 17:14 Fylling says a Rego v2 import enables the new syntax per module, ahead of an OPA 2.0 release the team plans for next year.
    5. 20:06 Fylling presents Java and Swift evaluators that run OPA's intermediate representation inside applications as libraries, with bundle management and decision logging.

    Stop AI Agents from Guessing SQL with Semantic Operator on Kubernetes

    Manabu McCloskey

    The speaker introduces Semantic Operator, a new project that lets teams define business metrics in the Apache Ossie format as Kubernetes resources so agents request metrics and never write SQL. He says the operator runs the queries on StarRocks or Trino, has built-in governance, and is in its early days and looking for contributors.

    5 min slot · Level not listed · Session

    Unclassified

    Watch this if: You build agents or BI tools that answer questions from company databases and want them to stop producing wrong SQL.

    1. 0:32 The speaker says a benchmark of 90 prompts gave 28 wrong answers when an agent was asked about business metrics.
    2. 1:09 The speaker says the Apache Ossie spec is vendor neutral and is applied to the Kubernetes cluster, where the operator runs the query for the agent.
    3. 1:40 The speaker says the execution engine can be StarRocks or Trino right now and that adding new engines is easy enough.
    4. 2:43 The speaker says agents never write the SQL queries and only look at the metrics that are available.
    5. 3:00 The speaker describes a built-in governance model for columns, rows and metrics, with Open Policy Agent and Apache Ranger integrations.

    What Can Your AI Agents Actually Do? Cedar Analysis for MCP Servers

    Lucas Käldström, Chris Burns

    Lucas Käldström and Chris Burns discuss putting authorization decisions for MCP servers in a policy engine so the rules can be analyzed separately from the application. They demonstrate how Cedar Woodpecker can flag combinations of permissions and help check a policy revision.

    30 min slot · Any Level · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you operate MCP servers and want to reason about what permissions an agent can combine.

    1. 5:56 The speakers distinguish the component that enforces an authorization decision from the external policy engine that makes it.
    2. 15:04 They explain static analysis with a question about two policies: would they make the same decision for any user and request?
    3. 19:45 Käldström introduces Cedar Woodpecker, a tool for analyzing permissions expressed in Cedar.
    4. 22:26 Burns shows a local kind cluster running ToolHive and two MCP servers as the setting for the policy demo.
    5. 26:47 They rerun the policy analysis after tightening access and report that the unwanted permission combination is ruled out under the modeled assumptions.
