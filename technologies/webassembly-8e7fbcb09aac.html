    Open Policy Agent. (OPA) Intro & Deep Dive

    Sebastian Spaink, Johan Fylling

    Sebastian Spaink and Johan Fylling introduce Open Policy Agent as a general-purpose policy engine and Rego as its declarative policy language. They then cover this year's Rego changes, new Java and Swift evaluators built on OPA's intermediate representation, runtime improvements, and updates from Gatekeeper, opa-java-wasm and Conftest.

    30 min slot · Level not listed · Session

    Security, identity and policy

    Watch this if: you write Rego policies and want to know about the new and, or and not semantics and the coming Rego v2.

    1. 0:53 Spaink describes the problem OPA targets: policy scattered across enforcement points owned by different teams, so nobody can easily answer what the policy is.
    2. 8:42 Fylling shows the new or keyword for inline disjunction, while still recommending helper rules to keep large logical expressions maintainable.
    3. 12:33 Fylling explains the pitfall where a not expression over an undefined input value stopped the whole rule, and how the compiler now wraps negations in closures.
    4. 17:14 Fylling says a Rego v2 import enables the new syntax per module, ahead of an OPA 2.0 release the team plans for next year.
    5. 20:06 Fylling presents Java and Swift evaluators that run OPA's intermediate representation inside applications as libraries, with bundle management and decision logging.

    Sandboxing on Kubernetes with WebAssembly: A Hands-on Tutorial

    Eric Gregory, Bailey Hayes

    Eric Gregory and Bailey Hayes use wasmCloud and Kubernetes to show how WebAssembly components get explicit permissions for the resources they need. In the workshop, they start with an agent that has no tools and add capabilities one at a time, then show a separate scaling benchmark.

    80 min slot · Beginner · Tutorial

    Kubernetes internals and runtimesSecurity, identity and policy

    Watch this if: You want to see a WebAssembly sandbox on Kubernetes and how to grant an agent tool only the access it needs.

    1. 6:18 The speakers explain the deny-by-default model and show where the wasmCloud operator schedules a workload onto a host pod.
    2. 23:14 The speakers introduce the workshop's scripted model and explain why it makes the effect of sandbox permissions easier to distinguish from model behavior.
    3. 37:40 The speakers build an optional Rust component and inspect the WebAssembly interfaces it imports for HTTP and filesystem access.
    4. 56:36 The speakers demonstrate a narrow GitHub integration for triaging pull requests and explain how the host plugin keeps the sign-in token out of the workload.
    5. 1:03:56 The speakers switch from the single-instance workshop to a recorded density test and explain the resource constraints they encountered while scaling on Kubernetes.

    The Easiest Path Wins: Earning Platform Adoption with DDD and Product Thinking

    Fabrizio Lazzaretti

    Fabrizio Lazzaretti of Wavestone argues that mandates make platforms serve everyone and no one, and lays out four steps for earning adoption instead. He combines a product canvas, domain-driven design techniques, Kotter's change steps and implementation advice such as offering a GUI and WebAssembly extensions.

    25 min slot · Any Level · Session

    Platform engineering and developer experience

    Watch this if: you are planning a new internal platform and want product canvas, DDD and change-management steps to earn adoption rather than mandate it.

    1. 1:41 Lazzaretti says mandates push a platform to serve everybody and turn the goal into registering more users instead of checking whether they are satisfied.
    2. 3:23 For the why, he suggests a product canvas over a long business plan: the label pitch, goals, key metrics, a specific target user group (never everybody) and how the platform is funded.
    3. 7:37 He brings in domain-driven design: domain storytelling with a business expert to agree a shared language, then event storming to find bounded contexts and where the software can be split.
    4. 14:29 On the human side he follows Kotter's eight steps for change, including a guiding coalition with a management sponsor and short-term wins from a lighthouse project.
    5. 17:03 For implementation, he says not to underestimate a GUI for getting new users started, and suggests server-side WebAssembly extensions as a sandbox where others can add features in their own language.
