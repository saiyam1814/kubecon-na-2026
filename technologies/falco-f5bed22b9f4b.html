    BurritoBot Said Let's Dance, the Platform Said No

    Whitney Lee, Michael Forrester

    Whitney Lee and Michael Forrester let the audience attack a deliberately unprotected burrito-ordering chatbot that is wired to MCP tools and runs on a Kubernetes-based internal developer platform. They then switch on Kubernetes guardrails and LLM-specific guardrails in stages and explain which control they say stopped each attack.

    30 min slot · Any Level · Session

    Security, identity and policyAI agents and automationPlatform engineering and developer experience

    Watch this if: you want to see prompt injection and tool poisoning against a chatbot on Kubernetes, and which guardrail the speakers use against each.

    1. 2:16 The speakers invite the audience to break a live BurritoBot that they say has no guardrails, warning that submitted prompts can be shown on screen.
    2. 7:29 Whitney talks the bot into revealing the fictional CEO's home address, which she says is stored in a Kubernetes secret the bot should not be able to read.
    3. 15:08 Whitney turns on the Kubernetes guardrails with one command and says it adds Kyverno, KubeArmor, RBAC and network policy, then maps each one to the attack it blocked.
    4. 19:29 Michael shows a support ticket with hidden instructions that makes the bot deploy an app, which he calls prompt injection in a trusted system, before turning on the AI guardrails.
    5. 28:21 Michael explains a poisoned get-weather MCP tool whose description makes the bot read an internal config, and says the MCP gateway's classifier removes the tool from the tool set.

    CNCF Bingo: Play, Learn, Win!!!!!!

    Michael Rishi Forrester

    Michael Forrester runs a live bingo game he calls unofficial, in which the audience marks CNCF projects on a phone card as he reads three clues per project, from broad to narrow. He works through about fifteen projects, from Kubeflow to Knative, until three attendees win, and points to flashcards he wrote covering every CNCF project.

    12 min slot · Level not listed · Session

    Community and open source adoption

    Watch this if: You are new to the CNCF landscape and want a quick, game-style pass over what about fifteen well-known projects do.

    1. 0:13 The speaker explains the game: scan a QR code for a bingo card of CNCF projects with Kubernetes as the free middle square, and long-press a square to read what the project does.
    2. 2:17 He runs a practice round with three clues that lead to Kubeflow: a machine learning platform with notebooks and pipelines, started at Google, used for MLOps on Kubernetes.
    3. 4:15 He gives clues for Open Policy Agent: a general-purpose engine that answers allow or deny, run by Gatekeeper for Kubernetes admission, with rules written in Rego.
    4. 9:20 The first attendee gets bingo after the Harbor clues, which describe a private registry that scans images for vulnerabilities.
    5. 10:50 He says the same site has flashcards for every CNCF project, and that he had to look up about a third of the projects when writing them.

    Falco Never Flies Alone: Runtime Security as an Ecosystem

    Leonardo Grasso, Alessandro Cannarella

    Leonardo Grasso and Alessandro Cannarella describe how Falco, now ten years old, spent the year consolidating its core and growing an ecosystem around it. They cover core and plugin updates, new experiments for AI coding agents, Falco Operator 0.5, and a from-scratch rewrite of Falcosidekick as version 3.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimesSecurity, identity and policy

    Watch this if: you run Falco for runtime security and want to see what changed in its core, the Falco Operator and Falcosidekick.

    1. 0:51 Grasso explains how Falco taps the Linux kernel with an eBPF probe or kernel module, enriches events with plugins, and matches them against YAML rules.
    2. 3:22 Grasso lists core cleanups such as removing the legacy BPF probe and gVisor support, new list operators in the rule language, and an experimental GPU hijacking rule.
    3. 6:38 Grasso introduces a new subproject that gives coding agents a version-pinned knowledge base and skills for contributing to the Falco code base.
    4. 16:35 Cannarella says Falco Operator 0.5 pulls artifacts from the registry once, serves them to every node, and checks rules against the Falco version before installing.
    5. 19:55 Cannarella announces Falcosidekick version 3, rewritten with per-output pipelines, live config reloads, API and UI configuration, and a single binary.

    Supply Chain, Runtime and SDLC: A Cloud Native Security Tour

    Dr. Constanze Roedig

    Constanze Roedig walks through cloud native security in three parts, the software supply chain you consume, the software development lifecycle where you build and deploy, and the runtime, naming CNCF and OpenSSF projects for each. She closes with her view that AI agents put more weight on runtime detection and on protecting and rotating secrets.

    12 min slot · Level not listed · Session

    Security, identity and policy

    Watch this if: You find cloud native security overwhelming and want a 16-minute overview of which problem each group of projects addresses.

    1. 0:40 The speaker frames the talk around three areas: the supply chain of software you consume, the software development lifecycle where you produce and deploy it, and the runtime.
    2. 3:44 She says an SBOM declares what is in your software but cannot be assumed complete, and suggests following OpenSSF recommendations on tooling.
    3. 5:51 She distinguishes a signature from an attestation, which she describes as a piece of evidence put in an envelope together with a signature, and names in-toto.
    4. 10:36 For runtime detection she contrasts signatures, which encode known adversary behavior, with anomalies, which are deviations from your own baseline, and says to combine them.
    5. 14:18 She says that with AI agents there are vulnerabilities with no patches available, which in her view puts the spotlight on runtime detection and on short-lived, rotatable secrets.

    Zero-Trust Telemetry: Stopping AI-Powered Poisoning Attacks on Observability Pipelines

    Chad M. Crowell, Diana Todea

    Chad M. Crowell and Diana Todea describe why telemetry should be treated as untrusted input when it feeds automated decisions. They propose independent controls for transport, query access, and network policy, then discuss how to verify those controls in Kubernetes.

    30 min slot · Advanced · Session

    Observability and reliabilitySecurity, identity and policy

    Watch this if: telemetry drives automated responses and you want to limit what each source and consumer can do.

    1. 13:37 The speakers describe using mutual TLS between OpenTelemetry Collectors and backends, and explain that verifying the sender does not verify that the data is true.
    2. 16:43 They propose checking the identity and scope of human and agent queries with fine-grained role-based access, then logging those decisions for audit.
    3. 20:02 They recommend default-deny network policies for the telemetry namespace, with explicit allowances for the application-to-collector and collector-to-backend flows.
    4. 22:42 They describe using Falco with Kubernetes audit events to detect suspicious activity, complementing the communication limits from network policy.
    5. 23:54 They recommend validating which sources feed Prometheus federation and restricting who can reach federation endpoints and exporters.
