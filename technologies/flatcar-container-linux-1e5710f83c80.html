    Extending the Immutable OS: Adding Tools to Flatcar with Systemd-Sysext

    Jan Bronicki

    Jan Bronicki, a Flatcar Container Linux maintainer, explains that an immutable OS has no package manager for adding software to the read-only /usr. He describes systemd-sysext as a signed, verifiable overlay on /usr for things like GPU drivers or Kubernetes binaries, and shows how it is declared in Butane.

    5 min slot · Level not listed · Lightning Talk

    Kubernetes internals and runtimesDelivery, GitOps and release safety

    Watch this if: You run or are considering an immutable node OS and wonder how to add drivers or debugging tools to it.

    1. 0:46 Jan Bronicki says the core of an immutable OS, such as /usr, cannot be changed and is verifiable, meaning the kernel can check whether someone tampered with it.
    2. 1:19 He says package managers such as apt or dnf do not exist on such a system, which raises the question of how to get your software onto it.
    3. 1:48 He says systemd-sysext creates an overlay on top of /usr to add a particular runtime version, a GPU driver or anything else needed.
    4. 2:48 He says the key part is that a sysext is not a random blob of binaries: it plugs into the immutability and verification system, so tampering would not go unnoticed.
    5. 3:13 He shows a Butane config that declares which sysext version to fetch from where, says offline sources work, and says the binary is linked into /usr at boot.

    Flatcar Container Linux: Growing the Cloud Native OS Ecosystem

    Jan Bronicki

    Jan Bronicki, a Flatcar Container Linux maintainer, introduces Flatcar as a declarative, immutable, minimal operating system for running containers. He gives a project update covering its CNCF incubating status, its work toward graduation, new governance and changes to packaging, infrastructure and security automation.

    5 min slot · Level not listed · Lightning Talk

    Kubernetes internals and runtimesCommunity and open source adoption

    Watch this if: you are choosing a container host OS and want a short introduction to Flatcar and its plans.

    1. 0:44 Jan Bronicki frames Flatcar as an operating system as code: declarative, immutable, minimal and container optimized.
    2. 1:21 He explains immutability: the core of the OS such as /usr is read-only and verified at boot, and atomic updates replace the whole core without touching user space.
    3. 1:50 He says the same declarative YAML configuration is meant to run on AWS, Azure, GCP and other providers, and that the project is fully open and community driven.
    4. 2:27 He says Flatcar was the first OS distribution accepted into the CNCF and is at the incubating level, and names Adobe, Giant Swarm, AT&T and Dell among its public users.
    5. 3:12 He says the project is aiming for graduation, redoing its governance with a steering committee and a technical committee, aligning packaging with upstream Gentoo, and adding AI-driven triaging of security issues.

    Your GPU Nodes Deserve Better: Flatcar Container Linux for AI Workloads

    Jan Bronicki, Sayan Chowdhury

    Flatcar maintainers Jan Bronicki and Sayan Chowdhury introduce Flatcar Container Linux as an immutable, image-based operating system provisioned from a Butane configuration, and explain its read-only /usr partition, A/B updates and release channels. In recorded demos they provision a VM, add Kubernetes as a systemd system extension, bring up GPU nodes with NVIDIA drivers shipped as an extension, and switch driver versions with a config change and a reboot.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimesAccelerators and workload scheduling

    Watch this if: you run GPU nodes on Kubernetes and want to see how an immutable host OS handles NVIDIA driver updates and rollbacks.

    1. 5:12 Jan Bronicki presents the idea of the operating system as code: Flatcar is provisioned rather than installed, from one Butane YAML file applied at first boot, and the whole OS updates atomically so machines do not drift.
    2. 12:02 Sayan Chowdhury explains A/B partition updates, in which a new version is staged to the inactive /usr partition and becomes active after a successful boot, with automatic rollback to the previous version if the boot fails.
    3. 18:42 In a recorded demo, Jan Bronicki adds Kubernetes to a Flatcar VM as a systemd system extension declared in Butane, and shows kubeadm and kubectl available under the read-only /usr.
    4. 22:18 He explains that NVIDIA drivers are packaged as a system extension pinned to the kernel and Flatcar release, so they update and roll back with the OS, then shows nvidia-smi working on a Flatcar GPU node.
    5. 26:22 Sayan Chowdhury shows a recorded driver change on an AWS instance, editing the extension configuration from the 570 driver to 580 and rebooting to load the newer driver.
