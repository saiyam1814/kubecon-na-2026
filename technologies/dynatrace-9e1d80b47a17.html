    From Traceroute to OTel Traces: Modeling Network Paths with OpenTelemetry

    Antonio Jimenez Martinez

    Antonio Jimenez Martinez describes how ThousandEyes converts traceroute results into OpenTelemetry traces, with each hop-to-hop edge modeled as a client span and a server span, enriched with host name, AS number, prefix and location. He shows recorded demos of these traces as waterfalls and service maps in Splunk, proposes span links to tie network path traces to application traces, and describes the OpenTelemetry network group working on shared semantic conventions.

    30 min slot · Advanced · Session

    Observability and reliabilityNetworking and connectivity

    Watch this if: you debug latency across networks and want traceroute data in the same tracing backend as your application traces.

    1. 3:39 Jimenez Martinez says hops that do not reply are kept as unknown hops, and an unreached target gets an extra span marked as not reached or loss.
    2. 8:19 He explains that traceroute gives only round trip time, so spans cannot have real start and end times and carry the delay as an attribute instead.
    3. 15:56 In the demo of an unreachable target, he shows the last hop spans in Splunk with an error status and error type loss.
    4. 18:42 He proposes joining network and application data with a span link, since the application trace ID is known in advance when the request is sent with the traceroute.
    5. 25:36 He proposes a scope name such as network path model, instead of a new span kind, so backends can tell a network path from service-to-service calls.

    OpenFeature Update from the Maintainers

    Jonathan Norris, Todd Baert

    Jonathan Norris and Todd Baert report on OpenFeature's growth in providers and SDK downloads, including vendors that now use OpenFeature as their native SDK. They cover new Dart and C++ SDKs, spec 0.9.0, flagd and OFREP improvements, agent skills for OpenFeature, and governance changes.

    30 min slot · Level not listed · Session

    Delivery, GitOps and release safety

    Watch this if: you use feature flags and want to know what changed in OpenFeature, flagd and OFREP this year.

    1. 2:55 Norris says OpenFeature now has almost 300 providers across 51 vendors and, by his estimate, well over 100 million SDK downloads per quarter.
    2. 3:58 Baert describes vendors such as Datadog, Cloudflare, Google Cloud, Vercel and Dynatrace choosing OpenFeature as their native SDK.
    3. 6:41 Baert lists flagd changes, including fractional bucketing on any context type, disabled flags no longer counted as errors, and later a FIPS 140 mode.
    4. 10:08 Norris explains that OFREP can now send a server-sent events URL so clients refetch flags in real time when configuration changes.
    5. 12:12 Norris presents OpenFeature agent skills, saying evaluations improved Haiku from 59% to 89% and Sonnet from 79% to 94%.
