    Building Reproducible AgentOps Pipelines with Kubeflow and MLflow

    Alyssa Goins, Ana Biazetti

    The speakers say multi-turn agent loops drive up inference cost and propose a repeatable model compression pipeline as one answer. They demo a Kubeflow Pipelines workflow that serves a model with KServe, benchmarks it, compresses it and benchmarks it again, with the runs tracked in MLflow.

    13 min slot · Level not listed · Session

    Unclassified

    Watch this if: You want a worked example of a Kubeflow Pipelines run that compresses a model and compares benchmarks before and after.

    1. 1:04 The speaker proposes a continuous optimization flow that compresses models with pipelines, which she says cuts hardware footprint and latency.
    2. 4:25 The speaker lists the pipeline steps, which are ingesting the base model, a baseline evaluation, compression, deployment with KServe and a final validation.
    3. 6:36 The speaker shows the compression step, which she says uses GPTQ quantization with a W8A8 scheme and outputs a metrics artifact and the compressed model.
    4. 9:27 The speaker says the 2.17 release of Kubeflow Pipelines added an MLflow plugin that uploads pipeline runs to MLflow automatically.
    5. 11:13 The speaker reports that the compressed model had three times faster time to first token, double the request throughput and 37% of the memory footprint.

    OptimizationJob: Hyperparameter Optimization at Scale with Kubeflow Trainer

    Aniket Shaha, Ricardo Aravena

    The speakers present OptimizationJob, a new Kubeflow Trainer API that they say runs hyperparameter tuning with each trial as a TrainJob and no second system to install. They explain how it grew out of Katib, play a recorded demo, and list the limits of the first alpha phase and the roadmap.

    20 min slot · Level not listed · Session

    Unclassified

    Watch this if: You tune hyperparameters on Kubernetes and want to know what the new OptimizationJob API in Kubeflow Trainer does today and what it leaves out.

    1. 3:13 The speaker says Katib works but means two installs, two APIs and metrics that live outside the job.
    2. 3:51 The speaker says the change that made this possible was putting training metrics in the TrainJob status, so tuning can live inside Trainer.
    3. 12:13 The speaker says trials are just TrainJobs, so they reuse runtimes, JobSet and gang scheduling, and each trial is queued by Kueue like any other.
    4. 13:04 The speaker says phase one is small on purpose, with random search, one objective, alpha feature gates that are off by default, and YAML only.
    5. 14:17 The speaker lays out the roadmap in three buckets, which are smarter search, more resiliency and a Python SDK.
