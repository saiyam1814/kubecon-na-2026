    Dropping LLM Inference Cost by Two-Thirds with Open Weights and Kubernetes

    Omisha Gupta

    The speaker describes replacing a general-purpose LLM API with a fine-tuned, quantized Qwen model served by vLLM on Kubernetes for a multi-label classification workload. She reports her own accuracy, throughput, and cost numbers, and explains how a traffic surge test failed until she shortened GPU node startup.

    30 min slot · Any Level · Session

    AI inference and servingAccelerators and workload scheduling

    Watch this if: you run a narrow, high-volume LLM task on a paid API and want one practitioner's account of moving it to a small fine-tuned model with autoscaled GPUs.

    1. 1:45 The speaker says newer model versions from both API providers scored lower on her task, and one broke her JSON output format 18% of the time.
    2. 6:08 The speaker reports exact-match results on her classification task: 56% with the tuned API prompt, 12% with the base 8B model, and 91% after fine-tuning it on her labeled data.
    3. 14:49 The speaker says AWQ 4-bit quantization shrank the model from 16 GB to 5.7 GB, and that the payoff was GPU memory left for the KV cache.
    4. 20:52 The speaker describes her surge test: KEDA asked for ten replicas but only one arrived in time, and she says only 18% of requests were served.
    5. 21:49 The speaker says compressing the container image and baking it into the node image brought a new GPU node to about four minutes from being useful.
