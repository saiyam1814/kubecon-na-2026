    I Built an AI Running Coach: A Personal kagent Agent in Production

    Adam Gordon Bell

    Adam Gordon Bell of Pulumi tells how he built a personal AI running coach that messages him in Slack, first as a Lambda function and then as a single long-running kagent session on a small Kubernetes cluster, to train for a trail race against a friend. He describes the design choices he says worked for him, shows his own training graphs from the year, and encourages the audience to build small agents for their own needs.

    30 min slot · Any Level · Session

    AI agents and automation

    Watch this if: you want a small, concrete example of a long-running personal agent on Kubernetes, told as a story with the design choices that kept it simple.

    1. 9:15 Bell describes his first version: an AWS Lambda called by a Strava webhook, a scraper for his Peloton treadmill data, a morning cron job, DynamoDB for storage and one LLM call that posted to Slack.
    2. 12:22 He shows the kagent version, an agent defined as one Kubernetes resource deployed with Pulumi, where the Strava hook, the Peloton sync and a morning cron all post messages into the running session over the agent-to-agent protocol.
    3. 13:54 His main lesson is to use deterministic code wherever possible: the MCP tool parses raw run data and hands the agent only the date, duration, incline and heart rate zones.
    4. 15:25 He keeps one session going indefinitely and handles memory with a custom compaction rule under fixed headings, plus tools that let the agent write to a plan file and an athlete file.
    5. 27:47 He reports finishing the 30K race in 4:30 against his friend's 4:41 from the previous year, after a year in which he says his weeks with three or more runs almost doubled.
