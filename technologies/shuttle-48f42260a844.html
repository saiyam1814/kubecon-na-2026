    You don't have to migrate everything — Envoy is the Bridge Between Your Old World and Your New One.

    Michael Bolot, Aidan Carson

    Two GEICO engineers describe how they connect legacy Kubernetes clusters and VMs to a new Istio mesh without migrating those workloads first. They present three Envoy-based pieces: a sidecar called Shuttle with SPIRE identities, an explicit egress proxy, and an xDS configuration server behind a simplified API.

    10 min slot · Level not listed · Lightning Talk

    Networking and connectivity

    Watch this if: You are running a multi-year migration to a service mesh and need old VMs and clusters to talk to it securely in the meantime.

    1. 0:33 Aidan Carson describes the new environment: a hybrid cloud flat layer 3 network with directly routable IPs, SPIRE for identity, and Istio-programmed Envoy sidecars enforcing which workloads may talk to each other.
    2. 2:49 Michael Bolot says an ingress gateway works for HTTP but not for clients that must address nodes by IP, such as Cassandra, and that it does not bring mTLS to the old environment.
    3. 3:49 Aidan Carson introduces Shuttle, an Envoy sidecar for legacy workloads that gets a SPIRE identity and uses DNS capture to answer hostnames with the endpoints running in the new environment.
    4. 5:21 Michael Bolot says they replaced a vendor-provided egress proxy, which he calls expensive, with an Envoy-based explicit proxy that serves workloads in both environments.
    5. 6:55 They describe an xDS configuration server that gives each proxy least-access configuration based on its identity, fed by a simplified REST API so users do not write Envoy or Istio resources.
