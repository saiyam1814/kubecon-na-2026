    DRA in KubeVirt Update

    Alay Patel

    In a recording that starts partway through the talk, the speaker outlines which DRA features are in upstream KubeVirt today, which he expects in release 1.10, and which come later. He describes CPU requests backed by generated resource claims and proposals for managed claims and Multus network support.

    5 min slot · Level not listed · Session

    Accelerators and workload schedulingKubernetes internals and runtimes

    Watch this if: you run VMs with GPUs on KubeVirt and want a five-minute status of its DRA support.

    1. 1:28 The speaker recounts that KubeVirt first released alpha GPU DRA support in 1.6, then changed the implementation and released another alpha in 1.8 because VM migration was hard with the first design.
    2. 2:28 The speaker says that with KubeVirt 1.9 and the NVIDIA DRA driver's alpha feature gate, users can attach DRA-backed passthrough GPUs.
    3. 2:38 The speaker says the upcoming release will bring alpha support for CPUs with DRA and beta support for networks with DRA.
    4. 3:34 The speaker explains that with the feature gate on, KubeVirt generates a resource claim for requested CPUs, without NUMA alignment for now.
    5. 4:37 The speaker previews managed claims, where a user names a provisioner that renders a claim aligned on PCI root and NUMA boundaries.

    Two Drivers, One Topology: GPU:NIC Rail Alignment for RDMA VMs with KubeVirt DRA

    Jian Li, Alay Patel, Kazuki Sato

    Kazuki Sato of NTT DOCOMO BUSINESS, Jian Li of SK Telecom and Alay Patel describe how a multi-site GPU platform on KubeVirt moved from a manual workaround to Dynamic Resource Allocation claims that pair each GPU with an RDMA NIC under the same PCIe root. They show a recorded benchmark comparing aligned and misaligned VMs, explain the Multus change they are proposing upstream, and outline what KubeVirt's DRA support covers today and what is planned.

    15 min slot · Level not listed · Session

    Accelerators and workload schedulingNetworking and connectivity

    Watch this if: you run GPU virtual machines with RDMA networking on KubeVirt and need each GPU paired with the right NIC without pinning devices by hand.

    1. 2:07 Sato describes the earlier workaround: filling a node with placeholder pods that each hold one GPU or NIC and deleting only the ones holding the wanted pair, which had to be redone VM by VM after every node or VM restart.
    2. 5:10 Li explains that the GPU driver and the SR-IOV NIC driver both publish the standard PCI root attribute, so one resource claim with a GPU request, a VF request and a match constraint lets the scheduler allocate them as a pair.
    3. 7:15 He says upstream KubeVirt network DRA could not consume a VF wired through a Multus network, so they added a feature gate that takes the VF from the resource claim and leaves the existing CNI chain unchanged.
    4. 10:21 In the recorded demo Sato compares two four-GPU VMs: he reports about 200 Gbps of RDMA bandwidth on the misaligned VM and 391 Gbps on the aligned one, with placement as the only difference.
    5. 12:33 Li says the next gap is that CPUs and huge pages are still placed by the kubelet without topology hints from DRA devices, so a VM can get its GPU and NIC on one socket and its memory on another.
