    Legacy-Free, Zero-Maintenance Bare Metal Kubernetes Clusters With RISC-V and Immutable Linux

    Felicitas Pojtinger

    Felicitas Pojtinger of LiveKit argues that operators should be able to own every layer of their stack, and builds one on a SpacemiT K3 RISC-V board from open firmware up to a K3s cluster. Recorded demos show an AI agent flashing and debugging the board through a hardware harness, signed image updates with systemd-sysupdate, TPM-backed remote attestation and an attested process migration between nodes.

    30 min slot · Advanced · Session

    Kubernetes internals and runtimes

    Watch this if: you want to see how far a fully open bare-metal stack on RISC-V can go, from firmware and signed images to attestation and a running cluster.

    1. 1:45 Pojtinger says x86 and Arm carry expensive licences and firmware blobs that cannot be inspected or replaced, which is her reason for building on RISC-V.
    2. 12:31 A recorded demo shows solenoids pressing the board's buttons to enter flash mode while an MCP server flashes the images, so an agent can then check the result over KVM, UART and JTAG.
    3. 18:48 She explains choosing systemd-sysupdate over bootc, with signed system and configuration extensions overlaid on an immutable /usr.
    4. 22:35 She describes measuring every boot stage into TPM platform configuration registers so the booted image can be compared with predicted values.
    5. 28:12 In a recorded demo she enables a signed K3s system extension on the board and runs Valkey, then shows the system refusing a tampered extension.

    Look Before You Leap: Preventing In-Motion K8s Updates in Fleet Robotics

    Tom Ingleby, Rian Bogle

    Rian Bogle and Tom Ingleby of Agility Robotics describe how they run K3s on humanoid robots and manage them from the cloud with GitOps. Ingleby then shows an admission webhook he calls the locomotion guard, which he says rejects cluster changes in restricted namespaces while a robot is walking.

    30 min slot · Any Level · Session

    Delivery, GitOps and release safetySecurity, identity and policy

    Watch this if: you run Kubernetes on edge or embedded devices and need to block changes while the device is in a state where a restart is unsafe.

    1. 4:56 Bogle lays out the on-robot stack: K3s on a read-only OS, GitOps with continuous deployment, OCI images, OpenTelemetry and Fluent Bit for telemetry, and Teleport with SPIFFE identities.
    2. 7:44 Ingleby explains the risk they want to avoid: a cluster change that restarts critical software while the robot is balancing could make it fall and damage itself or the customer site.
    3. 11:38 Ingleby describes the locomotion guard, a small admission webhook that queries the robot's control software for its state and rejects changes while it is walking.
    4. 14:43 Ingleby shows the override: an operator creates a ConfigMap that opens a short exemption window, and he says Teleport's audit trail records who did it.
    5. 28:06 Asked whether the webhook fails open or closed, Ingleby says it currently fails open and that they plan to fail closed as confidence grows.

    What’s New in Kairos, 2026 Edition

    William Rizzo

    William Rizzo, a Kairos maintainer, runs through the past year's releases: Kairos 4.4.0 in a monorepo, the Hadron Linux distribution, the Kairos operator, kubeadm support in the Kubernetes provider, and AuroraBoot. He also describes Cluster API providers for Kairos, which he says let Kamaji hosted control planes use Kairos-managed worker nodes.

    5 min slot · Level not listed · Lightning Talk

    Kubernetes internals and runtimesPlatform engineering and developer experience

    Watch this if: you run Kairos or immutable Linux at the edge and want a quick list of what changed over the past year.

    1. 0:52 William Rizzo says Kairos is now at version 4.4.0 and has moved to a monorepo with one version and one pipeline that builds everything.
    2. 1:29 He describes Hadron Linux as an immutable, minimal distribution built on musl and systemd, and says the work focused on hardening trusted boot, FIPS compliant images and gating releases on vulnerability scans.
    3. 2:40 He says the Kairos operator is a Kubernetes native way to handle day two operations such as draining, cordoning and upgrading nodes, and that it replaces their use of the system upgrade controller.
    4. 3:10 He says version 4.0 of the Kubernetes provider now supports kubeadm in addition to K3s and k0s.
    5. 4:26 He describes the Kairos Cluster API bootstrap and control plane provider, and says kubeadm worker node support means Kamaji hosted control planes can have Kairos-managed workers.
