    Atlantis: What's New in IaC Orchestration

    PePe Amengual

    PePe Amengual, an Atlantis maintainer, introduces the tool as a self-hosted Go binary that runs Terraform and OpenTofu plans and applies from pull request comments, and walks through recent additions and security fixes. He describes the road to Atlantis 1.0, with new features landing behind an experiments flag and work on durable storage for high availability.

    5 min slot · Level not listed · Lightning Talk

    Delivery, GitOps and release safetyPlatform engineering and developer experience

    Watch this if: you run Atlantis for Terraform or OpenTofu pull requests and want to know what changed recently and what 1.0 will bring.

    1. 0:13 Amengual describes Atlantis as a GitOps workflow tool for Terraform that listens for VCS webhooks or API calls and runs plan and apply when you comment on a pull request.
    2. 2:14 Amengual lists recent additions: first-class OpenTofu support, an alpha drift detection API, plan storage on S3, and Redis cluster support for the locking database.
    3. 2:40 Amengual says the team removed the Terraform and OpenTofu binaries from the images because of security scan findings, so images are lighter and the configured version is downloaded instead.
    4. 3:08 Amengual says the project is publishing 15 security advisories, one of them critical, covering issues such as symlink path traversal and approval bypasses, with the fixes already in main.
    5. 4:09 Amengual says new features will arrive behind an experiments flag and be promoted to regular flags once stable, and that a storage plugin design aims at horizontally scaled high availability.

    Governing and Scaling Agents in Heterogeneous Environments

    Antonio Ojea, Tomás Tormo

    Antonio Ojea and Tomás Tormo say agents on phones, laptops, and in clusters need common identity and policy without forcing every workload into Kubernetes. They present Agent Mesh and demonstrate how node-level policy limits who can reach services in a simulated hospital workflow.

    30 min slot · Any Level · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You need agents to discover services across devices and clouds without giving every node the same access.

    1. 4:06 The speakers describe why the same connectivity layer needs to run as an edge gateway, inside an agent framework, or beside a workload in a Kubernetes pod.
    2. 8:57 The speakers describe using libp2p for a distributed data plane with service discovery and cryptographic node identities.
    3. 15:04 The speakers explain that Biscuit credentials can be checked offline and narrowed when a node delegates access to a sub-agent.
    4. 18:11 The speakers distinguish the control plane that enrolls nodes, the routers that keep the distributed network connected, and the nodes or SDKs used by agents.
    5. 29:38 In a simulated hospital workflow, the speakers recap how the mesh blocked traffic to an out-of-region agent and rejected requests from nodes without the required identity.

    Untrusted Code on Secure Runtimes: Agent Sandboxes on Kubernetes

    Mofi Rahman

    Mofi Rahman leads a hands-on lab on GKE, with four Google colleagues helping attendees in the room, and explains that it uses the newly open-sourced Agent Substrate where the abstract promised Agent Sandbox. Attendees create workers, actor templates and actors, suspend and resume them with their state, allow a model call through an egress policy and run 20 actors on two workers, and he says internal benchmarks reached more than 100 million actors.

    80 min slot · Beginner · Tutorial

    AI agents and automationSecurity, identity and policyKubernetes internals and runtimes

    Watch this if: you want to follow a full lab on suspending and resuming agent workloads on Kubernetes and see how actors differ from one pod per sandbox.

    1. 21:39 Rahman explains why the lab switched projects: Agent Sandbox maps a sandbox to a pod with warm pools, while Agent Substrate adds actors, many per pod, and he suggests Sandbox for agents that run for days and Substrate for short, bursty sessions.
    2. 25:22 He lists Substrate's parts: an API server, Postgres in place of etcd, which he says could not scale to the 100 million actor goal, egress control, and a router that proxies requests so actors do not each need an IP address.
    3. 36:15 He suspends an actor, sends it a request and gets an answer anyway, explaining that the router holds the request while the actor resumes from its snapshot mid-state, unlike Cloud Run, Lambda or Knative starting from zero.
    4. 49:14 A model call from the actor fails because egress is denied by default, and it succeeds after he creates an egress gateway and a policy that allows the one model URL.
    5. 57:09 A third actor times out on two full workers, and he stresses that Substrate does not decide when to suspend: the platform team defines idle, here three seconds without a request, after which 20 actors share two workers.
