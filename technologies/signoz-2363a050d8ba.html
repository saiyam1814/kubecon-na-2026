    OpenFGA: Fine-Grained Authorization for Apps, APIs, and Agents

    Will Vedder

    OpenFGA maintainer Will Vedder introduces OpenFGA as a centralized, Zanzibar-inspired authorization decision engine and explains its authorization models, tuples, check and list APIs, and CEL-based conditions through a running example of whether a user or the user's agent may deploy a service. He then presents dynamic conditions, which he describes as a new feature that attaches CEL expressions to tuples so per-task agent rules need no model change, with an MCP gateway as the enforcement point.

    30 min slot · Level not listed · Session

    Security, identity and policyAI agents and automation

    Watch this if: you are choosing or building an authorization system and want an introduction to OpenFGA's model, plus its approach to scoping what an agent may do on a user's behalf.

    1. 4:54 Will Vedder compares RBAC, ABAC and ReBAC, saying relationship-based access control expresses inheritance and reverse lookups natively but requires writing or backfilling the relationships.
    2. 12:35 He says an OpenFGA check is a graph reachability problem: John may deploy the payments API because a chain of tuples links him through the SRE team and the checkout project to that service.
    3. 15:26 He describes conditions as OpenFGA's ABAC feature, written as CEL expressions and used for cases such as expiring grants, usage-based entitlements and IP allow lists.
    4. 17:40 He says the pattern they see most for authorizing AI agents is an MCP gateway that consults OpenFGA before forwarding a tool call.
    5. 20:57 He introduces dynamic conditions, where a CEL expression such as environment not equal to prod is stored on the tuple and evaluated at query time, so a new per-agent rule needs no model change.
