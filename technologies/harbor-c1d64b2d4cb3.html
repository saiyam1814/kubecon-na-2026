    CNCF Bingo: Play, Learn, Win!!!!!!

    Michael Rishi Forrester

    Michael Forrester runs a live bingo game he calls unofficial, in which the audience marks CNCF projects on a phone card as he reads three clues per project, from broad to narrow. He works through about fifteen projects, from Kubeflow to Knative, until three attendees win, and points to flashcards he wrote covering every CNCF project.

    12 min slot · Level not listed · Session

    Community and open source adoption

    Watch this if: You are new to the CNCF landscape and want a quick, game-style pass over what about fifteen well-known projects do.

    1. 0:13 The speaker explains the game: scan a QR code for a bingo card of CNCF projects with Kubernetes as the free middle square, and long-press a square to read what the project does.
    2. 2:17 He runs a practice round with three clues that lead to Kubeflow: a machine learning platform with notebooks and pipelines, started at Google, used for MLOps on Kubernetes.
    3. 4:15 He gives clues for Open Policy Agent: a general-purpose engine that answers allow or deny, run by Gatekeeper for Kubernetes admission, with rules written in Rego.
    4. 9:20 The first attendee gets bingo after the Harbor clues, which describe a private registry that scans images for vulnerabilities.
    5. 10:50 He says the same site has flashcards for every CNCF project, and that he had to look up about a third of the projects when writing them.

    Harbor Project – The Maintainers Session

    Orlin Vasilev, Vadim Bauer, Rani Chowdary Mandepudi

    Three Harbor maintainers and contributors cover what is in Harbor 2.16, including custom project roles, proxy cache filters and upstream Arm64 builds, and share community statistics. They then outline what they are working on for 2.17, such as syncing AI models from Hugging Face into Harbor as OCI artifacts, and ask for feedback on the open proposals.

    30 min slot · Level not listed · Session

    Security, identity and policyDelivery, GitOps and release safety

    Watch this if: you run Harbor and want to know what 2.16 changed and what the maintainers plan for 2.17, or if you need Harbor on Arm.

    1. 0:40 Vadim Bauer lists the highlights he picks from Harbor 2.16: custom project roles, a configurable proxy cache with bandwidth limits and regex filters, Valkey replacing Redis, multi-architecture images and PostgreSQL 18.
    2. 7:36 Rani Chowdary Mandepudi explains how Arm64 support landed upstream in four parts: native CI, build tooling, online and offline installers, and multi-platform OCI manifests.
    3. 14:23 Orlin Vasilev shows that pull requests nearly doubled year over year, which he attributes to AI, and asks contributors to link an issue, keep PRs small and be patient.
    4. 18:05 Vadim Bauer describes the model sync proposal for 2.17: replicate models from Hugging Face and convert them on the fly into OCI artifacts in the model spec format.
    5. 21:13 Vadim Bauer describes a proposed scanner spec upgrade that he says would let Harbor run several scanners at once, including linters, license and secret scanners, and aggregate the results.

    I Packaged My Application in a Container Image, and Now What?

    Aurélie Vache

    The speaker takes a small Go API packaged as a container image and walks through supply chain security steps for it, with a live demo for each one. She covers generating an SBOM, scanning for vulnerabilities, publishing a VEX file, signing the image, generating SLSA provenance and automating all of it in a GitHub Action.

    30 min slot · Any Level · Session

    Security, identity and policyDelivery, GitOps and release safety

    Watch this if: You can build and push a container image and want to see the next supply chain security steps done live, one command at a time.

    1. 2:18 The speaker starts with the SBOM, an inventory of the components in an image, and says it is no longer nice to have but becoming mandatory.
    2. 10:32 In the demo, a Trivy scan of the image reports 26 vulnerabilities, and the speaker points out that the first one applies to a Go version her application does not use.
    3. 13:22 The speaker introduces VEX as a way to tell users whether a vulnerability is exploitable in the application, and says OpenVEX is her favorite format.
    4. 17:11 After generating a VEX file with govulncheck and fixing its product ID, the speaker scans again with Trivy and she says the filtered result shows zero exploitable ones among the high and critical findings.
    5. 20:32 The speaker generates a key pair in a KMS, signs the image with Cosign and verifies the signature.

    Lightning Harbor Update

    Orlin Vasilev

    Orlin Vasilev, the Harbor community manager, covers what shipped in Harbor 2.15 and 2.16, including ARM64 support, the move from Redis to Valkey and a PostgreSQL upgrade that he says needs extra steps. He shares contributor and pull request numbers, asks contributors for patience with reviews, and points to a proposal to run Harbor as a common registry for CNCF projects.

    5 min slot · Level not listed · Lightning Talk

    Delivery, GitOps and release safetyCommunity and open source adoption

    Watch this if: you run Harbor and want to know what changes in 2.15 and 2.16 before you upgrade.

    1. 1:03 Orlin Vasilev says Harbor 2.15 added Cosign v3 bundles, replication adapters for JFrog and AWS ECR, and proxy cache connection limit updates.
    2. 1:25 He says Harbor 2.16 officially supports ARM64 and migrated from Redis to Valkey.
    3. 2:13 He says 2.16 moves the internal database from Postgres 15 to 18, so upgrades need a few steps and a database backup, and webhooks for private networks are disabled by default afterwards.
    4. 3:29 He says Harbor had 562 pull requests last year and 1,213 so far this year, and asks contributors to be patient and keep pull requests small because the reviewers are the same people.
    5. 4:42 He says the team opened a proposal for registry.cncf.io, with Harbor as a common registry for all CNCF projects, and invites people to read and vote on it.

    ORAS Go v3: Batteries-Included Registry SDK

    Terry Howe

    Terry Howe, an ORAS and Helm maintainer, says oras-go v3 loads the same registry configuration files that Podman uses, so TLS, mirrors and policy no longer need to be wired by hand as in v2. He also describes a client builder, a changed token flow, namespace-scoped credentials, streaming without writing to disk and a new module path.

    5 min slot · Level not listed · Lightning Talk

    Delivery, GitOps and release safetyPlatform engineering and developer experience

    Watch this if: you build Go tools that push or pull OCI artifacts and are deciding whether to move from oras-go v2 to v3.

    1. 0:56 Howe says a single convenience function loads the Docker config, auth.json, registries.conf, policy.json, registries.d and certs.d files, following mostly the same priority as Podman.
    2. 3:09 Howe says v3 brings mirror support for air-gapped setups, policy support to allow or deny registries, and a token flow that tries OAuth2 first and falls back to the distribution token flow.
    3. 3:51 Howe says reading auth.json adds namespace-scoped credentials, which he says makes it possible to copy between Harbor projects that each have their own credentials.
    4. 4:29 Howe says v3 can stream data directly so large artifacts move without being written to disk.
    5. 4:47 Howe says the module path now points at GitHub after an outage made the earlier module path unavailable, and that 70 new contributors joined since v3 branched from v2.

    Securing the Agentic Future: Distributing LLM Weights and Sandboxed AI Agents via Harbor

    Chenyu Zhang, Yan Wang

    Chenyu Zhang and Yan Wang present Harbor as a shared registry for model weights and sandboxed agent images, with different checks for the two supply chains. They demonstrate importing a model from Hugging Face and mounting it in Kubernetes, then discuss declaring an agent's requested permissions alongside its image.

    30 min slot · Beginner · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you want to distribute model weights through Harbor and review the permissions a sandboxed agent requests.

    1. 6:45 The speaker explains that ModelPack packages a model as an OCI artifact so a compliant registry can store it without tying distribution to a serving stack.
    2. 12:32 The speaker distinguishes model scanning from ordinary CVE scanning and describes signing model artifacts with Cosign as a separate supply-chain check.
    3. 17:33 The speaker shows a Harbor sync policy for a Hugging Face model, previews the source file list, and inspects the model card and license after the sync.
    4. 19:43 The speaker shows a Kubernetes deployment pointing at Harbor and says Kubernetes mounts the synced model files into the pod.
    5. 22:14 The speaker describes the Docker Sandbox Kit Spec as a declaration attached to the agent image that lists the network destinations, credentials, and paths the agent asks to use.
