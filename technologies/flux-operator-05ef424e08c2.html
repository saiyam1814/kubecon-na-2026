    Celebrate Flux's 10 Years!

    Tamao Nakahara

    Tamao Nakahara, a Flux maintainer, gives an overview of Flux and says it is trusted by cloud providers, telcos and enterprises because it was designed security first. She then describes identity features built on SPIFFE and mTLS and the Artifact Generator, which she says composes and decomposes deployment artifacts and now supports multi-tenancy.

    5 min slot · Level not listed · Lightning Talk

    Delivery, GitOps and release safetySecurity, identity and policyCommunity and open source adoption

    Watch this if: You want a quick update on Flux's security and artifact features at its ten-year mark.

    1. 0:22 Tamao Nakahara says Flux is the project that created the term and practice of GitOps.
    2. 1:25 She says several cloud providers that offer GitOps run Flux under the hood, naming Microsoft Azure as a long-time maintainer, and that almost every telco the team has spoken to uses Flux.
    3. 3:05 She says Flux has always had object and workload identity and that users can now customize them directly with SPIFFE or mTLS, moving toward no passwords and no secrets.
    4. 3:34 She argues that Flux controllers in the same cluster should not trust each other by default, and says they can now verify each other with certificates and two-way handshakes.
    5. 4:18 She describes Artifact Generator as composing one artifact from multiple sources and decomposing monorepos into smaller ones, and says multi-tenancy is new to it.

    You Don’t Have to Choose: Argo and Flux Are Friends!

    Emily Chen, Leigh Capili

    Emily Chen of Akuity and Flux maintainer Leigh Capili compare the design priorities of Argo CD and Flux and describe ways teams run both, such as Flux for cluster add-ons across a fleet and Argo CD for developer applications. In live demos, Flux bootstraps Argo CD, a Flux signature failure shows up as a degraded Argo CD application, and Kargo promotes a Flux Helm release of cert-manager across three virtual clusters.

    30 min slot · Advanced · Session

    Delivery, GitOps and release safety

    Watch this if: your organization runs both Argo CD and Flux, or is arguing over which one to pick, and you want to see them working in one cluster.

    1. 8:43 Chen says Argo CD has shipped Flux health checks since version 2.13, so Flux Helm releases and kustomizations show their health in an Argo CD application.
    2. 10:12 The speakers describe a common split where Flux handles fleet management and cluster add-ons while Argo CD serves application developers.
    3. 16:34 In the demo, Capili pushes an unsigned chart and the signature verification failure from Flux appears in the Argo CD interface.
    4. 20:19 Chen's Kargo promotion of cert-manager commits directly to Git for Flux to pick up, without using Argo CD.
    5. 22:16 Capili says Kargo has only one health checker, for Argo CD applications, and proposes one that reads kstatus so Kargo could understand Flux and other tools.
