    Edging Closer to AI Assisted Troubleshooting - AI Assisted Dashboard Analysis

    Vijay Samuel

    Vijay Samuel credits Jing Hu for much of the work on eBay's dashboard analyzer and explains why his team moved away from feeding raw telemetry to a model. He describes how the analyzer computes statistics in code and links its hypotheses back to specific dashboard evidence.

    30 min slot · Any Level · Session

    AI agents and automationObservability and reliability

    Watch this if: You want AI-assisted dashboard triage that keeps the math in code and gives on-call engineers evidence they can verify.

    1. 2:27 Samuel sketches a two-server MCP approach that sends dashboard metadata and raw results to a model, then explains why doing this for every panel can bury important facts in the context window.
    2. 6:08 Samuel describes the design rule he wants on-call engineers to take away: compute the telemetry statistics in code and let the model reason over the results rather than do the arithmetic.
    3. 6:38 Samuel explains how the analyzer links hypotheses to findings and then back to the exact dashboard panel and time range so an engineer can verify them.
    4. 10:02 Samuel walks through fetching dashboard metadata, making a plan, and handing different telemetry types to specialized subagents before combining their findings.
    5. 14:04 Samuel describes a metrics subagent that computes statistics in Go, detects anomalies in Python, and uses Largest Triangle Three Buckets to reduce the points it sends to the model.

    Engineering Kubernetes for the Next Era of Workloads

    Mike Stefaniak

    Mike Stefaniak describes bottlenecks AWS found when running large Kubernetes clusters and says the team contributed fixes upstream. He walks through watch-cache and scheduler changes, accelerator-aware provisioning with Karpenter, and parallel image unpacking in containerd.

    5 min slot · Level not listed · Keynote

    Accelerators and workload schedulingKubernetes internals and runtimes

    Watch this if: you run large GPU clusters and want concrete examples of upstream fixes from image unpacking to accelerator placement.

    1. 0:47 Stefaniak says AWS replaced a long-held Kubernetes API server watch-cache lock with a lazy snapshot, cutting writer wait from over half a second to 2 ms in its million-pod benchmark.
    2. 1:03 Stefaniak says a new Horizontal Pod Autoscaler selector store removed a read/write bottleneck, letting AWS run four times as many HPA workers in its largest clusters.
    3. 1:21 Stefaniak says an incremental scheduler cache avoided rebuilding volume reference counts and that AWS saw scheduling stay above 300 pods per second in its largest clusters.
    4. 2:28 Stefaniak explains that Dynamic Resource Allocation can describe GPU and network topology, and says Karpenter can now model devices for instances it has not launched yet.
    5. 3:48 Stefaniak says parallel layer unpacking in containerd brought a 10 GB image pull from about two minutes to under 45 seconds in AWS's testing.

    OpenChoreo: Developer Platform for Humans & Agents

    Sameera Jayasoma

    Sameera presents OpenChoreo as a Kubernetes-native control plane that hides tooling complexity behind guarded abstractions for humans and agents. He argues that agents should become first-class platform workloads and shows how catalogs, deployment state, logs, metrics, cost insights, and audit data can share those abstractions.

    5 min slot · Any Level · Keynote

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you are evaluating control-plane abstractions that serve both developers and AI agents.

    1. 1:20 Sameera says platform maintainability becomes difficult when added capabilities require repeated changes to glue code across portals and pipelines.
    2. 2:18 Sameera argues that exposing every underlying tool directly to agents can work but wastes iterations and tokens, while a smaller set of guarded abstractions gives agents a controlled interface.
    3. 3:36 Sameera presents OpenChoreo as a control-plane middle layer that abstracts the tooling layer and compiles higher-level concepts toward Kubernetes while preserving their meaning for status, logs, and metrics.
    4. 5:29 Sameera says OpenChoreo expands its control plane to treat agents as first-class workloads because they can run untrusted or unpredictable code and need runtimes such as Agent Sandbox and Agent Substrate.
    5. 5:56 Sameera introduces a quick portal demo built around a CLI and Backstage-based plugins, showing catalogs, component deployment state, logs, metrics, cost insights, and audit data.

    SIG API Machinery in the Era of AI: Updates

    Joe Betz

    Joe Betz reviews a year of work in Kubernetes SIG API Machinery, from contributor trends to API server performance, resilience and controller improvements. He covers the storage version migrator, internal type and protobuf cleanups, declarative validation with its linter, manifest-based admission policies and client library updates, then outlines what comes next.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimes

    Watch this if: you build Kubernetes APIs, CRDs or controllers and want to know what changed in the API machinery underneath them.

    1. 1:38 Betz says PRs to the SIG rose about 50% this year, which he links to AI-assisted development, while reviewer capacity stayed roughly flat.
    2. 7:21 Betz says the storage version migrator has finally landed, so CRD authors can migrate stored objects and eventually retire conversion webhooks.
    3. 12:14 Betz explains that making internal types match the preferred serving version lets the Go compiler skip needless copies during conversion.
    4. 14:45 Betz shows declarative validation, where tags on API types generate validation code, plus a linter that catches mistakes such as a field marked both required and optional.
    5. 17:10 Betz describes a tool to detect backward-incompatible CRD changes and manifest-based admission policies loaded at API server startup that users cannot bypass or modify.
