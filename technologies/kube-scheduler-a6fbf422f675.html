    Frameworkless ML Serving: Scaling to Thousands of Models with KEDA, Pub/Sub, and Native K8s

    Robin Deaconu, Neb Jovanovic

    The presenters explain why multi-minute drug-discovery jobs led their team away from a general-purpose inference framework. They describe how stateless workers, durable queues, and native Kubernetes scheduling serve interactive and batch requests on the same fleet.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: interactive inference and long-running batch jobs need to share the same pool of accelerators.

    1. 6:01 The presenters explain why multi-minute accelerator jobs made durable requests and backlog-based scaling more useful to them than in-flight concurrency.
    2. 9:12 They describe how a stateless worker backed by an asynchronous queue became the core building block of the new platform.
    3. 16:29 They explain how KEDA wakes a deployment from zero replicas and passes queue signals to the Horizontal Pod Autoscaler for further scaling.
    4. 18:46 They walk through high-priority requests preempting batch workers and describe how queue leases let interrupted work become available again.
    5. 27:52 They describe dual-writing to Redis and Bigtable to verify parity before cutting over with a configuration flag they could flip back.

    Here be DRAgons: Bringing native zero-copy networking to Pods with Cilium and netkit

    Daniel Borkmann, Aaron Campbell

    The speakers compare two Cilium network drivers for Kubernetes Dynamic Resource Allocation, one using SR-IOV and the other using netkit with queue leasing. They demonstrate how a pod can use a leased hardware receive queue and explain how zero-copy receive works with the kernel networking stack.

    30 min slot · Advanced · Session

    Accelerators and workload schedulingNetworking and connectivity

    Watch this if: you are evaluating hardware-accelerated pod networking and want to understand what Cilium queue leasing requires.

    1. 8:37 Borkmann explains how running BPF in the netkit device driver reduces the queue traversals seen with virtual Ethernet devices.
    2. 14:33 He introduces Cilium's two DRA driver options, SR-IOV and netkit queue leasing, and describes how the agent integrates with the node.
    3. 19:54 He explains how Linux queue leasing removes selected receive queues from the default set and binds them to a netkit device in a pod.
    4. 22:13 Campbell begins the demo by showing the operator's view of queue leasing and identifying the required hardware receive-queue capabilities.
    5. 30:22 He explains how packet headers stay in kernel memory while io_uring enables payload delivery directly to user space.

    One Workload to Rule Them All: Workload Aware Scheduling for Distributed AI Training on Kubernetes

    Andrey Velichkevich

    Andrey Velichkevich explains why scheduling distributed training one pod at a time can deadlock jobs and how the Kubernetes Workload and PodGroup APIs model them as a unit. He shows how Kubeflow Trainer exposes those capabilities through training runtimes and compares three scheduling policies on a local cluster.

    30 min slot · Any Level · Session

    Accelerators and workload scheduling

    Watch this if: You run distributed training on Kubernetes and want to understand when pod groups and topology constraints matter.

    1. 0:48 Velichkevich illustrates how two training jobs can deadlock when the scheduler gives each job some GPUs but neither gets enough to start all its ranks.
    2. 4:44 Velichkevich distinguishes the Workload template from runtime PodGroups and shows how a PodGroup can express a minimum pod count and topology constraints.
    3. 7:10 Velichkevich introduces composite PodGroups for workloads with a hierarchy, where a parent can require a minimum number of child groups before scheduling proceeds.
    4. 10:12 Velichkevich explains the Kubeflow Trainer split: platform admins define runtime blueprints, and scientists use a Python SDK to submit jobs without managing Kubernetes deployment details.
    5. 15:17 In a local kind demo, Velichkevich sets up a comparison of default pod-by-pod placement, gang scheduling, and rack-constrained placement for a PyTorch job.

    The Scheduling Stack: Real-World Lessons from Anthropic, Anyscale, Google, and CERN

    Wojciech Tyczyński, Ricardo Rocha, Kaslin Fields, Decheng Dai, Jui-An Huang

    The panelists compare what upstream Kubernetes scheduling can handle with where their teams still specialize. They describe how placement, queueing, cluster boundaries, and resource fragmentation affect distributed workloads.

    30 min slot · Any Level · Panel

    Accelerators and workload scheduling

    Watch this if: you are deciding which scheduling concerns belong in Kubernetes and which belong in a higher-level workload scheduler.

    1. 5:42 Fields introduces KubeRay as the controller for running Ray on Kubernetes.
    2. 10:30 A panelist distinguishes workload placement from deciding what should run now or wait in a queue.
    3. 13:46 Rocha recalls splitting CERN clusters because the scheduler could not launch the volume of workloads CERN wanted, rather than because of node count.
    4. 20:01 A panelist explains why they try to keep a tightly coupled workload within one cluster instead of exposing it to failures across several clusters.
    5. 25:14 A panelist describes a background job that scans for fragmentation and moves workloads when it finds a better placement.
