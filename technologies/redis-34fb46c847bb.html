    DisaggregatedSet Meets Multi-EPP: Coordinating llm-d at Scale in production

    Mathis Felardos, Lucas Fernandes Martins

    Mathis Felardos presents DisaggregatedSet, which Mistral AI contributed to the LeaderWorkerSet project to deploy and roll out prefill and decode roles together. Lucas Fernandes Martins presents multi-EPP for llm-d, where several router replicas share in-flight load state through a pluggable cross-replica syncer, with Mistral's Redis implementation as the example.

    20 min slot · Level not listed · Session

    AI inference and serving

    Watch this if: You run disaggregated prefill and decode serving and want safer rollouts or a horizontally scaled llm-d router.

    1. 1:18 Mathis Felardos explains disaggregated serving, splitting compute-bound prefill from memory-bound decode, and why it is hard to operate during rollouts.
    2. 3:10 He describes DisaggregatedSet, contributed into LeaderWorkerSet, with declarative prefill and decode roles and coordinated rolling updates.
    3. 5:48 He describes cross-revision gating, where llm-d shifts requests gradually to a new revision so incompatible prefill and decode pods do not pair up.
    4. 9:07 Lucas Fernandes Martins shows why naive multiple EPP replicas diverge, and introduces a cross-replica syncer interface with set, get and aggregate.
    5. 14:38 He shows benchmarks where one EPP fails after around 700 requests per second while three EPPs syncing through Redis keep serving.

    Frameworkless ML Serving: Scaling to Thousands of Models with KEDA, Pub/Sub, and Native K8s

    Robin Deaconu, Neb Jovanovic

    The presenters explain why multi-minute drug-discovery jobs led their team away from a general-purpose inference framework. They describe how stateless workers, durable queues, and native Kubernetes scheduling serve interactive and batch requests on the same fleet.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: interactive inference and long-running batch jobs need to share the same pool of accelerators.

    1. 6:01 The presenters explain why multi-minute accelerator jobs made durable requests and backlog-based scaling more useful to them than in-flight concurrency.
    2. 9:12 They describe how a stateless worker backed by an asynchronous queue became the core building block of the new platform.
    3. 16:29 They explain how KEDA wakes a deployment from zero replicas and passes queue signals to the Horizontal Pod Autoscaler for further scaling.
    4. 18:46 They walk through high-priority requests preempting batch workers and describe how queue leases let interrupted work become available again.
    5. 27:52 They describe dual-writing to Redis and Bigtable to verify parity before cutting over with a configuration flag they could flip back.

    How Podium Ships 30% of PRs with Autonomous K8s Coding Agents

    Drew Bowman

    Drew Bowman describes how Podium runs coding-agent sessions on Kubernetes and shares what the team learned about keeping those sessions recoverable. He explains why the team asks agents to attach evidence from realistic test environments and requires a human to approve their pull requests.

    30 min slot · Any Level · Session

    AI agents and automationDelivery, GitOps and release safety

    Watch this if: You are designing an internal coding-agent platform and want examples of recoverable sessions, realistic testing, and human review.

    1. 3:45 Bowman describes Podium's ORA service receiving events and handing work to an orchestrator that schedules agent sessions in pods.
    2. 5:34 Bowman explains how a separate disk-backed workspace for each session lets the team resume its work after a pod dies.
    3. 16:58 Bowman describes replacing separate staging stacks with shared team namespaces and using mirrord to route test traffic to a specific service preview.
    4. 20:39 Bowman explains the team's test evidence requirement: reproduce the failure against the unchanged service and show the result against the preview.
    5. 21:34 Bowman discusses the automated review checks Podium uses and says that changes from autonomous agents still need human approval.

    Platform as Context: Evolving Our IDP for AI Agents

    Gang Luo

    Gang Luo of Electrolux Group explains how his team extended their internal developer platform so AI agents can use it as context through MCP tools. He shares the context categories they defined, a switch to GraphQL, and benchmarks where he reports lower token use and fewer tool calls.

    25 min slot · Intermediate · Session

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you want to expose your internal developer platform to AI agents through MCP and see one team's measured token and tool-call results.

    1. 1:56 Luo describes the starting point: about 400 developers, an average of six SREs, and an IDP where developers pick templates, get approval and have infrastructure provisioned for them on golden paths.
    2. 3:50 Because developers work in the IDE and terminal, his team added MCP read and write tools on top of the IDP so agents can read and provision the infrastructure it manages.
    3. 6:41 He lists the context agents need, starting with ownership, then infrastructure, deployment through GitHub Actions and telemetry, and says the IDP should hold only what is needed and point to the other sources.
    4. 9:29 He says moving the MCP tools from static APIs to GraphQL cut the tokens an agent used for discovery by about 80% from roughly 17K.
    5. 12:19 In benchmarks comparing an agent with GitHub alone against GitHub plus the IDP, he reports one task using 50% fewer tool calls and 65% fewer tokens, while noting some experiments got worse.

    Set the Terms for Your Agents and Let Your Humans Be Creative: How to Govern Code Nobody Reviewed

    Thomas Schuetz, Dr. Constanze Roedig

    Thomas Schuetz and Constanze Roedig demonstrate a platform feedback loop that checks AI-generated applications against engineering and compliance requirements. In a recorded example, they show how evidence from runtime probes guides the coding agent's next revision.

    25 min slot · Any Level · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You want a way to check what AI-generated apps do at runtime and turn that evidence into feedback.

    1. 5:40 The speakers ask how to translate a human-readable architectural decision record or regulation into something that runtime probes can check and produce evidence for.
    2. 9:23 They explain how they made decision records machine-readable for the demo and used profiles to define a starting boundary for observed runtime behavior.
    3. 11:04 In a recorded demo, they show the first app revision, evidence from ClickHouse in the Pixie UI, and findings sent back to the coding agent to guide the next revision.
    4. 14:33 They point out that the same feedback loop produced a PostgreSQL backend in one run and Redis in another, illustrating why teams must state any backend requirements explicitly.
    5. 21:03 They recap handing off a generated app without a pre-existing CI pipeline or guardrails, and describe using runtime evidence to assess it and send feedback with little human involvement.

    The Storage Bottleneck AI Didn't See Coming: Inside StepFun’s Multimodal Production Stack

    Joe Zhou, Frank Li

    Frank Li explains why StepFun needed one file access layer for data preparation, training, checkpoints, and model loading across GPU clusters. Joe Zhou walks through the JuiceFS and TiKV architecture and reports what changed after StepFun tuned caching and metadata handling and contributed improvements upstream.

    3 min slot · Level not listed · Keynote

    AI inference and servingData, storage and state

    Watch this if: you want an example of diagnosing and improving storage bottlenecks in a multimodal AI pipeline.

    1. 0:55 Li describes how storage needs change from data preparation to training, checkpoint writes, and inference deployment.
    2. 1:23 Li says metadata overhead and unnecessary reads and writes became bottlenecks, prompting StepFun to choose a unified file layer.
    3. 1:56 Zhou breaks down JuiceFS into the client, a pluggable metadata engine, and backing storage.
    4. 2:48 Zhou explains how Kubernetes mounts provide unified file access and how a CSI driver DaemonSet automates local cache configuration.
    5. 3:33 Zhou reports more than ten thousand concurrent mount points, better read-only metadata performance, and lower read amplification after StepFun's changes.
