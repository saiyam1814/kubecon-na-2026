    Beyond Dashboards: A Semantic Layer for AI-Driven Observability in Kubernetes

    Pronnoy Goswami

    Pronnoy Goswami argues that pasting raw logs and traces into an LLM gives unreliable answers, and presents a four-layer design that uses OpenTelemetry for consistent context and an MCP server that exposes typed, bounded, summarized tools instead of raw query access. He shows a recorded local demo with synthetic data and shares lessons on cardinality, latency and when he thinks the approach reduces MTTR.

    30 min slot · Any Level · Session

    Observability and reliabilityAI agents and automation

    Watch this if: you are wiring an AI agent to your metrics and traces and want a bounded design for it.

    1. 1:52 Pronnoy lists four ways he says raw telemetry in a prompt fails: volume, no schema, unbounded queries and no provenance.
    2. 4:20 He outlines the four layers: instrument with OpenTelemetry semantic conventions, collect and store, an MCP semantic query layer, and agents with human approval.
    3. 9:21 He says MCP tools should be designed for how an on-call engineer thinks rather than wrapping the Prometheus API, and should be typed, discoverable, summarized and cited.
    4. 13:00 In a recorded demo with a fault injected into a payments API, the tool reports spikes in the checkout API's error ratio and p99 latency and in the payments API's p99 latency as the top three signals.
    5. 17:32 He shares production lessons: never offer a free-form group by, back the catalog with recording rules, set per-tool timeouts and budgets, cache, and summarize inside the server.
