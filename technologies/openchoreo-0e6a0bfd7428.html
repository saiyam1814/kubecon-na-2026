    MCP Was the Easy Half, The Rest Was a Skill Issue

    Lakmal Warusawithana

    Lakmal Warusawithana, an OpenChoreo maintainer presenting alone because his co-speaker could not attend, reports what his team saw after exposing their developer platform to coding agents through two MCP servers. He says the agents reached correct results by inconsistent routes, and that short Agent Skills written like onboarding for a new teammate made repeatable tasks run more directly.

    30 min slot · Any Level · Session

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you have put an MCP server in front of your platform and the agents get there but waste calls on the way.

    1. 6:13 Warusawithana says repeating the same task gave different token counts, tool calls and run times, with agents trying the wrong tool first, looping on a failing call or skipping prerequisite steps.
    2. 10:26 He shows a skill from their repository and explains that only its name and description are loaded at first, so the description is written close to the user's intent and concepts and recipes are loaded on demand.
    3. 16:10 He says documentation-style skills diluted the agent's performance and API-reference skills changed nothing because the tool list already had that information, so they wrote skills the way they would onboard a new teammate.
    4. 20:17 He says results improved by removing content such as product positioning, duplicated API references, soft warnings and edge cases, leaving SKILL.md files of roughly 28 to 121 lines.
    5. 21:51 He says skills go stale as APIs and tools change, so the team treats them as code, updating them with every release and checking them in CI.

    OpenChoreo: Developer Platform for Both Humans and Agents

    Sameera Jayasoma

    Sameera Jayasoma argues that developer platforms scatter glue code across portals and pipelines and expose too much underlying complexity to both developers and agents. He presents OpenChoreo as a CNCF project that puts a control plane of higher-level abstractions over existing clusters, observability and workflow tooling, with APIs, MCP servers and a built-in Backstage portal.

    5 min slot · Level not listed · Lightning Talk

    Platform engineering and developer experienceAI agents and automation

    Watch this if: you want a five-minute introduction to OpenChoreo's architecture and its pitch for serving both developers and agents.

    1. 1:19 Sameera says existing developer platforms are hard to maintain because glue code is scattered across portals and pipelines whenever tools are added or replaced.
    2. 2:05 Sameera argues that giving agents unguarded access to underlying tools makes them loop and burn tokens, and that guarded higher-level abstractions with few options work better.
    3. 2:51 Sameera says OpenChoreo was donated to the CNCF last January and reached GA in April after a few years of work behind the scenes.
    4. 3:07 Sameera walks through the architecture of a control plane over data, observability and workflow planes, with an experience plane on top for portal, CLI and agent users.
    5. 4:11 Sameera says agents are also becoming platform workloads that need special treatment, pointing to newer projects such as Agent Sandbox and Agent Substrate.

    OpenChoreo: Developer Platform for Humans & Agents

    Sameera Jayasoma

    Sameera presents OpenChoreo as a Kubernetes-native control plane that hides tooling complexity behind guarded abstractions for humans and agents. He argues that agents should become first-class platform workloads and shows how catalogs, deployment state, logs, metrics, cost insights, and audit data can share those abstractions.

    5 min slot · Any Level · Keynote

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you are evaluating control-plane abstractions that serve both developers and AI agents.

    1. 1:20 Sameera says platform maintainability becomes difficult when added capabilities require repeated changes to glue code across portals and pipelines.
    2. 2:18 Sameera argues that exposing every underlying tool directly to agents can work but wastes iterations and tokens, while a smaller set of guarded abstractions gives agents a controlled interface.
    3. 3:36 Sameera presents OpenChoreo as a control-plane middle layer that abstracts the tooling layer and compiles higher-level concepts toward Kubernetes while preserving their meaning for status, logs, and metrics.
    4. 5:29 Sameera says OpenChoreo expands its control plane to treat agents as first-class workloads because they can run untrusted or unpredictable code and need runtimes such as Agent Sandbox and Agent Substrate.
    5. 5:56 Sameera introduces a quick portal demo built around a CLI and Backstage-based plugins, showing catalogs, component deployment state, logs, metrics, cost insights, and audit data.
