    How Podium Ships 30% of PRs with Autonomous K8s Coding Agents

    Drew Bowman

    Drew Bowman describes how Podium runs coding-agent sessions on Kubernetes and shares what the team learned about keeping those sessions recoverable. He explains why the team asks agents to attach evidence from realistic test environments and requires a human to approve their pull requests.

    30 min slot · Any Level · Session

    AI agents and automationDelivery, GitOps and release safety

    Watch this if: You are designing an internal coding-agent platform and want examples of recoverable sessions, realistic testing, and human review.

    1. 3:45 Bowman describes Podium's ORA service receiving events and handing work to an orchestrator that schedules agent sessions in pods.
    2. 5:34 Bowman explains how a separate disk-backed workspace for each session lets the team resume its work after a pod dies.
    3. 16:58 Bowman describes replacing separate staging stacks with shared team namespaces and using mirrord to route test traffic to a specific service preview.
    4. 20:39 Bowman explains the team's test evidence requirement: reproduce the failure against the unchanged service and show the result against the preview.
    5. 21:34 Bowman discusses the automated review checks Podium uses and says that changes from autonomous agents still need human approval.

    No RAG, No Regrets: Letting an LLM Drive 30 EKS Clusters in Production

    Trevor Linton

    Trevor Linton describes how Mastercard built an agent harness to handle repeatable infrastructure work without retrieval-augmented generation. He walks through a cert-manager upgrade and explains how scoped tools, result filtering, token limits, and human approvals fit into the workflow.

    30 min slot · Advanced · Session

    AI agents and automationPlatform engineering and developer experience

    Watch this if: You want to automate routine Kubernetes maintenance while keeping approvals and audit trails visible.

    1. 7:30 Linton says his team deploys its Node.js agent harness as a Kubernetes application and uses PostgreSQL to resume interrupted sessions.
    2. 10:16 Linton shows a cert-manager upgrade run that reads release notes, checks compatibility, proposes changes, and leaves merge and production change approvals to people.
    3. 11:39 Linton opens an audit trace that exposes individual tool calls and lets reviewers inspect the data given to the model.
    4. 16:46 Linton describes projections that filter or aggregate tool results before they enter the model context, using a SQL-like interface.
    5. 18:50 Linton explains how each task gets a hard token budget and iteration cap, with the remaining allowance available to the agent on each loop.

Brandon Schoen explains how Heroku uses Kubernetes, Cloud Native Buildpacks, and OpenTelemetry to handle orchestration, base image updates, and observability for those builders.

    Sample Smarter, Not Harder (Or Not At All!)

    Reese Lee, Juliano Costa

    Reese Lee and Juliano Costa say sampling at the backend doesn't remove the overhead of generating telemetry in the application. Using the OpenTelemetry Demo, they compare disabling redundant instrumentation with probabilistic, policy-based tail, and adaptive sampling.

    30 min slot · Any Level · Session

    Observability and reliability

    Watch this if: You want to cut tracing overhead and keep visibility into slow, failing, or low-traffic requests.

    1. 8:58 The speakers show how they disabled overlapping HTTP instrumentation in the Node.js frontend so it did not generate spans they did not need.
    2. 11:49 The speakers set the collector to sample ten percent probabilistically and compare spans received by the collector with spans sent to Jaeger.
    3. 15:43 The speakers explain that tail sampling sends complete traces to the collector so it can apply policies before forwarding or dropping them.
    4. 16:49 The speakers show tail-sampling rules that keep errors and requests above a latency threshold rather than relying on a fixed fraction for all traces.
    5. 21:41 The speakers describe how adaptive sampling responds to changes in load so a rare checkout flow is more likely to remain visible during a traffic spike.
