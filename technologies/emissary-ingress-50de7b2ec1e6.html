    Emissary-Ingress: State of the Project

    Flynn

    Flynn gives a short update on Emissary-ingress, covering the 4.2.0 release shipped the day before, the mostly community-contributed changes in it and the rebuilt test coverage that he says makes large changes less risky. He also shares the maintainers' position on AI-assisted contributions and outlines plans for a single-language code base, a v4 API and a considered approach to Gateway API and agentic use cases.

    30 min slot · Level not listed · Session

    Networking and connectivityCommunity and open source adoption

    Watch this if: you use or contribute to Emissary-ingress and want the latest release news and the maintainers' plans for the code base and API.

    1. 1:07 Flynn announces that Emissary 4.2.0 shipped the day before, with security work, dependency updates such as Envoy 1.40.2 and the Kubernetes 1.37 client libraries, tech debt cleanup and a lot of testing work.
    2. 3:12 He describes a fix for an old security problem where someone with the right in-cluster access could push configuration into a running Emissary; the internal API moved from TCP to a Unix domain socket.
    3. 6:59 He says the maintainers welcome AI tools for research and writing code but insist on a human behind every change whom they can talk to.
    4. 11:07 He says the maintainers are determined to reach a single-language code base, starting with rewrites of Python parts in Go, and that there will be a v4 API.
    5. 12:09 He says Gateway API in its current shape makes more sense for platform engineers than for application developers, and that the project will have to reconcile that with the value of transferable knowledge.
