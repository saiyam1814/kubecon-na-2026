    Agents Fail. Workflows Recover. Durable Agent Orchestration with Cadence

    Diana Zawadzki, Shijie Sheng

    Diana Zawadzki and Shijie Sheng of Uber's Cadence team argue that agent workflows fail like any other workflow and describe wrapping model and tool calls as Cadence activities so a replacement worker can resume from recorded history. They show a demo of an error-analysis agent that survives a rate limit and a killed worker, share numbers from Uber's Agent Executor Service, and answer questions on Temporal, guardrails and operating Cadence.

    30 min slot · Any Level · Session

    AI agents and automationObservability and reliability

    Watch this if: you run long-lived AI agents in production and want to see how a workflow engine can let them resume after crashes instead of starting over.

    1. 1:02 Zawadzki explains the model: each model call is a Cadence activity, the workflow is the code that orders them, and progress is recorded in a separate service so a replacement worker can reuse completed results.
    2. 5:31 She says Uber's Agent Executor Service, built in July, hosted around 830,000 agentic workflows on Cadence in September for background and scheduled jobs.
    3. 8:19 Sheng demos an error-analysis agent with a human in the loop: a rate-limited log fetch is retried automatically, a human signal asks for more evidence, and after the worker is killed a new worker replays history to the current state.
    4. 12:33 Zawadzki says the protected run in their demo used about half the model responses and tokens of the raw run with zero new calls during recovery, while cautioning that failures were injected on purpose.
    5. 18:36 Asked how Cadence compares with Temporal, the speakers say Temporal forked from Cadence in 2019 and describe Cadence as the more community-driven CNCF project.

    Autoscaling at Scale with KEDA

    Ali Aqel

    Ali Aqel, a Stripe engineer and KEDA contributor, describes how Stripe's Kubernetes team runs workload autoscaling with KEDA across its clusters, organized around four principles: safe, stable, scalable and simple. He covers rollout protection, break-glass locks, canaries for every scaler, tuning and per-cluster Prometheus workspaces, and walks through two hypothetical incidents.

    30 min slot · Any Level · Session

    Accelerators and workload schedulingObservability and reliabilityDelivery, GitOps and release safety

    Watch this if: you run KEDA or HPA on large clusters and want one company's guardrails, locks and canaries.

    1. 3:09 Ali gives Stripe's numbers: more than 90 self-managed clusters, about 84,000 deployments and 180,000 application pods for over 8,600 services, run by about a dozen Kubernetes engineers.
    2. 10:03 He says Stripe built a pod deletion cost controller that annotates pods so scale-downs keep the spread across availability zones.
    3. 11:02 He describes scale-down and scale-up locks, from one service up to global, built on KEDA's pause annotation and annotations he says Stripe upstreamed, including force activation.
    4. 13:17 He says a canary for every supported scaler pages the team when degraded, and that these canaries found Prometheus rate limiting and a DNS problem.
    5. 16:45 He says scaling on Prometheus broke Amazon Managed Prometheus rate limits, which led through caching and sync period changes to one autoscaling workspace per cluster.

    From Platform Catalog to Conversational Agent: Wiring AI Into Your Internal Developer Platform

    Eduardo Munari, Fabiano Amaral

    Eduardo Munari and Fabiano Amaral of Stone, a Brazilian payments company, describe adding AI to Caravela, their internal developer platform, through an AI Hub catalog of agents, skills and MCP servers and a conversational agent platform called Vela. They also present Armada, their agent framework for writing and reviewing code, and share adoption and cost figures along with four pieces of advice.

    30 min slot · Any Level · Session

    Platform engineering and developer experienceAI agents and automation

    Watch this if: you already have an internal developer platform and want to see how one company put agents, MCP servers and cost controls on top of it.

    1. 9:59 Fabiano argues that AI did not create new kinds of problems but made existing ones bigger, so Stone treats agents, skills and MCP servers like applications with a catalog, standards and security rules.
    2. 13:57 Eduardo says Vela is now the main page of Caravela, a chat interface connected to many MCP servers with company context, and that this is where non-technical people started using the platform.
    3. 18:39 Eduardo says Vela publishes generated reports and static apps only inside the company VPN, more than 3,000 so far, which he counts as that many possible data breaches avoided.
    4. 24:44 Eduardo says that moving to open-weight models with automatic routing cut weekly cost by 88% and cost per million tokens by 86%, after a week of checking quality with users.
    5. 26:03 Eduardo describes Armada as one coding agent and three reviewers for business rules, security and failure scenarios, orchestrated with Temporal and run as isolated Kubernetes jobs.
