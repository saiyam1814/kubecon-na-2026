    Not Just for Infrastructure: Rebuilding an OSS Product with Kubernetes-Style Architecture

    Artur Wierzbicki, Stephanie Hingtgen

    The speakers describe embedding Kubernetes API machinery in Grafana to give product features common resource and versioning patterns. They use the dashboard migration to explain which parts of that model they kept and which they replaced to preserve existing behavior.

    30 min slot · Any Level · Session

    Kubernetes internals and runtimes

    Watch this if: you are considering Kubernetes-style APIs for an existing application and need to keep old clients working during the migration.

    1. 2:48 The speakers explain why they embedded parts of Kubernetes in Grafana instead of adopting a separate application framework.
    2. 5:47 They describe representing a service-level objective as a resource whose controller keeps its dashboard and alert rules in sync.
    3. 9:12 They explain that dashboard lists needed folder and permission filters, pagination, and sorting, which led them to build a unified storage layer.
    4. 10:55 They describe migrating playlists by writing to legacy and new tables in parallel and using a translation layer to keep the old API working.
    5. 20:24 They explain how a Grafana router replaced API aggregation without changing the URLs or versioning clients relied on.
