    From Laptop to Cluster: The Agentic AI Inner Loop on Kubernetes

    Kevin Dubois

    Dubois uses a multiplayer racing game to demonstrate an agentic application with MCP tools and cooperating agents. He explains how he inspects and tests the application locally and what he would monitor and secure when deploying it to Kubernetes.

    30 min slot · Any Level · Session

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you are building an agentic application locally and want practical checks before deploying it to Kubernetes.

    1. 5:50 Dubois connects a coding assistant to the game's MCP server and shows that administrator controls require authentication.
    2. 13:07 He introduces reShapr as an option for exposing selected existing API operations through MCP without rewriting them.
    3. 22:41 He opens the Quarkus developer UI to inspect Kafka game events, AI services, and the MCP tools the game exposes.
    4. 24:34 He shows how a model change led a game agent to choose a different speed multiplier and recommends adding evaluations to the test suite.
    5. 26:13 He recommends checking the health of sub-agents and MCP servers, not just the main application, and measuring latency and token usage.

    Governing and Scaling Agents in Heterogeneous Environments

    Antonio Ojea, Tomás Tormo

    Antonio Ojea and Tomás Tormo say agents on phones, laptops, and in clusters need common identity and policy without forcing every workload into Kubernetes. They present Agent Mesh and demonstrate how node-level policy limits who can reach services in a simulated hospital workflow.

    30 min slot · Any Level · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You need agents to discover services across devices and clouds without giving every node the same access.

    1. 4:06 The speakers describe why the same connectivity layer needs to run as an edge gateway, inside an agent framework, or beside a workload in a Kubernetes pod.
    2. 8:57 The speakers describe using libp2p for a distributed data plane with service discovery and cryptographic node identities.
    3. 15:04 The speakers explain that Biscuit credentials can be checked offline and narrowed when a node delegates access to a sub-agent.
    4. 18:11 The speakers distinguish the control plane that enrolls nodes, the routers that keep the distributed network connected, and the nodes or SDKs used by agents.
    5. 29:38 In a simulated hospital workflow, the speakers recap how the mesh blocked traffic to an out-of-region agent and rejected requests from nodes without the required identity.

    The Harness Is the New Runtime

    Idit Levine, Keith Babo

    Idit Levine and Keith Babo describe how a sandbox and a policy gateway can give agent sessions boundaries on a laptop or in a Kubernetes cluster. They introduce Agent Desktop for managing desktop sessions and announce that kagent now uses Agent Substrate.

    5 min slot · Level not listed · Keynote

    AI agents and automationKubernetes internals and runtimes

    Watch this if: you want to see how Solo.io connects desktop agent harnesses, policy gateways, and Kubernetes-hosted agent sessions.

    1. 1:07 Levine describes the agent harness as a shell that plugs in models, skills, and tools, and argues its filesystem is a useful place for infrastructure to enforce boundaries.
    2. 2:55 Levine proposes running a harness in a sandbox with its own filesystem and routing traffic through a gateway as an enforcement point.
    3. 4:23 Babo distinguishes the harness from its sessions, calling each session an actor, and introduces Agent Desktop for inventory, configuration, and governance of those actors.
    4. 5:19 Levine introduces Agent Substrate as the Kubernetes-side infrastructure for actors, and says the project has reached general availability.
    5. 6:50 Babo describes kagent as the developer-facing layer and announces that its 1.0 release is based on Agent Substrate.
