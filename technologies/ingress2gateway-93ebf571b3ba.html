    Feeling Lost? A Newcomer's Guide to the Gateway API

    Ian Rudie, Mike Morris

    Ian Rudie and Mike Morris introduce Gateway API and explain how its resources divide responsibility between platform and application teams. They discuss portability and conformance, then show an example conversion from Ingress and what the conversion leaves unresolved.

    30 min slot · Beginner · Session

    Networking and connectivity

    Watch this if: You are choosing a Gateway API implementation or migrating from Ingress and want to know which behaviors to verify first.

    1. 2:08 The speakers explain why Gateway API separates gateway configuration from routes so different teams can share traffic infrastructure.
    2. 10:04 The speakers show where a ReferenceGrant is needed when an HTTPRoute sends traffic to a service in another namespace.
    3. 14:15 The speakers explain why a successful kubectl apply is only the beginning and show which route status conditions to inspect when a backend reference fails.
    4. 18:27 The speakers describe how conformance reports help compare implementations and distinguish supported features from project-specific extensions.
    5. 20:53 The speakers run ingress2gateway on an ingress-nginx example and inspect the generated resources and a session-persistence annotation that did not carry over.

    Gateway API Project Update: – Building the Future of Traffic

    Evaline Ju, Norwin Schnyder, Ricardo Katz, Lior Lieberman, Grant Spence

    The Gateway API maintainers walk through what they say changed up to version 1.7, including promoted TCP and UDP routes, HTTPRoute retries reaching the standard channel, and experimental telemetry policy, session persistence on the Backend resource, pre-routing filters and ClusterTrustBundle references. They also describe the agentic networking subgroup's access policy for MCP traffic, stricter conformance rules, and an initiative they call Gateway for AI and Agents to consolidate the AI-related subgroups.

    30 min slot · Level not listed · Session

    Networking and connectivity

    Watch this if: you run or implement Gateway API and want the maintainers' rundown of the 1.6 and 1.7 features and where the AI and agent traffic work is heading.

    1. 5:07 Ricardo Katz says the 1.6 release focused on layer 4, promoting TCPRoute and UDPRoute so different ports on one IP can forward to different backends, and that port ranges are not supported yet.
    2. 10:19 Evaline Ju says the agentic networking subgroup's access policy lets you control which agents can call which MCP tools, using identity-aware policies based on SPIFFE IDs or service accounts.
    3. 14:46 Grant Spence says session persistence moved to the new Backend resource to avoid having two APIs for one thing, and that in 1.7 a Backend can select in-cluster pods by label.
    4. 18:23 He describes experimental pre-routing filters that run at the listener level before route selection, in strict order, and in 1.7 support only external auth and implementation-specific extensions.
    5. 25:23 Norwin Schnyder says conformance requirements are being tightened and that the 1.8 release is planned to remove the partial conformance level.

    SIG Network Intro and Updates

    Surya Seetharaman, Guilherme Cassolato, Austin Abro, Bowei Du

    Four SIG Network contributors review what the SIG owns and what changed in 2026 across Kubernetes core and its subprojects, including kube-proxy's planned move to nftables as the default mode, Gateway API releases, Cluster Network Policy reaching v1beta1 and the status of smaller subprojects. They also report findings from the SIG's first structured survey of its 22 subprojects, and Austin Abro describes how he used AI to make his first contribution.

    30 min slot · Level not listed · Session

    Networking and connectivityKubernetes internals and runtimes

    Watch this if: you want a year's worth of Kubernetes networking changes in one session, or you run kube-proxy and need to plan for nftables.

    1. 3:40 Bowei Du mentions a new proposal for network-isolated pods with no networking by default, which he links to agent sandbox use cases, and lists deprecations of external IPs, kube-proxy IPVS mode and the Endpoints API.
    2. 4:45 Austin Abro explains the opt-in TCP userspace proxy that lets nftables mode serve NodePorts on localhost, and advises setting the kube-proxy backend explicitly before the default changes to nftables in 1.40.
    3. 9:57 Surya Seetharaman announces the v1beta1 release of Cluster Network Policy, which unifies the former admin and baseline CRDs, and notes the work began in March 2020.
    4. 16:11 Guilherme Cassolato says the SIG ran its first structured survey of its 22 subprojects and learned that AI is driving many agendas to the point of overlap, some projects have only one or two maintainers, and maintainers want faster API review.
    5. 20:47 Abro recounts using AI to learn kube-proxy internals for his localhost NodePort contribution, and says the maintainers' insistence on not breaking existing users kept the feature opt-in.
