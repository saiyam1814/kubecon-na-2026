    Hope Is Not a Rollout Strategy: Balancing (AI) Quality, Cost, and Risk Through Experimentation

    Todd Baert

    Baert presents feature flags and telemetry as a way to manage AI rollouts without redeploying the application. He uses a calculator demo to show how he evaluates guardrails and model settings for different groups of users.

    30 min slot · Any Level · Session

    AI inference and servingDelivery, GitOps and release safety

    Watch this if: you want to test changes to AI models or guardrails on a small group before rolling them out to everyone.

    1. 7:26 Baert shows an application asking OpenFeature for a model name with a fallback and context, while leaving targeting decisions outside the application code.
    2. 8:43 He shows how the OpenFeature Operator represents flags as Kubernetes custom resources so their values can change without an application redeploy.
    3. 9:54 He introduces an LLM-powered calculator so he can compare generated answers against a known correct result.
    4. 12:27 He enables a guardrail through a flag and uses the dashboard to watch what changes after the rollout.
    5. 18:54 He demonstrates assigning a zero-temperature variant to a quarter of trial users while the rest stay on the old setting.

    Securing the Agentic Future: Distributing LLM Weights and Sandboxed AI Agents via Harbor

    Chenyu Zhang, Yan Wang

    Chenyu Zhang and Yan Wang present Harbor as a shared registry for model weights and sandboxed agent images, with different checks for the two supply chains. They demonstrate importing a model from Hugging Face and mounting it in Kubernetes, then discuss declaring an agent's requested permissions alongside its image.

    30 min slot · Beginner · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you want to distribute model weights through Harbor and review the permissions a sandboxed agent requests.

    1. 6:45 The speaker explains that ModelPack packages a model as an OCI artifact so a compliant registry can store it without tying distribution to a serving stack.
    2. 12:32 The speaker distinguishes model scanning from ordinary CVE scanning and describes signing model artifacts with Cosign as a separate supply-chain check.
    3. 17:33 The speaker shows a Harbor sync policy for a Hugging Face model, previews the source file list, and inspects the model card and license after the sync.
    4. 19:43 The speaker shows a Kubernetes deployment pointing at Harbor and says Kubernetes mounts the synced model files into the pod.
    5. 22:14 The speaker describes the Docker Sandbox Kit Spec as a declaration attached to the agent image that lists the network destinations, credentials, and paths the agent asks to use.

    The Local AI Renaissance

    Jason Stryker

    Jason Stryker explains why he runs open-weight models on his own hardware and demonstrates a laptop setup that serves a model through KServe and llama.cpp. He compares inference engines and discusses memory and concurrency limits that shape which workloads he runs locally.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: you want to try serving open-weight models on hardware you already own.

    1. 3:34 Stryker distinguishes local models, which run on your own hardware, from models you reach through a hosted subscription.
    2. 13:40 He identifies memory as a major constraint for local inference and explains why it matters for the model he can run in the demo.
    3. 14:39 He introduces KServe as the layer that runs inference engines on his local Kubernetes cluster.
    4. 17:11 He turns off Wi-Fi and shows the local inference request and service logs continuing without an internet connection.
    5. 23:55 He introduces vLLM as an option when concurrency matters and contrasts its key-value cache approach with llama.cpp.
