    Don’t Lose Your Agent’s Mind: Platform Patterns for Stateful Agents

    Evaline Ju, Maia Iyer

    The speakers explain why stateful agents lose sessions, files, and context when treated like ordinary pods, and they examine community work on sandboxing, snapshotting, and resuming agent state. They present their moca prototype and argue for server-held sessions, harness-neutral state, and an open harness-sandbox boundary.

    25 min slot · Any Level · Session

    AI agents and automationData, storage and state

    Watch this if: you are designing Kubernetes platform support for stateful or delegated AI agents.

    1. 4:00 The speakers say a plain pod is a poor fit for stateful agents because deleting the pod discards sessions, files, and learned context.
    2. 5:48 The speakers point to Agent Sandbox templates and Agent Substrate snapshot and resume work as community efforts aimed at configurable isolation and multiplexing idle agents.
    3. 9:19 The speakers present moca as their open-source managed-agents experiment, using Pi for the harness, Valkey for externalized sessions, and a relay boundary into pluggable sandboxes.
    4. 16:10 In the recorded demo, Evaline shows the user closing a session, starting another one, and still picking up the subagent's work without resending context.
    5. 18:41 The speakers argue that platforms should make sessions first-class and server-held, treat agent state as harness-neutral data, and make the harness-sandbox boundary an open protocol, while provenance, cost attribution, legibility, and delegated trust remain open.

    Harbor Project – The Maintainers Session

    Orlin Vasilev, Vadim Bauer, Rani Chowdary Mandepudi

    Three Harbor maintainers and contributors cover what is in Harbor 2.16, including custom project roles, proxy cache filters and upstream Arm64 builds, and share community statistics. They then outline what they are working on for 2.17, such as syncing AI models from Hugging Face into Harbor as OCI artifacts, and ask for feedback on the open proposals.

    30 min slot · Level not listed · Session

    Security, identity and policyDelivery, GitOps and release safety

    Watch this if: you run Harbor and want to know what 2.16 changed and what the maintainers plan for 2.17, or if you need Harbor on Arm.

    1. 0:40 Vadim Bauer lists the highlights he picks from Harbor 2.16: custom project roles, a configurable proxy cache with bandwidth limits and regex filters, Valkey replacing Redis, multi-architecture images and PostgreSQL 18.
    2. 7:36 Rani Chowdary Mandepudi explains how Arm64 support landed upstream in four parts: native CI, build tooling, online and offline installers, and multi-platform OCI manifests.
    3. 14:23 Orlin Vasilev shows that pull requests nearly doubled year over year, which he attributes to AI, and asks contributors to link an issue, keep PRs small and be patient.
    4. 18:05 Vadim Bauer describes the model sync proposal for 2.17: replicate models from Hugging Face and convert them on the fly into OCI artifacts in the model spec format.
    5. 21:13 Vadim Bauer describes a proposed scanner spec upgrade that he says would let Harbor run several scanners at once, including linters, license and secret scanners, and aggregate the results.

    Legacy-Free, Zero-Maintenance Bare Metal Kubernetes Clusters With RISC-V and Immutable Linux

    Felicitas Pojtinger

    Felicitas Pojtinger of LiveKit argues that operators should be able to own every layer of their stack, and builds one on a SpacemiT K3 RISC-V board from open firmware up to a K3s cluster. Recorded demos show an AI agent flashing and debugging the board through a hardware harness, signed image updates with systemd-sysupdate, TPM-backed remote attestation and an attested process migration between nodes.

    30 min slot · Advanced · Session

    Kubernetes internals and runtimes

    Watch this if: you want to see how far a fully open bare-metal stack on RISC-V can go, from firmware and signed images to attestation and a running cluster.

    1. 1:45 Pojtinger says x86 and Arm carry expensive licences and firmware blobs that cannot be inspected or replaced, which is her reason for building on RISC-V.
    2. 12:31 A recorded demo shows solenoids pressing the board's buttons to enter flash mode while an MCP server flashes the images, so an agent can then check the result over KVM, UART and JTAG.
    3. 18:48 She explains choosing systemd-sysupdate over bootc, with signed system and configuration extensions overlaid on an immutable /usr.
    4. 22:35 She describes measuring every boot stage into TPM platform configuration registers so the booted image can be compared with predicted values.
    5. 28:12 In a recorded demo she enables a signed K3s system extension on the board and runs Valkey, then shows the system refusing a tampered extension.

    Lightning Harbor Update

    Orlin Vasilev

    Orlin Vasilev, the Harbor community manager, covers what shipped in Harbor 2.15 and 2.16, including ARM64 support, the move from Redis to Valkey and a PostgreSQL upgrade that he says needs extra steps. He shares contributor and pull request numbers, asks contributors for patience with reviews, and points to a proposal to run Harbor as a common registry for CNCF projects.

    5 min slot · Level not listed · Lightning Talk

    Delivery, GitOps and release safetyCommunity and open source adoption

    Watch this if: you run Harbor and want to know what changes in 2.15 and 2.16 before you upgrade.

    1. 1:03 Orlin Vasilev says Harbor 2.15 added Cosign v3 bundles, replication adapters for JFrog and AWS ECR, and proxy cache connection limit updates.
    2. 1:25 He says Harbor 2.16 officially supports ARM64 and migrated from Redis to Valkey.
    3. 2:13 He says 2.16 moves the internal database from Postgres 15 to 18, so upgrades need a few steps and a database backup, and webhooks for private networks are disabled by default afterwards.
    4. 3:29 He says Harbor had 562 pull requests last year and 1,213 so far this year, and asks contributors to be patient and keep pull requests small because the reviewers are the same people.
    5. 4:42 He says the team opened a proposal for registry.cncf.io, with Harbor as a common registry for all CNCF projects, and invites people to read and vote on it.
