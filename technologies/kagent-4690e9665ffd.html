    Cloud Native Without Limits: What Can AI Agents Do for Us?

    Lin Sun

    Lin Sun uses a live drone photo and a group of Kubernetes-hosted agents to make a short film with the audience. When the workflow hits a rate limit, she shows an agent proposing a pull request for human review and uses distributed traces to see what went wrong.

    12 min slot · Level not listed · Keynote

    AI agents and automation

    Watch this if: you want a live example of agents working across Kubernetes, pull requests, authentication, and distributed tracing.

    1. 1:14 Sun introduces the drone pilot and uses the live flight to capture an image of the audience for the demo.
    2. 2:49 Sun shows how she deploys agents with Argo CD and describes the services that let suspended agents resume when needed.
    3. 7:01 Sun calls on a platform agent to troubleshoot a rate-limit error, then reviews the pull request it opens before approving it.
    4. 12:39 Sun asks the audience for permission to publish the film and explains why the publishing tool requires authentication.
    5. 13:38 Sun uses distributed traces to identify the earlier rate-limit error and show where the successful run spent time generating video.

    Compliance Drift on Kubernetes: Building Proof Infrastructure for AI Agents in Regulated Industries

    Saideep Navakoti

    Saideep Navakoti presents ACRA, a Kubernetes proof workflow intended to detect changes in AI-agent behavior and make the resulting investigations auditable. He shows how the demo displays investigation tickets and describes how auditors could query evidence drawn from traces.

    25 min slot · Intermediate · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You need to show auditors what an AI agent was approved to do and what it actually did.

    1. 7:55 Navakoti explains that Kyverno checks pod admission and OpenTelemetry records traces, but argues that neither alone tells an operator whether an agent's behavior has drifted.
    2. 9:32 He introduces ACRA's API server, controller, and gate, then explains how its contract evaluator checks agent behavior against a declared baseline.
    3. 12:21 He shows a demo UI that calls the API to display investigation tickets, after describing how a drift event produces evidence from collected traces.
    4. 20:04 He frames drift as a reason to re-approve an agent rather than silently fix it, and walks through how a custom Kubernetes controller reports the agent's state.
    5. 21:32 He describes evidence an auditor can query for a specific task or incident, including a telemetry graph rather than a manually maintained spreadsheet.

    Platform-First AI Agent Security: Zero-Trust Patterns for Kubernetes

    Carlos Santana

    Carlos Santana argues that a Kubernetes platform should treat agent-generated code as untrusted and provision isolation, credentials, and network policy separately. He describes using kro to compose those controls behind a platform API and shows captures of an Agent Sandbox warm pool assigning a ready pod.

    30 min slot · Any Level · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you need to give teams a Kubernetes API for agents without giving those agents unrestricted access.

    1. 5:25 Santana describes SPIFFE and SPIRE as a way to identify an agent by URI and associate that identity with a credential across different environments.
    2. 12:14 Santana shows a kro ResourceGraphDefinition and explains how a declarative resource graph can give platform users a custom API without requiring the platform team to write a Go controller.
    3. 19:05 Santana compares gVisor, Kata Containers, and AWS Nitro Sandboxes as different isolation choices for running untrusted agent code.
    4. 21:27 Santana shows captures of a two-pod Agent Sandbox warm pool and says applying a claim assigned a ready pod instead of waiting for a fresh sandbox to start.
    5. 25:48 Santana describes a credential proxy that attaches a credential to an outbound request without handing the underlying secret to the agent, and gives an Agent Substrate example.

    Pods Are Not Enough for AI Agents, Meet Agent-substrate

    Christian Posta

    Christian Posta says long-lived agent sessions need an identity and state that can outlast any one Kubernetes pod. He demonstrates how Agent Substrate suspends and resumes actors on shared workers and controls their access to outside services.

    30 min slot · Any Level · Session

    AI agents and automationKubernetes internals and runtimes

    Watch this if: You need to run agents that pause and resume without keeping one Kubernetes pod per session.

    1. 8:16 Posta says an actor's identity and policy should be independent of the pod so the actor can keep its state when it isn't running.
    2. 11:06 Posta explains that an actor's identity persists for the actor's lifetime and that network calls from the sandbox require policy approval.
    3. 18:22 Posta suspends one actor in the demo, freeing enough capacity in the same worker for another actor to run.
    4. 22:22 Posta explains how agentgateway can check egress policy and attach a credential outside the sandbox instead of handing the secret to the actor.
    5. 28:47 Posta distinguishes Agent Substrate's actor runtime from kagent, which can use conversation and user context to decide when to suspend or resume an actor.

    The Harness Is the New Runtime

    Idit Levine, Keith Babo

    Idit Levine and Keith Babo describe how a sandbox and a policy gateway can give agent sessions boundaries on a laptop or in a Kubernetes cluster. They introduce Agent Desktop for managing desktop sessions and announce that kagent now uses Agent Substrate.

    5 min slot · Level not listed · Keynote

    AI agents and automationKubernetes internals and runtimes

    Watch this if: you want to see how Solo.io connects desktop agent harnesses, policy gateways, and Kubernetes-hosted agent sessions.

    1. 1:07 Levine describes the agent harness as a shell that plugs in models, skills, and tools, and argues its filesystem is a useful place for infrastructure to enforce boundaries.
    2. 2:55 Levine proposes running a harness in a sandbox with its own filesystem and routing traffic through a gateway as an enforcement point.
    3. 4:23 Babo distinguishes the harness from its sessions, calling each session an actor, and introduces Agent Desktop for inventory, configuration, and governance of those actors.
    4. 5:19 Levine introduces Agent Substrate as the Kubernetes-side infrastructure for actors, and says the project has reached general availability.
    5. 6:50 Babo describes kagent as the developer-facing layer and announces that its 1.0 release is based on Agent Substrate.

    The Missing Layer of Platform Maturity: Kubernetes Networking

    Faseela Kundattil, Christophe Sauthier, Chad M. Crowell, Marino Wijay, James Spurin

    The panel explains why Kubernetes networking remains a maturity gap despite higher-level abstractions, using incidents and observability workflows to show why engineers still need mental models of the underlying stack. The panelists describe the hands-on CKNE exam as a vendor-flexible way to validate networking skills while arguing that AI should assist rather than replace engineering judgment.

    35 min slot · Any Level · Panel

    Networking and connectivityPlatform engineering and developer experience

    Watch this if: your platform team owns Kubernetes networking troubleshooting or is evaluating the CKNE curriculum.

    1. 1:41 The panel argues that Kubernetes networking is a missing layer of platform maturity because usable abstractions still require underlying troubleshooting knowledge when failures occur.
    2. 10:08 Chad uses a 504 ingress incident to argue for peeling back the network path locally, from pod logs and events through service endpoints to ingress routing and host-header behavior.
    3. 15:21 James argues that engineers should learn enough iptables, nftables, conntrack, and eBPF to understand failures and judge AI-suggested fixes rather than treating AI as the authority.
    4. 17:35 Chad argues that knowing where in the networking stack a problem lives matters more than loyalty to a toolset, with observability used to narrow environment and namespace before deep packet inspection.
    5. 23:31 Christophe says SMEs from varied projects designed the hands-on CKNE exam so candidates can answer with different tools rather than being forced into one stack.
