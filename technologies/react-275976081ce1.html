    Compliance Drift on Kubernetes: Building Proof Infrastructure for AI Agents in Regulated Industries

    Saideep Navakoti

    Saideep Navakoti presents ACRA, a Kubernetes proof workflow intended to detect changes in AI-agent behavior and make the resulting investigations auditable. He shows how the demo displays investigation tickets and describes how auditors could query evidence drawn from traces.

    25 min slot · Intermediate · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: You need to show auditors what an AI agent was approved to do and what it actually did.

    1. 7:55 Navakoti explains that Kyverno checks pod admission and OpenTelemetry records traces, but argues that neither alone tells an operator whether an agent's behavior has drifted.
    2. 9:32 He introduces ACRA's API server, controller, and gate, then explains how its contract evaluator checks agent behavior against a declared baseline.
    3. 12:21 He shows a demo UI that calls the API to display investigation tickets, after describing how a drift event produces evidence from collected traces.
    4. 20:04 He frames drift as a reason to re-approve an agent rather than silently fix it, and walks through how a custom Kubernetes controller reports the agent's state.
    5. 21:32 He describes evidence an auditor can query for a specific task or incident, including a telemetry graph rather than a manually maintained spreadsheet.

    How We Are Enabling Feature Flagging At Scale

    Juan Bernal

    Juan Bernal explains why CVS Health looked for an alternative to expensive vendor plans and limited homegrown feature flagging. He describes how OpenFeature and a self-hosted control plane let his team separate flag management from evaluation.

    30 min slot · Any Level · Session

    Delivery, GitOps and release safety

    Watch this if: You are weighing a self-hosted feature flag platform against vendor tools or ticket-driven workflows.

    1. 1:58 Bernal explains how feature flags separate deployment from release and let teams target a rollout to a specific segment.
    2. 4:53 Bernal explains why his team chose OpenFeature: it offers a common contract for evaluating flags across platforms and backends.
    3. 6:42 Bernal walks through the CVS architecture, where a core API feeds both the management interface and flagd, the service that evaluates the flags.
    4. 7:27 Bernal recalls how an OpenFeature maintainer proposed flagd FlagSets to support configuration at both the application and environment level.
    5. 11:09 In a recorded demo, Bernal shows the Flag Controller interface for organizing teams and applications, defining reusable targeting segments, and creating feature flags.

    Zero to Maintainer in 45 Days: An AI-Assisted Migration of a CNCF Project's Legacy Frontend

    Jeff Spahr

    The speaker, who says he is not a frontend developer, describes how he used AI coding agents to migrate the aging Kubeflow Pipelines frontend off deprecated dependencies, starting from a wish to remove vulnerabilities. He walks through the checks he used to earn maintainers' trust, from adding tests before each change to a pixel-by-pixel visual comparison, and how he became a frontend approver after 45 days and later a maintainer.

    30 min slot · Any Level · Session

    Community and open source adoptionAI agents and automation

    Watch this if: You have a daunting migration in an open source project's backlog and want to see how one contributor used AI agents on it while keeping maintainers' trust.

    1. 2:50 The speaker says the dependency problem had stayed unsolved because it meant replacing deprecated dependencies such as Create React App and the whole UI testing framework, not just bumping versions.
    2. 6:38 His approach for each change was to check test coverage with his AI agent, add the missing tests first and only then make the change; along the way he found the frontend end-to-end tests had been disabled for years.
    3. 8:50 The speaker shows a comparison tool he built with his AI agent that compares main and the pull request pixel by pixel and circles visual regressions, such as a contrast problem that passing tests had missed.
    4. 10:11 He opens the largest pull request, which adds about 124,000 lines and removes about 145,000, and says the maintainers merged it after the visual comparison showed no regressions.
    5. 21:25 The speaker's takeaway is to retry problems that looked too hard a year ago, and he says unexciting migration work on the foundations is a perfect use case for AI.
