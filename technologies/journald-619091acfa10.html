    Fluent Bit: The Evolution of High-Performance Telemetry Pipelines

    Eduardo Silva

    Eduardo Silva introduces Fluent Bit as an agent or aggregator for moving logs, metrics and traces, and announces the Fluent Bit 5.2 release. He highlights a new typed Lua scripting interface, performance comparisons he presents against Fluent Bit 5.1 and the OpenTelemetry Collector, and a build of Fluent Bit that runs in the browser.

    5 min slot · Level not listed · Lightning Talk

    Observability and reliability

    Watch this if: You run Fluent Bit and want the 5.2 release highlights in five minutes.

    1. 0:49 Eduardo Silva says Fluent Bit collects from sources such as journald, HTTP and OTLP with more than a hundred connectors, then filters data and routes it to multiple destinations.
    2. 1:46 He announces Fluent Bit 5.2 and lists a new journald collector that converts to OpenTelemetry logs, throttling for slow destinations, and improved filesystem buffering.
    3. 2:53 He says a new fully typed interface for Lua scripts, which he calls FTS, gives an API for logs, with the same available for metrics and traces.
    4. 4:11 He shows a comparison of the new version with Fluent Bit 5.1 and the OpenTelemetry Collector on throughput and CPU use when ingesting JSON logs and OTLP.
    5. 4:51 He says Fluent Bit can now be compiled to run in the browser, and that a first implementation called Fluent Bit Studio lets users test Lua scripts and processors before production.
