    No Network? No Problem: How We Designed for Kubernetes Nodes Running in Air-Gapped VPCs

    Shachar Tal

    Shachar Tal describes a security scanning product that runs in customer-owned cloud accounts with no ingress or egress, and how his team replaced Konnectivity's gRPC tunnel with a cloud storage bucket so Kubernetes nodes there can talk to a remote control plane. He demos kubectl exec and logs running over bucket objects and says adaptive polling keeps the cost at about $5 per VM instance per month.

    30 min slot · Any Level · Session

    Networking and connectivitySecurity, identity and policy

    Watch this if: you need Kubernetes nodes in networks with zero egress and want to see a control plane tunnel built on object storage.

    1. 3:58 Tal says the outpost VPC is designed so that an attacker who gets code running inside cannot exfiltrate data, with one tightly controlled bucket as the only path.
    2. 11:17 Tal says Konnectivity solves only one direction of reachability, so his team carries messages in both directions through the bucket as a rendezvous point.
    3. 18:48 In the demo, Tal runs kubectl exec into a pod and says every keystroke is a file uploaded to the bucket and pulled down by the other side.
    4. 21:36 Tal says moving to Kubernetes with CSI plugins let the team throw out 80% of its application code for volumes, snapshots and mounting.
    5. 23:05 Tal explains that polling speeds up to 500 milliseconds while a session is active and backs off to 10 seconds, at a cost he puts at about $5 per VM instance per month.

    Why Quotas Are Hard in Kubernetes: Lessons from Building a Production-Grade Quota System

    Deepak Kinni, Xing Yang

    Xing Yang explains how Kubernetes ResourceQuota is enforced at admission, including optimistic updates, a lookaside cache, per-namespace batching and a controller that corrects drift, and where races still reject valid requests. Deepak Kinni then describes the webhook-based storage quota system Broadcom built for vSphere, with policy-level and hierarchical limits and usage tracking for snapshots, and demos it rejecting a claim that exceeds its limit.

    30 min slot · Any Level · Session

    Kubernetes internals and runtimesData, storage and state

    Watch this if: you run multi-tenant clusters and want to understand how ResourceQuota behaves under concurrency, or are designing your own quota system.

    1. 7:45 Yang says a request can be rejected after reaching the maximum number of update retries even though quota is still available.
    2. 10:36 Kinni lists why ResourceQuota was not enough for vSphere, including usage tracking, policy-level limits and snapshots whose size is known only after they complete.
    3. 14:06 Kinni says the biggest design challenge is that webhooks are unordered, so a later webhook can reject a request after quota was reserved, leaving phantom reservations.
    4. 15:22 Kinni says the system always writes parent quotas first, so a partial failure leaves it over-reserved and never under-reserved.
    5. 21:59 In the demo, the webhook denies a 50 GB claim for insufficient storage quota and the reserved and used values do not change.
