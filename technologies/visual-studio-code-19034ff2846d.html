    Open Policy Agent. (OPA) Intro & Deep Dive

    Sebastian Spaink, Johan Fylling

    Sebastian Spaink and Johan Fylling introduce Open Policy Agent as a general-purpose policy engine and Rego as its declarative policy language. They then cover this year's Rego changes, new Java and Swift evaluators built on OPA's intermediate representation, runtime improvements, and updates from Gatekeeper, opa-java-wasm and Conftest.

    30 min slot · Level not listed · Session

    Security, identity and policy

    Watch this if: you write Rego policies and want to know about the new and, or and not semantics and the coming Rego v2.

    1. 0:53 Spaink describes the problem OPA targets: policy scattered across enforcement points owned by different teams, so nobody can easily answer what the policy is.
    2. 8:42 Fylling shows the new or keyword for inline disjunction, while still recommending helper rules to keep large logical expressions maintainable.
    3. 12:33 Fylling explains the pitfall where a not expression over an undefined input value stopped the whole rule, and how the compiler now wraps negations in closures.
    4. 17:14 Fylling says a Rego v2 import enables the new syntax per module, ahead of an OPA 2.0 release the team plans for next year.
    5. 20:06 Fylling presents Java and Swift evaluators that run OPA's intermediate representation inside applications as libraries, with bundle management and decision logging.

    The Harness Is the New Runtime

    Idit Levine, Keith Babo

    Idit Levine and Keith Babo describe how a sandbox and a policy gateway can give agent sessions boundaries on a laptop or in a Kubernetes cluster. They introduce Agent Desktop for managing desktop sessions and announce that kagent now uses Agent Substrate.

    5 min slot · Level not listed · Keynote

    AI agents and automationKubernetes internals and runtimes

    Watch this if: you want to see how Solo.io connects desktop agent harnesses, policy gateways, and Kubernetes-hosted agent sessions.

    1. 1:07 Levine describes the agent harness as a shell that plugs in models, skills, and tools, and argues its filesystem is a useful place for infrastructure to enforce boundaries.
    2. 2:55 Levine proposes running a harness in a sandbox with its own filesystem and routing traffic through a gateway as an enforcement point.
    3. 4:23 Babo distinguishes the harness from its sessions, calling each session an actor, and introduces Agent Desktop for inventory, configuration, and governance of those actors.
    4. 5:19 Levine introduces Agent Substrate as the Kubernetes-side infrastructure for actors, and says the project has reached general availability.
    5. 6:50 Babo describes kagent as the developer-facing layer and announces that its 1.0 release is based on Agent Substrate.

    The Missing Front-Door to Your AI Supercomputer – Kubeflow Workspaces

    Mathew Wicks, Siyuan Zhang

    The speakers introduce Kubeflow Workspaces, which they describe as the second major version of Kubeflow Notebooks and say reached GA about five days before the talk. They show how admins define workspace options and access rules while users launch Spark, training and inference jobs from a workspace, and they lay out the roadmap and the end of life of v1.

    20 min slot · Level not listed · Session

    Accelerators and workload schedulingPlatform engineering and developer experience

    Watch this if: You run notebooks for data scientists on Kubernetes and want to see what the new Workspaces version changes for admins and users.

    1. 2:24 The speaker introduces the two new custom resources, WorkspaceKind for the admin and Workspace for the user, with admin-defined options in between.
    2. 3:12 The speaker walks through redirects, filter rules and activity rules, which he says help admins manage image upgrades, valid combinations and idle workspaces.
    3. 9:32 The speaker says admins can define fine-grained access rules in a WorkspaceKind and the controller creates a dedicated service account per workspace.
    4. 10:45 The speaker walks through a demo that launches a PySpark job, a four-GPU PyTorch training job, a TPU run and inference from one CPU workspace.
    5. 15:31 The speaker says v1 is end of life with security patches until April next year, and that v1 and v2 can be installed side by side to migrate.

    Your Quickstart is Broken – AI Agents as Synthetic New Users

    Aman Singh

    Aman Singh describes how the Drasi maintainers use an AI agent as a synthetic new user that follows their tutorials exactly and reports where the docs and the real output differ. He walks through the setup with Dev Containers, GitHub Actions, GitHub Copilot CLI and Playwright, and shows bugs it found in Drasi, Dapr Agents and Radius tutorials.

    5 min slot · Any Level · Lightning Talk

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you maintain a project's tutorials and want them tested automatically the way a new user would follow them.

    1. 0:32 Aman Singh says a broken quickstart could be a user's first and last interaction with a young project like Drasi, which he helps maintain.
    2. 1:15 He describes giving the job to an AI agent acting as a beginner, with one key instruction: do not fix anything, report the gap instead of hiding it.
    3. 2:14 He explains the setup: the tutorial's Dev Container runs in a weekly GitHub Actions workflow with GitHub Copilot CLI and Playwright, and a failing run files a GitHub issue with the evidence.
    4. 3:20 He shows a tutorial where every command succeeded and CI was green, but the output was missing a name because the query read the wrong field.
    5. 4:09 He says the same prompt and workflow, with minimal changes, found gaps in the Dapr Agents and Radius getting started guides.
