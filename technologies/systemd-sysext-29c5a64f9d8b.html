    Extending the Immutable OS: Adding Tools to Flatcar with Systemd-Sysext

    Jan Bronicki

    Jan Bronicki, a Flatcar Container Linux maintainer, explains that an immutable OS has no package manager for adding software to the read-only /usr. He describes systemd-sysext as a signed, verifiable overlay on /usr for things like GPU drivers or Kubernetes binaries, and shows how it is declared in Butane.

    5 min slot · Level not listed · Lightning Talk

    Kubernetes internals and runtimesDelivery, GitOps and release safety

    Watch this if: You run or are considering an immutable node OS and wonder how to add drivers or debugging tools to it.

    1. 0:46 Jan Bronicki says the core of an immutable OS, such as /usr, cannot be changed and is verifiable, meaning the kernel can check whether someone tampered with it.
    2. 1:19 He says package managers such as apt or dnf do not exist on such a system, which raises the question of how to get your software onto it.
    3. 1:48 He says systemd-sysext creates an overlay on top of /usr to add a particular runtime version, a GPU driver or anything else needed.
    4. 2:48 He says the key part is that a sysext is not a random blob of binaries: it plugs into the immutability and verification system, so tampering would not go unnoticed.
    5. 3:13 He shows a Butane config that declares which sysext version to fetch from where, says offline sources work, and says the binary is linked into /usr at boot.
