    5,000 Nodes in Minutes, Twice in a Week: A Pattern for Fleet-Wide Node Changes

    Alex Yuskauskas

    Alex Yuskauskas describes patching the Copy-Fail and Dirty Frag kernel CVEs across NVIDIA's fleet with NodeWright, a controller he maintains for changing node operating systems. His main point is to ship every node change together with a check that fails when the change did not work, declared as a Kubernetes resource so kubectl shows the rollout status.

    5 min slot · Advanced · Lightning Talk

    Accelerators and workload schedulingDelivery, GitOps and release safety

    Watch this if: you need to roll out a kernel or OS change to every node and prove it actually took effect.

    1. 0:18 Alex Yuskauskas recounts the Copy-Fail CVE workaround: a one-line modprobe drop-in file plus unloading the module with rmmod.
    2. 0:45 He explains the catch: if the module is in use, rmmod silently leaves it loaded, so nodes look fixed but are not until they reboot.
    3. 1:20 He says the NodeWright package ships the change and its check in the same image, and the check only passes once the module is gone from /proc/modules.
    4. 2:26 He describes rollout status as a fixed set of values (complete, in progress, erroring, blocked), which let the SRE team write an agent skill that stops and asks a human when a cluster does not complete.
    5. 3:05 He says they ran it across 16 clusters with thousands of nodes in half an hour, then folded Dirty Frag into the same package so the next CVE is a YAML change.
