    Breaking Things Safely, Finding Bugs Before They Find You: Fuzzing Metal³ Through Controlled Chaos

    Moshiur Rahman

    The speaker explains how the Metal3 project is starting to use fuzz testing on small, fast targets such as parsers and validation functions, and stresses that each target needs a clear expected behavior. He runs three Bare Metal Operator fuzz targets in a GitHub Actions workflow and says the project is at an early stage with many targets still to add.

    30 min slot · Level not listed · Session

    Observability and reliabilityKubernetes internals and runtimes

    Watch this if: you maintain Kubernetes controllers and want a practical starting point for adding fuzz tests without flooding maintainers with noise.

    1. 5:49 The speaker names the components in scope, the IP address manager, the Cluster API provider, Bare Metal Operator, and Ironic Standalone Operator, and says he is not claiming they all have the same fuzzing coverage.
    2. 7:28 The speaker says a fuzzer does not know which unusual results are wrong, so each target needs an oracle such as no panic, a required invariant, or an expected error.
    3. 13:03 The speaker lists good first targets: parsers, decoders, validation paths, input normalization, and small deterministic functions with a clear expected behavior.
    4. 18:46 In a live run, the speaker starts a one-minute workflow with three Bare Metal Operator fuzz targets and explains that the reported new interesting inputs mean new code paths, not faults.
    5. 25:38 The speaker gives current target counts per component and his estimate of how many more each needs, and invites new contributors to start with the least covered ones.

    Metal3 Project Update! Whats New and Exciting?

    Kashif Khan

    Kashif Khan, a Metal3 maintainer, explains how the project describes physical servers as Kubernetes resources and provisions them into clusters, and lists what recent releases shipped. He says the roadmap covers switch and network automation, multi-tenancy and a more stable Bare Metal Operator API, and that the project is aiming for CNCF graduation.

    5 min slot · Level not listed · Lightning Talk

    Kubernetes internals and runtimesAccelerators and workload scheduling

    Watch this if: you run Kubernetes on bare metal and want a five-minute update on what Metal3 shipped and what is planned.

    1. 0:26 Khan says Metal3 manages bare metal hosts through Kubernetes APIs: you describe a server as a resource, apply it, and it joins the cluster as a node with no SSH or manual steps.
    2. 1:51 Khan says the project moved from sandbox to incubating last year, has more than 100 contributors, and runs in production at Ericsson, Red Hat, SUSE and Mirantis.
    3. 2:25 Khan says Cluster API Provider Metal3 moved to the v1beta2 API and that Ironic 39 now comes bundled through the standalone operator, so OpenStack Ironic does not need a separate deployment.
    4. 2:48 Khan highlights security work on the provisioning path: TLS and authentication, stricter URL validation, image digest pinning and fuzz testing in CI.
    5. 3:16 Khan says top-of-rack switch management is in progress, and that multi-tenancy will let teams share one hardware pool while BMC credentials stay with the infrastructure admins.
