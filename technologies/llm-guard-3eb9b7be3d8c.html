    BurritoBot Said Let's Dance, the Platform Said No

    Whitney Lee, Michael Forrester

    Whitney Lee and Michael Forrester let the audience attack a deliberately unprotected burrito-ordering chatbot that is wired to MCP tools and runs on a Kubernetes-based internal developer platform. They then switch on Kubernetes guardrails and LLM-specific guardrails in stages and explain which control they say stopped each attack.

    30 min slot · Any Level · Session

    Security, identity and policyAI agents and automationPlatform engineering and developer experience

    Watch this if: you want to see prompt injection and tool poisoning against a chatbot on Kubernetes, and which guardrail the speakers use against each.

    1. 2:16 The speakers invite the audience to break a live BurritoBot that they say has no guardrails, warning that submitted prompts can be shown on screen.
    2. 7:29 Whitney talks the bot into revealing the fictional CEO's home address, which she says is stored in a Kubernetes secret the bot should not be able to read.
    3. 15:08 Whitney turns on the Kubernetes guardrails with one command and says it adds Kyverno, KubeArmor, RBAC and network policy, then maps each one to the attack it blocked.
    4. 19:29 Michael shows a support ticket with hidden instructions that makes the bot deploy an app, which he calls prompt injection in a trusted system, before turning on the AI guardrails.
    5. 28:21 Michael explains a poisoned get-weather MCP tool whose description makes the bot read an internal config, and says the MCP gateway's classifier removes the tool from the tool set.
