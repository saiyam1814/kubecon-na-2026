    Gone in 60 Minutes: Effectively Close the Exploitable Window with Detection as Code

    Ben Hirschberg, Constanze Roedig

    Ben Hirschberg and Constanze Roedig show two ways to detect exploitation with Kubescape in the hours between a vulnerability becoming public and a patch being deployed, both shipped to the cluster as YAML through GitOps. Hirschberg writes rules from published indicators of compromise, and Roedig uses behavior profiles to flag deviations when the attacker's methods are not yet known.

    30 min slot · Any Level · Session

    Security, identity and policyDelivery, GitOps and release safetyObservability and reliability

    Watch this if: you need a way to detect exploitation of a newly disclosed vulnerability in running workloads before a patch can be rolled out.

    1. 2:19 Hirschberg describes the setup: the Kubescape node agent with eBPF sensors and a rule engine whose detection rules are written in CEL, with alerts sent to Slack.
    2. 6:16 In a recorded demo he pastes the indicators of compromise from a published write-up of the poisoned Trivy GitHub Action into an AI agent, which opens a pull request with Kubescape detection rules that Argo CD syncs to the cluster.
    3. 9:32 Roedig introduces what she calls a software bill of behavior, a custom resource listing allowed capabilities, network traffic, executables and file opens as composable fragments that can be signed separately.
    4. 11:56 She says build runners are a poor fit for anomaly detection because their behavior is not bounded, then shows a profile-based setup still flagging the same indicators as the rules did.
    5. 16:54 For a PHP server that normally spawns shells, she says the profile caught the exploit because the id command ran outside the expected process tree, and argues a good profile has as few entries as possible.
