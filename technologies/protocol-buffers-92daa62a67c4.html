    etcd from 3.7 to 3.8 and Beyond

    Siyuan Zhang, Marek Siarkowicz, Ivan Valdes Castillo, Nont Thanonchai W, Jeffrey Ying

    The SIG etcd maintainers give project updates, describe the RangeStream feature and dependency cleanup in etcd 3.7, and outline performance work planned for 3.8 such as non-blocking defragmentation, an index rewrite and compression. They also report on the etcd-operator's move away from StatefulSets and take audience questions about operator maturity and compression.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimesData, storage and stateObservability and reliability

    Watch this if: you run etcd or large Kubernetes control planes and want to hear from the maintainers what 3.7 changed and what 3.8 is aiming for.

    1. 2:34 Ivan Valdes Castillo says the project aims to support at least the latest three minor versions and gives the current patch levels of 3.5, 3.6 and 3.7.
    2. 6:28 Jeffrey Ying explains that RangeStream splits a very large range request into chunks sized by bytes instead of key count, which he says keeps etcd memory use more consistent.
    3. 9:06 Ying says RangeStream with concurrent decoding gave about two to three times the throughput for watch cache initialization, and that both are on by default in Kubernetes 1.37 and etcd 3.7.
    4. 15:33 Marek Siarkowicz says non-blocking defragmentation has landed for 3.8 and does most of its work in the background instead of locking the database for tens of seconds.
    5. 18:10 Nont says the etcd-operator stopped using StatefulSets and now manages pods directly, because StatefulSets got in the way of recovering from partial and full cluster failures.

    From Consumers to Contributors: How Growing Open Source Members Transformed Our ML Platform Team

    Tolga Tuncoglu, Herik Webb

    The speakers, who lead ML training platforms at Capital One, describe how their teams went from maintaining internal forks of Kubeflow Pipelines to fixing problems upstream and holding maintainer roles in the project. They share the three changes they made, the contribution numbers they attribute to the shift, and examples from Argo Workflows, OAuth2 Proxy and Notebook Intelligence.

    30 min slot · Any Level · Session

    Community and open source adoptionPlatform engineering and developer experience

    Watch this if: You run a platform built on open source projects you only consume and want to hear how one enterprise team made the case for contributing upstream.

    1. 3:58 Tolga Tuncoglu says that after Kubeflow Pipelines moved to v2 their tenants were not ready, so the team kept internal forks and struggled to keep them in sync with upstream.
    2. 5:32 He describes a high-severity protobuf CVE as the turning point: they fixed the upstream CI for the legacy version, shipped a release there and stopped maintaining the fork.
    3. 7:46 Tuncoglu lists the three things they changed: time for upstream work in sprints, asking whether a fix can go upstream first, and recognizing upstream contributions.
    4. 12:15 He says their share of human-merged pull requests in the project went from 5% to 48%, and that 71% of pull requests to release branches come from Capital One.
    5. 16:50 Herik Webb says they chose Netflix's Notebook Intelligence to add AI tooling to their Jupyter platform, talked to its maintainers and contributed 242 pull requests over six months.

    SIG API Machinery in the Era of AI: Updates

    Joe Betz

    Joe Betz reviews a year of work in Kubernetes SIG API Machinery, from contributor trends to API server performance, resilience and controller improvements. He covers the storage version migrator, internal type and protobuf cleanups, declarative validation with its linter, manifest-based admission policies and client library updates, then outlines what comes next.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimes

    Watch this if: you build Kubernetes APIs, CRDs or controllers and want to know what changed in the API machinery underneath them.

    1. 1:38 Betz says PRs to the SIG rose about 50% this year, which he links to AI-assisted development, while reviewer capacity stayed roughly flat.
    2. 7:21 Betz says the storage version migrator has finally landed, so CRD authors can migrate stored objects and eventually retire conversion webhooks.
    3. 12:14 Betz explains that making internal types match the preferred serving version lets the Go compiler skip needless copies during conversion.
    4. 14:45 Betz shows declarative validation, where tags on API types generate validation code, plus a linter that catches mistakes such as a field marked both required and optional.
    5. 17:10 Betz describes a tool to detect backward-incompatible CRD changes and manifest-based admission policies loaded at API server startup that users cannot bypass or modify.
