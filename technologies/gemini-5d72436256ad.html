    Agent Substrate: Open Layers for Agentic Systems

    Jaana Dogan, Dmitry Berkovich, Tim Hockin, Eitan Yarmush, Luiz Scheidegger

    The speakers describe Agent Substrate as a way to run many stateful agents on Kubernetes by snapshotting idle sandboxes and resuming them when work arrives. They introduce a bridge for Claude Managed Agents and show attendees sending agents on missions in a virtual KubeCon.

    7 min slot · Level not listed · Keynote

    AI agents and automationKubernetes internals and runtimes

    Watch this if: you want a live example of running many stateful agents on Kubernetes and waking them only when they have work.

    1. 1:29 Dogan says the stateful, bursty nature of agent systems calls for workload resumption and security guardrails beyond what Google had in Borg and Kubernetes.
    2. 2:12 Berkovich describes Agent Substrate's design goals: isolated sandboxes with agent identity but no credentials, high density, and fast wake-ups that preserve state.
    3. 2:46 The speakers explain how Agent Substrate snapshots memory and disk before suspending idle workloads and resumes them on custom workers when needed.
    4. 4:04 Scheidegger announces the Agent Substrate Bridge for Claude Managed Agents, then shows a virtual KubeCon where attendees can send their agents on missions.
    5. 5:44 Dogan says the live demo was running on a single Google Kubernetes Engine cluster with about 24 nodes and about 65 agents per node.

    Evolution of Agentic Networking Stack in Envoy

    Boteng Yao, Yan Avlasov

    Two Envoy maintainers from Google describe what they are adding to Envoy for AI traffic: an AI protocol manager with its own filter chains, MCP support and a REST-to-MCP bridge. They also introduce Agent Router with a Python SDK and outline a roadmap that includes semantic routing and pluggable policy engines.

    10 min slot · Level not listed · Session

    Networking and connectivityAI agents and automation

    Watch this if: You run Envoy and want to hear from its maintainers what is being built into the proxy for LLM, MCP and agent traffic.

    1. 0:52 Yan Avlasov says Envoy has been integrated into continuous security scanning by frontier models.
    2. 3:40 Boteng Yao introduces an AI protocol manager with AI filter chains, which he describes as an "L8" layer for model extraction, schema validation, model routing, guardrail callouts and transcoding between providers.
    3. 6:26 He says Envoy is committed to tracking the latest MCP spec, including the move to stateless MCP, with routing by tool, spec validation, RBAC and ext_authz authorization, and a built-in bridge that exposes a REST API as an MCP server.

    5. 8:55 Yan Avlasov lists the roadmap for the next year: semantic routing, pluggable policy engines for agent governance, more model providers, advanced inference routing and hardening against frontier-model scans.

    Kubernetes Solutions for Agent-Shaped Problems

    Tim Hockin, Dmitry Berkovich

    Tim Hockin and Dmitry Berkovich of Google say agent workloads are bursty, run untrusted code and have a human waiting, which makes one sandboxed pod per agent session wasteful and slow on Kubernetes. They present Agent Substrate, an open source system built on Kubernetes that suspends idle agents to snapshots and resumes them on request, and spend the second half answering audience questions about policy, autoscaling, memory and where it fits.

    30 min slot · Any Level · Session

    AI agents and automationKubernetes internals and runtimes

    Watch this if: you run or plan to run many agent sessions on your own Kubernetes clusters and want the reasoning behind Agent Substrate from its authors, plus a long Q&A on its current limits.

    1. 0:47 Hockin and Berkovich name three traits of agent workloads: they are bursty and mostly idle, they run untrusted code that must be sandboxed, and a human is usually waiting for the response.
    2. 6:57 Hockin states the three design principles of Agent Substrate (security by default, near-zero cost for idle agents, fast wake-up) and what he calls aspirational goals: billions of agents per cluster, 10,000 activations per second and wake-up in about 100 milliseconds.
    3. 9:16 Berkovich defines the five terms: an actor runs one agent session, an actor template configures it, a worker is the pod that hosts actors, a node-level manager handles images and snapshots, and a network layer routes requests in and applies policy to traffic out.
    4. 13:06 He explains resume speed through layers: volumes always survive, while root filesystem changes and the memory snapshot are reused only if the OCI image is unchanged, otherwise the actor cold starts from its volumes.
    5. 15:26 Hockin describes a use case they see often: a managed agent service runs the agentic loop while the work it triggers runs in Agent Substrate inside the customer's own cluster, where it can be audited and shut off.
