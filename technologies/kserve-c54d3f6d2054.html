    Building Reproducible AgentOps Pipelines with Kubeflow and MLflow

    Alyssa Goins, Ana Biazetti

    The speakers say multi-turn agent loops drive up inference cost and propose a repeatable model compression pipeline as one answer. They demo a Kubeflow Pipelines workflow that serves a model with KServe, benchmarks it, compresses it and benchmarks it again, with the runs tracked in MLflow.

    13 min slot · Level not listed · Session

    Unclassified

    Watch this if: You want a worked example of a Kubeflow Pipelines run that compresses a model and compares benchmarks before and after.

    1. 1:04 The speaker proposes a continuous optimization flow that compresses models with pipelines, which she says cuts hardware footprint and latency.
    2. 4:25 The speaker lists the pipeline steps, which are ingesting the base model, a baseline evaluation, compression, deployment with KServe and a final validation.
    3. 6:36 The speaker shows the compression step, which she says uses GPTQ quantization with a W8A8 scheme and outputs a metrics artifact and the compressed model.
    4. 9:27 The speaker says the 2.17 release of Kubeflow Pipelines added an MLflow plugin that uploads pipeline runs to MLflow automatically.
    5. 11:13 The speaker reports that the compressed model had three times faster time to first token, double the request throughput and 37% of the memory footprint.

    Cache Me If You Can: LLM Inference with llm-d (with fun drawings)

    Alexa Griffith

    Alexa Griffith says adding inference replicas only helps if requests reach pods that have capacity or can reuse cached work. She walks through how llm-d picks endpoints, queues workloads, and tests those choices against latency and throughput goals.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: You run inference on Kubernetes and want to decide whether cache-aware routing, offload, or queue policy is worth tuning.

    1. 4:10 Griffith walks one request through llm-d's filter, score, and pick sequence, explaining how the router estimates which pods already hold a matching prefix.
    2. 8:43 Griffith says offloading the key-value cache to CPU memory can avoid recomputing it for long-lived requests, at the cost of slower access.
    3. 9:13 Griffith describes splitting prompt processing from token generation and notes that the two stages then have to transfer cached state.
    4. 14:07 Griffith explains how priority bands choose which class goes first and how separate fairness and ordering policies govern work within a band.
    5. 23:58 Griffith recommends choosing a tuning change based on a measured symptom, then benchmarking it against a small baseline before adding more configuration.

    Reduce vLLM Pod Cold Starts with KServe Kernel Caching

    Jooho lee, Vishwa Hiren Gandhi

    The speakers explain how GPU kernel compilation can slow vLLM startup even when model weights are already cached. They describe KServe's approach for sharing signed kernel caches across pods and report what changed in their benchmark.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: Your vLLM replicas scale slowly even after you have cached the model weights.

    1. 4:33 The speakers break down a baseline vLLM startup of about 250 seconds and say the compilation step accounts for roughly 35 seconds, excluding image pulls and model downloads.
    2. 5:38 The speakers explain why a new replica can compile kernels again even after another pod has compiled them: the new pod does not inherit the previous pod's local cache.
    3. 10:31 The speakers propose packaging compiled kernels as a signed OCI artifact in a registry so another node can verify the signer before making the cache available.
    4. 13:52 The speakers distinguish a workload fingerprint that identifies where a cache came from from a compatibility fingerprint that checks whether compilation settings match.
    5. 18:24 In one benchmark, the speakers report that reusing the cache cut startup from 160 to 110 seconds and compilation from about 35 seconds to just over one second.
