    Scaling Across the Horizon: Dynamic Hardware Composability for Distributed LLM Inference via CoHDI

    Hidetsugu Sugiyama

    Hidetsugu Sugiyama, a CoHDI maintainer, describes how the project composes GPUs and CXL memory from shared pools onto Kubernetes hosts and how he plans to use it for LLM inference spread across sites. He outlines running prefill and decode at different sites linked by an all-photonics optical network, and using pooled CXL memory to run decode nodes with fewer GPUs.

    5 min slot · Level not listed · Lightning Talk

    Accelerators and workload schedulingAI inference and serving

    Watch this if: you plan GPU and memory capacity for LLM inference and are curious about composable hardware and splitting prefill and decode across sites.

    1. 0:12 Hidetsugu Sugiyama says CoHDI stands for Composable Hardware in Disaggregated Infrastructure and that it now supports CXL memory as well as GPUs.
    2. 0:25 He names three components, a composable DRA driver, a dynamic device scaler and a composable resource operator, which he says compose devices from GPU and CXL memory pools through a Redfish API.
    3. 0:56 He says large-scale LLM inference suffers from resource imbalance and over-provisioning because hardware configurations are fixed, and presents CoHDI as designed for that problem.
    4. 2:12 He describes transferring KV cache between a prefill site and a decode site over an open APN optical network, combining GPU-direct RDMA with the network so that, in his words, two distant sites operate as if next to each other.
    5. 3:47 He says decode nodes can be deployed with fewer GPUs and large CXL memory, which he says reduces GPU cost and power consumption at the decode site.
