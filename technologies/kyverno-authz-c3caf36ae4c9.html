    Integrating Envoy AI Gateway and Kyverno Authz for Realtime Governance of LLM and MCP Traffic

    Jim Bugwadia, Deepak Goel

    Deepak Goel explains why enterprises put Agent Router, which he says was formerly called Envoy AI Gateway, between agents and their models and MCP tools, and Jim Bugwadia shows Kyverno Authz plugging into it through Envoy's external authorization protocol. In a live demo, Kyverno allows or blocks MCP tool calls by asking the Kubernetes API whether the calling user has the matching RBAC permission.

    25 min slot · Level not listed · Session

    Security, identity and policyNetworking and connectivityAI agents and automation

    Watch this if: You route LLM and MCP traffic through an Envoy-based gateway and want tool calls authorized against the Kubernetes RBAC you already have.

    1. 2:57 Deepak Goel says that once many agents, models, users and sessions are involved, enterprises need a layer between agent and model for routing, security, observability and token cost, which is what Agent Router provides.
    2. 8:51 Jim Bugwadia explains Envoy's two plugin protocols: external authz returns allow or deny on a request, while external processing also sees the response, which he says matters because an MCP server's reply can carry a prompt injection.
    3. 10:04 He says Agent Router already has JWT authentication, MCP session management, CEL checks and quotas, but not policy as code with reporting and exception management, which Kyverno adds.
    4. 15:56 In the demo, a tool call by user Alice against another team's namespace is blocked because Kyverno ran a Kubernetes SubjectAccessReview and RBAC denied it.
    5. 18:02 After he adds a role binding for Alice, the scale call that failed earlier goes through, and he then shows the policy report Kyverno generated for the blocked calls.
