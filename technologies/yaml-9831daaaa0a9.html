    Filter, Transform, Route: Mastering OTTL in the OpenTelemetry Collector

    Evan Bradley, Edmo Vamerlatti Costa, Jamie Danielson, Tyler Helmuth

    Evan Bradley, Edmo Vamerlatti Costa, Jamie Danielson, and Tyler Helmuth teach how to filter, transform, and route telemetry with the OpenTelemetry Collector. They debug statements against sample data, work through a trace pipeline, and show how to build a Collector with a custom function.

    80 min slot · Any Level · Tutorial

    Observability and reliability

    Watch this if: You write Collector pipelines and want to debug a condition, normalize fields, or route a subset of spans without losing the original trace.

    1. 4:14 The presenters explain why the Collector moved from component-specific conditions to a shared transformation language.
    2. 12:53 The presenters compare three ways to debug a statement: inspecting emitted telemetry, tracing individual evaluations, and testing in the OTTL playground.
    3. 30:16 The presenters use AI-related spans to show why processing order matters when some spans need a separate destination but the full trace also needs to be preserved.
    4. 37:01 The presenters use the OpenTelemetry Collector Builder to scaffold a custom Collector and explain where a custom transform function fits.
    5. 53:36 The presenters use ottl.run to demonstrate renaming legacy HTTP attributes to the current semantic-convention names.

    Introducing go-yaml's New Plugin System

    Ingy döt Net

    Ingy döt Net, a co-creator of YAML who now leads maintenance of go-yaml, shows the plugin system in go-yaml v4, which he says lets an application change how YAML is loaded without changing the spec. He runs live examples of plugins for importing files, aliases across documents and tab indentation, and also tours his related projects YAMLScript, YAML Schema and YAMLStar.

    30 min slot · Any Level · Session

    Platform engineering and developer experience

    Watch this if: you maintain Go software that reads YAML and have wanted imports, custom tags or other behavior the standard loader does not give you.

    1. 3:39 He runs go-yaml v4's alias data and function tag plugins live: an import tag loads a separate vars file into an anchor, so shared values no longer have to appear in the output document.
    2. 6:29 He walks through the loader's phases (read, scan, parse, compose, resolve, construct) and shows that the resolver gives every untagged node a tag, which is what the plugins hook into.
    3. 13:53 He tells how the widely used go-yaml/yaml was archived in 2025 and how, working with Dims, the Kubernetes fork's patches were folded into the new yaml/go-yaml, which he says Kubernetes now uses.
    4. 16:58 He defines a plugin as a piece of the library that people want different behavior from, moved behind an API, and says it lets the core team try ideas before they go into the spec.
    5. 25:03 He demos tab-indented YAML loading through a plugin, then says the parser itself can be swapped and shows a CSV parser he wrote in YAMLScript.

    Minting Your Own Tokens: The Server Side of the Token Economy

    Suraj Deshmukh, Nilekh Chaudhari

    Suraj Deshmukh and Nilekh Chaudhari walk through vLLM deployments on Kubernetes, from a single GPU to a model split across two nodes. They compare throughput and first-token latency and explain how GPU memory and interconnects influence the deployment choices.

    80 min slot · Beginner · Tutorial

    AI inference and serving

    Watch this if: You want to deploy a model with vLLM and understand what changes when it no longer fits on one GPU.

    1. 15:18 The presenters inspect the running single-GPU deployment and show where the GPU request is specified in the vLLM configuration.
    2. 22:07 The presenters explain the difference between prefill, which processes the prompt and produces the first token, and decode, which generates the rest of the reply.
    3. 37:59 The presenters raise benchmark concurrency from one request to four and discuss why higher aggregate token throughput need not mean a shorter wait for each user.
    4. 53:21 The presenters animate how tensor-parallel workers exchange partial results at each layer and discuss why GPU interconnect speed matters.
    5. 1:07:01 The presenters introduce LeaderWorkerSet's leader and worker pattern before showing how they configure pipeline parallelism across two nodes.

    OptimizationJob: Hyperparameter Optimization at Scale with Kubeflow Trainer

    Aniket Shaha, Ricardo Aravena

    The speakers present OptimizationJob, a new Kubeflow Trainer API that they say runs hyperparameter tuning with each trial as a TrainJob and no second system to install. They explain how it grew out of Katib, play a recorded demo, and list the limits of the first alpha phase and the roadmap.

    20 min slot · Level not listed · Session

    Accelerators and workload scheduling

    Watch this if: You tune hyperparameters on Kubernetes and want to know what the new OptimizationJob API in Kubeflow Trainer does today and what it leaves out.

    1. 3:13 The speaker says Katib works but means two installs, two APIs and metrics that live outside the job.
    2. 3:51 The speaker says the change that made this possible was putting training metrics in the TrainJob status, so tuning can live inside Trainer.
    3. 12:13 The speaker says trials are just TrainJobs, so they reuse runtimes, JobSet and gang scheduling, and each trial is queued by Kueue like any other.
    4. 13:04 The speaker says phase one is small on purpose, with random search, one objective, alpha feature gates that are off by default, and YAML only.
    5. 14:17 The speaker lays out the roadmap in three buckets, which are smarter search, more resiliency and a Python SDK.
