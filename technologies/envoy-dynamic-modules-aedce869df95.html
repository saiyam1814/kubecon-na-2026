    Evolution of Agentic Networking Stack in Envoy

    Boteng Yao, Yan Avlasov

    Two Envoy maintainers from Google describe what they are adding to Envoy for AI traffic: an AI protocol manager with its own filter chains, MCP support and a REST-to-MCP bridge. They also introduce Agent Router with a Python SDK and outline a roadmap that includes semantic routing and pluggable policy engines.

    10 min slot · Level not listed · Session

    Networking and connectivityAI agents and automation

    Watch this if: You run Envoy and want to hear from its maintainers what is being built into the proxy for LLM, MCP and agent traffic.

    1. 0:52 Yan Avlasov says Envoy has been integrated into continuous security scanning by frontier models.
    2. 3:40 Boteng Yao introduces an AI protocol manager with AI filter chains, which he describes as an "L8" layer for model extraction, schema validation, model routing, guardrail callouts and transcoding between providers.
    3. 6:26 He says Envoy is committed to tracking the latest MCP spec, including the move to stateless MCP, with routing by tool, spec validation, RBAC and ext_authz authorization, and a built-in bridge that exposes a REST API as an MCP server.
    4. 7:28 He introduces Agent Router and a new Python SDK that he says lets developers define model policies and failover without having to understand Envoy.
    5. 8:55 Yan Avlasov lists the roadmap for the next year: semantic routing, pluggable policy engines for agent governance, more model providers, advanced inference routing and hardening against frontier-model scans.

    Extending Envoy for Secure, Scalable Connectivity

    Basundhara Chakrabarty, Hong Sng

    Two Databricks engineers describe using Envoy with Rust dynamic modules to route to and isolate a large, churning fleet of per-tenant microVMs that run AI apps. They say one custom cluster replaced a cluster per workload at the regional ingress, and that a multi-tenant Envoy on each node mediates all ingress and egress for the sandboxes.

    10 min slot · Level not listed · Session

    Networking and connectivitySecurity, identity and policy

    Watch this if: You need Envoy to route to very large numbers of short-lived, per-tenant workloads and are considering Rust dynamic modules.

    1. 1:38 Basundhara Chakrabarty describes two Envoy layers: a regional ingress Envoy where scale is the concern, and a single multi-tenant Envoy per data plane node where tenant isolation and policy enforcement are the concern.
    2. 2:24 She says a route and cluster per microVM does not scale, because each churn event triggers CDS updates that are expensive on Envoy's single main thread.
    3. 3:07 She describes the alternative: one custom dynamic module cluster written in Rust that gets endpoint snapshots over EDS and runs a chain of pluggable load balancers.
    4. 4:38 She says moving service discovery work off Envoy's main thread into the Tokio runtime was probably the single biggest win for reaching millions of workloads per region.
    5. 7:01 Hong Sng says the same dynamic modules run in a separate filter chain per tenant, each with its own connection pool and cryptographic identity, which he says let a couple of engineers move from single-tenant to multi-tenant in months.
