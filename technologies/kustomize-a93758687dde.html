    GitOps Without You Writing YAML: How Flux Grounds AI Agents in Real APIs

    Stefan Prodan

    Stefan Prodan argues that AI agents struggle more with Kubernetes YAML than with code because they lack a fast way to verify it, and presents the Flux Schema CLI plugin, a public catalog of custom resource schemas and an MCP server that he says give agents that feedback loop without a live cluster. He also describes the GitOps agent skills the Flux maintainers wrote and evaluated, and closes with the Flux roadmap and how to contribute to the catalog.

    30 min slot · Level not listed · Session

    Delivery, GitOps and release safetyAI agents and automation

    Watch this if: you use AI coding agents to write Kubernetes or Flux manifests and want to see how the Flux maintainers validate and ground that output.

    1. 1:01 Stefan Prodan says his conclusion from the Flux team's experiments is that generating YAML is harder for AI than generating code, because agents can test code in a fast loop but have no equivalent check for configuration data.
    2. 8:47 He introduces Flux Schema, a Flux CLI plugin that he says reproduces the Kubernetes API's validation rules offline, including label value rules and SOPS-encrypted secrets, and works on any Kubernetes YAML, not only Flux repositories.
    3. 13:27 He describes a public MCP server built on the project's ecosystem catalog of controller schemas, which he says reached one million requests a day and sees similar traffic from Codex, Claude and Copilot.
    4. 17:03 He says returning full OpenAPI schemas made agents hallucinate in long sessions, so the MCP server now exposes a grep schema tool that returns a compact format, after which he could generate hundreds of manifests.
    5. 26:48 He says the first agent skills were built with frontier models and failed on quantized open models he ran at home, so the team rewrote them, and he advises evaluating skills on weaker models.

    Robust CI as a Safety Net: Moving Fast at Scale with AI-Generated GitOps

    Arthur Vardevanyan, Jennifer Weir

    Arthur Vardevanyan and Jennifer Weir describe how Ford checks GitOps changes from engineers, dependency automation, and coding agents. They explain how a Go-based validator traces affected overlays, checks Kubernetes semantics, and reports actionable findings in a single pull request comment.

    30 min slot · Advanced · Session

    AI agents and automationDelivery, GitOps and release safety

    Watch this if: You review Kubernetes GitOps changes and want CI to catch plausible-looking YAML that would behave incorrectly in a cluster.

    1. 6:23 The speakers describe replacing a multi-task pipeline with one Go binary and selecting files and overlays based on what the pull request changed.
    2. 8:58 The speakers distinguish checks on raw YAML from semantic checks on rendered overlays, after earlier syntax and lint gates.
    3. 12:22 The speakers explain that the pipeline reads validation hooks from the main branch by default and requires maintainer approval to test a modified hook.
    4. 13:52 The speakers describe porting Kubernetes API server admission rules and checking their upstream implementations for drift.
    5. 17:59 The speakers show a pull request report that groups the findings and includes the CLI command an engineer can use to reproduce the run locally.

    The Next Generation of Kyverno — Unified Policy as Code at Scale

    Jim Bugwadia, Justin Munoz

    Jim Bugwadia explains why Kyverno moved from its own policy language to CEL-based policy types, how to migrate before the legacy types are removed in 1.20, and what the project plans next. Justin Munoz describes how his platform team at Kinexys by J.P. Morgan adopted Kyverno for namespace baselines, certificate rotation, permission tightening and change-window checks on Argo CD syncs, and shares the lessons the team took from it.

    30 min slot · Level not listed · Session

    Security, identity and policyAI agents and automation

    Watch this if: you run Kyverno and need to plan the move to CEL-based policies, or want to see how a regulated platform team uses it beyond admission control.

    1. 3:36 Jim Bugwadia says Kyverno chose CEL because it is the native policy language in Kubernetes, compiled and fast, and that Kyverno adds reporting, exceptions and policies for existing resources on top of the built-in admission policy types.
    2. 9:52 Justin Munoz describes using Kyverno to watch for newly issued certificates and trigger rolling restarts of deployments that cannot reload them on their own.
    3. 11:57 He describes a policy that intercepts Argo CD sync events and allows them only when a custom resource shows an approved change management window is open, with a precise denial reason otherwise.
    4. 13:34 He shares lessons learned: start in audit mode, treat the denial message as the user interface, make the paved path compliant by default and ship policy through the normal software lifecycle.
    5. 16:09 Bugwadia says release 1.20 removes the older policy types but leaves their CRDs in place so old policies show as not ready, and that 1.21 will remove the CRDs as well.

    What's New with Kubectl and Kustomize … and How You Can Help!

    Eddie Zaneski, Yugo Kobayashi, Maciej Szulik, Marly Salazar

    The SIG CLI maintainers walk through the past year of Kustomize and kubectl changes, including kuberc, KYAML and the move from SPDY to WebSockets. They then describe ideas they are still working on, ask for contributors, and take audience questions on drain flags and multi-cluster commands.

    30 min slot · Level not listed · Session

    Kubernetes internals and runtimesDelivery, GitOps and release safety

    Watch this if: you use kubectl or Kustomize daily and want to know what changed, what is planned, and where a first contribution is easiest.

    1. 5:18 Yugo Kobayashi says AI contributions have raised the number of open Kustomize PRs and that he is preparing an AI contribution guide: state when AI was used, generated code is acceptable, but AI is not to be used for communication with maintainers.
    2. 7:25 Marly Salazar covers kuberc, which she says now includes command aliasing and a credential plugin allowlist, and the maintainers say it has fully graduated.
    3. 10:35 Maciej Szulik explains new node lifecycle conditions for maintenance, which he says were published in 1.37 and are being added to kubectl drain as an alpha behind a feature flag.
    4. 14:42 Eddie Zaneski describes the idea of a CRI-native copy API to replace the tar-based kubectl cp, which the maintainers say has a long history of path traversal CVEs.
    5. 20:37 The maintainers say Kustomize is kept alive by one maintainer and ask users to get their employers to let them contribute.
