    Agentic Inference at Scale

    Maroon Ayoub, Sean Horgan

    Maroon Ayoub and Sean Horgan describe how llm-d serves agentic sessions, which they say read far more input than they generate, by routing to cached context, offloading KV cache and splitting prefill from decode. They show production examples of zero-downtime router rollouts and flow control, and outline the Agentic Inference SIG's plans for session-level orchestration.

    20 min slot · Level not listed · Session

    AI agents and automationAI inference and serving

    Watch this if: You serve coding agents or other long multi-turn LLM sessions on Kubernetes and care about cache hit rates.

    1. 0:36 Maroon Ayoub says agentic sessions send far more input than output, around a hundred to one, so avoiding recompute unlocks hardware capacity.
    2. 2:46 He describes a production case where prefill compute fell from 16% to 4% while traffic doubled, after fixing how vLLM handled a timestamp Claude Code injects into each turn's system prompt.
    3. 6:26 He explains how the llm-d router balances prefix cache affinity against load-aware routing to avoid hot spots.
    4. 10:44 He shows a production router rollout where the new router loads a state snapshot, takes over traffic and the old one drains with zero errors.
    5. 13:38 Sean Horgan outlines the Agentic Inference SIG's work on orchestrating whole sessions rather than single requests.

    AI-Aware Traffic Management: Scaling Inference with Istio Ambient Mesh

    Hannah Olukoye, Mofesola Babalola

    An engineering manager and an engineer describe how they would run AI inference traffic through Istio ambient mesh while keeping GPU spend and security under control. They say an endpoint picker that knows which backend holds a cached prompt beats plain load balancing from the second turn onward, and they report a bug they hit when combining it with ambient mTLS.

    Length not listed · Level not listed · Type not listed

    Unclassified

    Watch this if: You plan to put LLM inference behind Istio ambient mesh and care about cache-aware routing and per-team token tracking.

    1. 0:52 Hannah Olukoye says load balancing that treats every request alike regardless of token count is a core problem for inference traffic.
    2. 1:25 She compares a per-pod Envoy sidecar at about 135 megabytes of memory with ztunnel in ambient mode, which she says stays at about seven megabytes for the whole node.
    3. 4:52 Mofesola Babalola says AI repeats the old layer 7 load-balancing problem, because routing should account for which pod holds the context, GPU capacity and KV cache state.
    4. 5:46 He shows test results comparing Istio with and without the endpoint picker and says the difference appears from the second turn, once a backend has the prompt cached.
    5. 6:39 He says the endpoint picker expects a pod IP and port but received a mesh address under ambient mTLS and fell back to round robin, so he opened pull requests to Envoy and Istio.

    From GPU to Fleet. The llm-d KV Cache Hierarchy

    Vita Bortnikov, Nishtha Jain

    Vita Bortnikov and Nishtha Jain describe how llm-d and vLLM keep KV cache across GPU memory, CPU memory, local disks, network storage and peer-to-peer transfers between pods. They present benchmarks they say show storage offloading only holds up at scale when it is paired with storage-aware routing in the llm-d router.

    20 min slot · Level not listed · Session

    AI inference and servingData, storage and state

    Watch this if: You run LLM inference on Kubernetes and want to understand KV cache offloading tiers and cache-aware routing.

    1. 1:51 Vita Bortnikov says agentic workloads read far more than they write, with long inputs and short outputs, and cites up to 95% KV cache reuse.
    2. 4:44 She describes the offloading connector contributed upstream to vLLM, which tiers KV cache from GPU to CPU to storage, while llm-d handles orchestration and eviction.
    3. 7:15 She explains peer-to-peer KV cache transfer between nodes, used when the node holding a prefix is busy and for prefill/decode disaggregation.
    4. 12:15 Nishtha Jain introduces the third tier, shared network storage such as parallel file systems, which she says takes KV cache from gigabytes and terabytes to petabytes.
    5. 19:18 She calls storage offloading without storage-aware routing a failure at scale, citing throughput falling from about 2,500 to 700 tokens per second at 800 users when the router's storage index was off.

    Reduce vLLM Pod Cold Starts with KServe Kernel Caching

    Jooho lee, Vishwa Hiren Gandhi

    The speakers explain how GPU kernel compilation can slow vLLM startup even when model weights are already cached. They describe KServe's approach for sharing signed kernel caches across pods and report what changed in their benchmark.

    30 min slot · Any Level · Session

    AI inference and serving

    Watch this if: Your vLLM replicas scale slowly even after you have cached the model weights.

    1. 4:33 The speakers break down a baseline vLLM startup of about 250 seconds and say the compilation step accounts for roughly 35 seconds, excluding image pulls and model downloads.
    2. 5:38 The speakers explain why a new replica can compile kernels again even after another pod has compiled them: the new pod does not inherit the previous pod's local cache.
    3. 10:31 The speakers propose packaging compiled kernels as a signed OCI artifact in a registry so another node can verify the signer before making the cache available.
    4. 13:52 The speakers distinguish a workload fingerprint that identifies where a cache came from from a compatibility fingerprint that checks whether compilation settings match.
    5. 18:24 In one benchmark, the speakers report that reusing the cache cut startup from 160 to 110 seconds and compilation from about 35 seconds to just over one second.
