    CoHDI: Bridging Kubernetes and Disaggregated Memory for Memory-Aware LLM Inference

    Naoki Oguchi, Hidetsugu Sugiyama

    Naoki Oguchi and Hidetsugu Sugiyama present CoHDI, a CNCF Sandbox project they describe as letting Kubernetes attach pooled CXL memory and GPUs to worker nodes on demand, with a focus on giving LLM inference more room for KV cache. They walk through the allocation sequence for an LMCache pod, share early measurements, and outline plans to split prefill and decode across sites connected by an optical network.

    30 min slot · Advanced · Session

    Data, storage and stateAI inference and servingAccelerators and workload scheduling

    Watch this if: you run LLM inference on Kubernetes and want to see how pooled CXL memory could be attached to nodes as an extra KV cache tier.

    1. 2:50 Oguchi says KV cache capacity needs to scale independently from GPU compute, after listing the drawbacks he sees in adding GPUs, adding local DRAM, or evicting the cache to storage.
    2. 6:47 Oguchi explains the CoHDI flow: a scheduled pod triggers composition, the Dynamic Device Scaler evaluates the GPU and CXL memory needed, and the Composable Resource Operator requests them from the pool and attaches them to the worker node.
    3. 11:52 Oguchi shows cache metrics where resubmitting the first prompt raises the blocks read from the second tier from 105 to 135, which he reads as KV cache kept in CXL memory being reused.
    4. 12:44 Oguchi reports first-stage results in which attached CXL memory was 10 times faster than SSD for random reads and 18 times faster for writes, and says LMCache still needs optimization for CXL access.
    5. 18:27 Sugiyama says GPU overprovisioning at the decode site remains a problem and describes decode nodes with few GPUs and large CXL memory pools composed by CoHDI as his answer.

    Composing Inference on Kubernetes: Gateway, Schedule, Serve, Observe

    Karena Angell, Alex Chircop

    Karena Angell and Alex Chircop argue that production inference on Kubernetes is too often built as a closed vertical stack, and present gateway, scheduling, serving and observability as separate layers joined by explicit interfaces. They go through six kinds of composability, show recorded lab runs of several traffic shapes and component swaps, and close with questions for teams to ask of their own clusters.

    30 min slot · Any Level · Session

    AI inference and servingNetworking and connectivityObservability and reliability

    Watch this if: you are building a shared inference platform on Kubernetes and want a way to decide which layer owns routing, admission, serving and tracing so that parts can be swapped later.

    1. 3:15 Angell says the biggest trap they see in production is building separate silos for chat, RAG and agents, which duplicates routing, scheduling and telemetry for what she describes as one nested workload.
    2. 14:16 Chircop separates admission from routing: he says a scheduler such as Kueue decides once whether pods can exist under quota and fairness rules, while the endpoint picker chooses which replica serves each prompt, using signals such as queue depth and a warm KV cache.
    3. 17:02 Chircop says the OpenTelemetry GenAI semantic conventions give components a shared vocabulary for spans and metrics, and W3C trace context propagation joins them into a single trace across the hops.
    4. 18:45 Angell cites Hugging Face moving Text Generation Inference into maintenance mode, and says teams that kept serving behind a gateway API contract could swap engines quickly while others had to rework their client apps.
    5. 27:13 Chircop narrates recorded lab runs in which gateways are swapped while routing live traffic, llm-d's endpoint picker is replaced by the reference picker for the Gateway API Inference Extension, and the scheduler is changed between Kueue, Volcano and KAI Scheduler.

    From Black-Box to Auditable AI-Grid: A Deterministic Governance Layer with Hybrid Cloud

    Fatih E. Nar, Andrew Hendrickson

    The speakers outline a governance layer for AI recommendations in communication networks that makes the decision process auditable without requiring identical model wording. They describe how versioned evidence, policy gates, and energy measurements could feed into decisions about network operations.

    30 min slot · Beginner · Session

    AI agents and automationSecurity, identity and policy

    Watch this if: you need to explain what evidence and policy allowed an AI-assisted decision in a regulated network.

    1. 4:58 Hendrickson says fixing the input, rule version, and evidence snapshot should make it possible to reconstruct the rules, evidence, and citations behind a decision.
    2. 10:33 Nar distinguishes using AI to improve network operations from using network infrastructure to host new AI workloads.
    3. 14:35 Nar walks through classifying intent, retrieving evidence, constraining reasoning with rules, synthesizing a result, and blocking an action if there is no supporting citation.
    4. 20:19 Nar cites Open Policy Agent and Kyverno for policy and describes using Git to keep track of models, rules, and standards.
    5. 24:19 Nar proposes using Kepler to measure power at host, platform, and workload levels so operators can weigh power use against service commitments.

    TAG Operational Resilience: Shaping the Future Through Initiatives

    Alolita Sharma, Saiyam Pathak, Nabarun Pal, Diana Todea, Niki Manoledaki

    The chairs and tech leads of the CNCF Technical Advisory Group for Operational Resilience explain the group's charter and walk through its open initiatives, from project release guidelines and scale testing guidance to observability personas, business continuity and AI sustainability papers. They describe how initiatives are proposed and reviewed in the CNCF TOC repository and ask for contributors and reviewers.

    30 min slot · Level not listed · Session

    Community and open source adoptionObservability and reliability

    Watch this if: you work on reliability, observability or sustainability and want to see which CNCF operational resilience initiatives are open and where they need help.

    1. 4:12 Alolita Sharma reads the group's charter: to define and advance good practices and standards for resilient, observable and efficient cloud native systems beyond the initial development cycle, which she sums up as production readiness.
    2. 8:17 Nabarun Pal presents the Project Release Guidelines initiative, which studies release patterns across CNCF projects to produce guidelines and reference implementations; he says a white paper draft is pending and needs reviewers.
    3. 10:30 Pal says the TOC asked the group for scale and performance testing guidance to use in its due diligence for incubation and graduation, and that the work is about to start by collecting data from projects.
    4. 11:51 Diana Todea describes an ongoing reference framework for levels of service reliability automation, meant to show how reliability tasks move from manual work toward autonomy.
    5. 15:02 Niki Manoledaki shows the cloud native AI sustainability foundations and framework paper, written with TAG Infrastructure, which she says is almost ready to publish and covers measuring power use with tools like Kepler.
