    From Proxy to Platform: Building a Multi-Tenant AI Gateway

    Dibyo Mukherjee, Tushar More

    The speakers describe how Adobe turned an internal model proxy into a shared gateway with team-scoped access and self-service configuration. They explain how customer-facing agents changed the way they attributed spending and which safeguards they put around platform upgrades.

    30 min slot · Any Level · Session

    AI inference and servingNetworking and connectivity

    Watch this if: several teams need to share an AI gateway without sharing model access, logs, or spend limits.

    1. 6:46 The speakers explain how teams share a gateway while using separate model deployments, cloud accounts, and scoped keys.
    2. 8:23 They walk through a console that lets tenant admins add models and set fallback rules and budgets without a platform ticket.
    3. 11:08 They explain how internal applications provide a customer identity so budgets and rate limits can follow the customer rather than a shared agent key.
    4. 14:13 They describe adding a seven-day wait before promoting releases from development to production and running API contract tests on development upgrades.
    5. 15:54 They describe using KEDA to scale the proxy by in-flight requests and setting a grace period to let requests drain during rollouts.
