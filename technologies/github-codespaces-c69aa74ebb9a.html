    Autoscaling Reality Check: The Hands-On HTTP Optimization Challenge

    David Pech

    David Pech runs a hands-on tutorial in which attendees benchmark HTTP services in NGINX, Go, PHP and Java with k6 and watch how autoscaling reacts, first with the CPU-based Horizontal Pod Autoscaler and then with Knative scaling on concurrent requests. He walks through each round on a Grafana dashboard and describes the tuning he tried, including cases where he says his own improvement failed.

    80 min slot · Any Level · Tutorial

    Accelerators and workload schedulingObservability and reliability

    Watch this if: you run HTTP services behind HPA or Knative and want to see, round by round, where autoscaling lags behind real traffic.

    1. 10:11 The speaker lays out the lab: Argo CD, Istio, Knative and a Prometheus stack on a local k3d cluster or GitHub Codespaces, with k6 load tests run against services in several flavors.
    2. 29:15 In the NGINX round scaled on CPU, the speaker shows on the dashboard that pods stay at the maximum after the load falls and that latencies remain, and asks the room why.
    3. 36:23 The speaker explains Knative's panic window: when demand jumps well above the estimate the autoscaler enters panic mode and does not scale down during it.
    4. 1:03:46 For the Java round the speaker says slow startup limits how fast scaling can react, names GraalVM as one option, and shows a tuning attempt that he says failed completely.
    5. 1:06:13 In the scale-to-zero round the speaker points out that a workload at zero has no metrics, which he says makes alerting on it hard.

    Sandboxing on Kubernetes with WebAssembly: A Hands-on Tutorial

    Eric Gregory, Bailey Hayes

    Eric Gregory and Bailey Hayes use wasmCloud and Kubernetes to show how WebAssembly components get explicit permissions for the resources they need. In the workshop, they start with an agent that has no tools and add capabilities one at a time, then show a separate scaling benchmark.

    80 min slot · Beginner · Tutorial

    Kubernetes internals and runtimesSecurity, identity and policy

    Watch this if: You want to see a WebAssembly sandbox on Kubernetes and how to grant an agent tool only the access it needs.

    1. 6:18 The speakers explain the deny-by-default model and show where the wasmCloud operator schedules a workload onto a host pod.
    2. 23:14 The speakers introduce the workshop's scripted model and explain why it makes the effect of sandbox permissions easier to distinguish from model behavior.
    3. 37:40 The speakers build an optional Rust component and inspect the WebAssembly interfaces it imports for HTTP and filesystem access.
    4. 56:36 The speakers demonstrate a narrow GitHub integration for triaging pull requests and explain how the host plugin keeps the sign-in token out of the workload.
    5. 1:03:56 The speakers switch from the single-instance workshop to a recorded density test and explain the resource constraints they encountered while scaling on Kubernetes.

    The Most Boring Talk at KubeCon - And the One That Will Save Your Job

    Lev Andelman, Regina Voloshin, Cortney Nickerson, Julie Gunderson

    In this tutorial, Lev Andelman, Regina Voloshin, Cortney Nickerson and Julie Gunderson argue that internal developer platforms need disaster recovery planning like production systems, and introduce hands-on GitHub Codespaces labs that break and recover Backstage, Argo CD and Kyverno. The recording covers the introductions and closing advice on ownership, communication, change freezes and chaos engineering, while the lab time itself is not shown in detail.

    80 min slot · Advanced · Tutorial

    Observability and reliabilityPlatform engineering and developer experienceDelivery, GitOps and release safety

    Watch this if: you run Backstage, Argo CD or Kyverno and have never tested recovering them.

    1. 4:07 Lev asks the room who has a portal, GitOps, policy as code and an RTO and RPO for their platform, then who has ever tested recovering it, and finds one person.
    2. 7:22 Lev says that when Backstage's Postgres database dies, some data can be repopulated from configuration but other data is lost for good, and asks what happens when version control, authentication or object storage is unavailable.
    3. 12:11 Regina calls creating Argo CD applications directly with the CLI or kubectl an anti-pattern, because losing the Argo CD cluster then loses the declarative source of truth.
    4. 15:29 Regina recommends ApplicationSets, Argo CD managing its own configuration, one bootstrap app, and regular disaster recovery drills on a non-production cluster.
    5. 21:40 Cortney says a Kyverno failure hurts because it sits on the path of every change, can fail in two directions, and rarely looks like a Kyverno problem.

    Your Quickstart is Broken – AI Agents as Synthetic New Users

    Aman Singh

    Aman Singh describes how the Drasi maintainers use an AI agent as a synthetic new user that follows their tutorials exactly and reports where the docs and the real output differ. He walks through the setup with Dev Containers, GitHub Actions, GitHub Copilot CLI and Playwright, and shows bugs it found in Drasi, Dapr Agents and Radius tutorials.

    5 min slot · Any Level · Lightning Talk

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you maintain a project's tutorials and want them tested automatically the way a new user would follow them.

    1. 0:32 Aman Singh says a broken quickstart could be a user's first and last interaction with a young project like Drasi, which he helps maintain.
    2. 1:15 He describes giving the job to an AI agent acting as a beginner, with one key instruction: do not fix anything, report the gap instead of hiding it.
    3. 2:14 He explains the setup: the tutorial's Dev Container runs in a weekly GitHub Actions workflow with GitHub Copilot CLI and Playwright, and a failing run files a GitHub issue with the evidence.
    4. 3:20 He shows a tutorial where every command succeeded and CI was green, but the output was missing a name because the query read the wrong field.
    5. 4:09 He says the same prompt and workflow, with minimal changes, found gaps in the Dapr Agents and Radius getting started guides.
