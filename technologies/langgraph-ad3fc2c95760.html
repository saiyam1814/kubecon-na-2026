    The Identity Crisis: Who is the AI Agent in Your Cluster?

    Abdel Sghiouar

    Abdel Sghiouar argues that agents sharing a Kubernetes service account are hard to distinguish when something goes wrong. He proposes short-lived SPIFFE identities, gateways for authorization, and sandboxing, with humans setting policy instead of approving every action.

    10 min slot · Level not listed · Keynote

    AI agents and automationSecurity, identity and policy

    Watch this if: you need to separate agent identity, authorization, and runtime isolation when designing a Kubernetes platform.

    1. 1:23 Sghiouar says it is hard to predict which tools or endpoints an agent will call, and argues that a shared Kubernetes service account makes it hard to trace an incident to a particular replica.
    2. 2:40 Sghiouar distinguishes agents acting for a human from agents triggered autonomously, and argues the latter need a unique, short-lived identity tied to their task.
    3. 3:29 Sghiouar proposes SPIFFE and SPIRE for giving agents short-lived identities at runtime, potentially scoped to a replica or session.
    4. 4:15 Sghiouar says identity does not answer authorization and discusses using a gateway to evaluate what an agent wants to do before it accesses an external resource.
    5. 8:09 Sghiouar urges platform engineers to move from human approval of each action to human-defined governance that sets boundaries for what agents can do.

    The Race to Standardize AI Observability

    Liudmila Molkova, Trask Stalnaker

    The speakers show a demo application whose two services emit AI telemetry in three different schemas, and argue that a shared protocol without a shared structure breaks cost tracking and evals. They present the OpenTelemetry GenAI semantic conventions, the common instrumentation layer, and a Weaver-based conformance suite, and say stabilizing the conventions is their top priority.

    30 min slot · Any Level · Session

    Observability and reliabilityAI agents and automationAI inference and serving

    Watch this if: you instrument LLM or agent applications and want to know where the OpenTelemetry GenAI conventions stand and how to check your telemetry against them.

    1. 6:10 The speaker shows a token-count query over traces that reports two model calls when the demo made at least three, and says a dashboard built on it would not match the provider bill.
    2. 10:38 The speaker says each message in the conventions has a role and a list of parts, so attribute values share one shape as well as one name.
    3. 14:28 The speaker describes a common layer that traces, measures, and logs every inference call the same way, leaving each library as a thin wrapper.
    4. 22:30 The speaker shows a conformance report for one Python SDK, with a column per instrumentation and a row per convention attribute, where the basics line up and gaps appear beyond them.
    5. 26:45 The speaker says they want a first release candidate covering inference, agents, and tools this year and hope to stabilize it by KubeCon Europe next year.

    Your Agent Needs a Platform: Cloud Native Infrastructure for Multi-Agent AI Systems

    Soham Ghadge

    Soham Ghadge describes problems he met running AI agents in production, such as crashes midway through a task, rate limits, repeated model calls and poor visibility, and maps each one to existing cloud native tools. He proposes defining agents as Kubernetes custom resources, saving each model call as a Dapr workflow step, queueing tasks through NATS JetStream and tracing with OpenTelemetry.

    30 min slot · Advanced · Session

    AI agents and automationPlatform engineering and developer experience

    Watch this if: you are building multi-agent systems and want a short overview of which cloud native tools cover crash recovery, queueing and tracing.

    1. 2:35 Ghadge lists his mapping of agent problems to tools, starting with describing each agent as a Kubernetes object through a CRD.
    2. 3:38 Ghadge shows a simplified agent definition as a Kubernetes object, with replicas, maximum tasks per copy and what the agent reads from and writes to.
    3. 7:00 Ghadge says to put every AI model call inside a saved step so that after a restart Dapr reuses the saved answer instead of paying for the call again.
    4. 7:39 Ghadge describes an agent queue, which he compares to a Redis queue, so agents do not handle every request directly.
    5. 9:48 Ghadge's conclusion is to treat an agentic system like a distributed system and agents like microservices.
