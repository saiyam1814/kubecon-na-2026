Talk summary

Andjelko Iharos of HAProxy Technologies argues that sending inference to vendor APIs takes sensitive data out of your control, and that in-cluster inference can be routed with the HTTP data plane you already run. He covers routing on the model field in the JSON body and consistent hashing across GPU clusters to protect KV caches during maintenance.

Watch this if:

you are bringing LLM inference in-house and want to route it with the load balancer you already run.

Key points from the speaker

  1. 0:10 Andjelko Iharos says that when AI arrives, sensitive requests such as documents and prompts with customer data start leaving your stack without visibility: "your cluster is sovereign, your AI isn't."
  2. 1:11 He argues you do not need a new gateway for in-cluster inference, because an inference request is plain HTTP, a method, a path and a JSON body, so the data plane you already run can route on the model field.
  3. 1:58 He says routing on the model gives back observability and control, letting you log a request, pass it on or change its destination, and points to HAProxy, an open source project you may already run.
  4. 2:45 He explains keeping requests on the same GPU cluster to reuse the KV cache, and using consistent hashing so a cluster under maintenance affects only itself.
  5. 4:06 He says you can swap models with a config change instead of a vendor migration, with no new software stack, and notes this year is HAProxy's 25th anniversary.
