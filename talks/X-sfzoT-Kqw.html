Talk summary

The SIG Scheduling speakers explain how the Kubernetes scheduler handles pod groups, nested workloads, and topology constraints. They describe plans for sharing scheduling logic with autoscalers and letting Kueue focus on quotas and fair sharing.

Watch this if:

you want to understand how Kubernetes evaluates groups of pods and where autoscalers fit.

Key points from the speaker

  1. 8:45 The speakers explain why gang scheduling needs to work alongside the lifecycle for individual pods in the same scheduler.
  2. 19:52 They walk through a pod-group scheduling attempt that uses one snapshot for all pods in the group.
  3. 23:15 They show an example where a failed second pod leaves the group below its minimum, so the scheduler reverts the first placement.
  4. 26:43 They illustrate trying the same pod group against multiple topology options to see which placements are feasible.
  5. 31:07 They describe the read-only scheduler library as a way for callers to test a hypothetical placement with the same logic as the live scheduler.
