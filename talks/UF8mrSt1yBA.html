Talk summary

The speakers, from Red Hat and Adobe, describe how an Adobe private cloud team that ran virtual machines on VMware is moving to OpenShift Virtualization and adopting the GitOps practices Adobe's public cloud Kubernetes platform, Ethos, already used. They cover the team's shift from click-driven operations to Git, architectural decision records kept in a repository, and lessons about working across storage, network and platform teams.

Watch this if:

You are moving virtual machines from VMware to a Kubernetes-based platform and want to hear how one team changed its ways of working along the way.

Key points from the speaker

  1. 6:23 Mike Wilson says the move was a business decision, not a technology one: after Broadcom acquired their main platform provider, Adobe chose OpenShift Virtualization and set a mandate to exit by 2028.
  2. 7:34 Wilson says the team's first instinct was to make the new platform feel as much like VMware as possible, and that they later moved to declarative, cloud native practices built on Kubernetes, Open Cluster Management, Argo CD and KubeVirt.
  3. 14:22 Wilson describes adopting architectural decision records in Git after decisions kept being reopened, and shows a cluster naming record with its proposed, accepted, rejected and superseded states.
  4. 16:39 He says the decision record repository was structured so AI agents can review it, for example checking whether a new implementation matches the recorded architectural intent.
  5. 24:03 Wilson says they have five production clusters and need to deploy around 60 more next year, using Open Cluster Management as the factory and a Cluster API provider so Ethos can target the private cloud.
