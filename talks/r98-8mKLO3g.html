Talk summary

The Gateway API maintainers walk through what they say changed up to version 1.7, including promoted TCP and UDP routes, HTTPRoute retries reaching the standard channel, and experimental telemetry policy, session persistence on the Backend resource, pre-routing filters and ClusterTrustBundle references. They also describe the agentic networking subgroup's access policy for MCP traffic, stricter conformance rules, and an initiative they call Gateway for AI and Agents to consolidate the AI-related subgroups.

Watch this if:

you run or implement Gateway API and want the maintainers' rundown of the 1.6 and 1.7 features and where the AI and agent traffic work is heading.

Key points from the speaker

  1. 5:07 Ricardo Katz says the 1.6 release focused on layer 4, promoting TCPRoute and UDPRoute so different ports on one IP can forward to different backends, and that port ranges are not supported yet.
  2. 10:19 Evaline Ju says the agentic networking subgroup's access policy lets you control which agents can call which MCP tools, using identity-aware policies based on SPIFFE IDs or service accounts.
  3. 14:46 Grant Spence says session persistence moved to the new Backend resource to avoid having two APIs for one thing, and that in 1.7 a Backend can select in-cluster pods by label.
  4. 18:23 He describes experimental pre-routing filters that run at the listener level before route selection, in strict order, and in 1.7 support only external auth and implementation-specific extensions.
  5. 25:23 Norwin Schnyder says conformance requirements are being tightened and that the 1.8 release is planned to remove the partial conformance level.
