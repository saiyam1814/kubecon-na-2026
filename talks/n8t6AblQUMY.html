Talk summary

Diana Zawadzki and Shijie Sheng of Uber's Cadence team argue that agent workflows fail like any other workflow and describe wrapping model and tool calls as Cadence activities so a replacement worker can resume from recorded history. They show a demo of an error-analysis agent that survives a rate limit and a killed worker, share numbers from Uber's Agent Executor Service, and answer questions on Temporal, guardrails and operating Cadence.

Watch this if:

you run long-lived AI agents in production and want to see how a workflow engine can let them resume after crashes instead of starting over.

Key points from the speaker

  1. 1:02 Zawadzki explains the model: each model call is a Cadence activity, the workflow is the code that orders them, and progress is recorded in a separate service so a replacement worker can reuse completed results.
  2. 5:31 She says Uber's Agent Executor Service, built in July, hosted around 830,000 agentic workflows on Cadence in September for background and scheduled jobs.
  3. 8:19 Sheng demos an error-analysis agent with a human in the loop: a rate-limited log fetch is retried automatically, a human signal asks for more evidence, and after the worker is killed a new worker replays history to the current state.
  4. 12:33 Zawadzki says the protected run in their demo used about half the model responses and tokens of the raw run with zero new calls during recovery, while cautioning that failures were injected on purpose.
  5. 18:36 Asked how Cadence compares with Temporal, the speakers say Temporal forked from Cadence in 2019 and describe Cadence as the more community-driven CNCF project.
