Talk summary

Cecil Wöbker describes how remberg moved from hand-written Grafana dashboards to scripts in CI that generate per-team dashboards, loaded into the cluster by the Grafana sidecar. He lists the mistakes his engineers ran into, including kube-state-metrics label allow lists, series that change across pod restarts and JSON that Grafana ignores.

Watch this if:

you want engineers to ship their own dashboards as code and avoid common mistakes.

Key points from the speaker

  1. 0:58 Cecil Wöbker says remberg's two hand-written Grafana dashboards were painful to keep current, so they were broken about half the time.
  2. 1:56 He describes scripts in CI/CD, often written with AI, that generate individual dashboards for each team based on the services it owns.
  3. 2:38 He explains the deployment: CI commits the script output, a labeled ConfigMap marks it as a dashboard, and the Grafana sidecar loads it automatically.
  4. 3:30 His first caveat: kube-state-metrics does not export all labels by default, so labels used for joins or filters must be on its allow list.
  5. 4:37 He warns that valid JSON is not always valid for Grafana and that AI tends to add fields from outdated docs, so dashboards still need checking.
