Talk summary

Prschita Prschita and Raj Bhensadadia show how an incident investigation agent can produce a plausible diagnosis by citing evidence from the wrong service or deployment. They rerun the same simulated incident with evidence checks and discuss where to put guardrails before a diagnosis or remediation goes out.

Watch this if:

you are building incident investigation agents and want their diagnoses to cite evidence you can verify.

Key points from the speaker

  1. 9:13 The speakers set up a simulated incident in the OpenTelemetry Astronomy Shop by constraining CPU for the recommendation service.
  2. 10:15 They run the incident agent without checks on its tool results or draft diagnosis to establish a baseline.
  3. 13:43 They show how the agent cited a real latency metric but attributed it to the wrong service.
  4. 19:50 They rerun the same incident with checks on query results, individual claims, and the final draft, using Prometheus, the service graph, and Kubernetes as evidence.
  5. 24:10 They suggest dry runs, auditing, human approval, and rollback as safeguards for automated remediation.
