Talk summary

The speakers show a demo application whose two services emit AI telemetry in three different schemas, and argue that a shared protocol without a shared structure breaks cost tracking and evals. They present the OpenTelemetry GenAI semantic conventions, the common instrumentation layer, and a Weaver-based conformance suite, and say stabilizing the conventions is their top priority.

Watch this if:

you instrument LLM or agent applications and want to know where the OpenTelemetry GenAI conventions stand and how to check your telemetry against them.

Key points from the speaker

  1. 6:10 The speaker shows a token-count query over traces that reports two model calls when the demo made at least three, and says a dashboard built on it would not match the provider bill.
  2. 10:38 The speaker says each message in the conventions has a role and a list of parts, so attribute values share one shape as well as one name.
  3. 14:28 The speaker describes a common layer that traces, measures, and logs every inference call the same way, leaving each library as a thin wrapper.
  4. 22:30 The speaker shows a conformance report for one Python SDK, with a column per instrumentation and a row per convention attribute, where the basics line up and gaps appear beyond them.
  5. 26:45 The speaker says they want a first release candidate covering inference, agents, and tools this year and hope to stabilize it by KubeCon Europe next year.
