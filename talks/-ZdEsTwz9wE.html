Talk summary

William Rizzo introduces Cluster API as the idea of representing a cluster as Kubernetes objects inside a management cluster, and walks through its core, infrastructure, bootstrap and control plane providers. He explains how machines map to nodes, in what order a cluster comes up, and how to try it locally with clusterctl and the Docker provider, then takes audience questions.

Watch this if:

You manage more than a few clusters by hand and want the Cluster API object model explained before you try the quick start.

Key points from the speaker

  1. 0:30 The speaker states the idea behind Cluster API: a cluster becomes a set of Kubernetes objects inside a management cluster.
  2. 0:54 He describes the controllers: the core, an infrastructure provider for where machines run, a bootstrap provider for machine configuration, and a control plane provider for etcd and the API server.
  3. 3:27 He compares a MachineDeployment to a workload Deployment, with a MachineSet in the place of a ReplicaSet and a Machine in the place of a Pod.
  4. 4:43 He says cluster creation follows a sequence in which one control plane node must be built first, because otherwise etcd cannot form its Raft consensus.
  5. 9:39 Asked about self-hosted infrastructure, he says clusterctl uses kubeadm by default but that other control plane and bootstrap providers can be chosen at init.
