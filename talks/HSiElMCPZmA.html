Talk summary

Sean Corcoran and Erin Walter describe how PlayStation replaced a centralized namespace and access workflow with separate Kubernetes custom resources. They explain how a hub controller reconciles those resources across clusters and how the team transfers ownership from its old scheduled jobs.

Watch this if:

You manage Kubernetes access across many clusters and want application teams to own access requests separately from namespace configuration.

Key points from the speaker

  1. 6:08 The speakers describe how chained pull requests repeated validations and then waited for a scheduled job to apply each change.
  2. 7:25 The speakers explain why they moved from one scheduled job per cluster to a controller in a hub cluster that applies changes downstream.
  3. 9:07 The speakers distinguish the resource that declares namespace configuration from the resource that declares who should have access and what permissions they receive.
  4. 11:38 The speakers walk through how the controller resolves a namespace reference and creates the corresponding role binding in the target cluster.
  5. 19:07 The speakers describe dry-run reconciliation that writes the generated manifest to resource status so they can inspect it before applying it downstream.
