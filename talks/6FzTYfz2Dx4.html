Talk summary

Pedro Célestin and Julia Furst Morgado present a case study in letting teams specify service objectives and using measured performance to test resource changes automatically. They describe using error budgets and production canaries to test proposed changes instead of letting an AI agent change allocation directly.

Watch this if:

You want to turn service objectives into allocation decisions without handing an AI agent direct control of production.

Key points from the speaker

  1. 2:55 The speakers translate an example latency goal into an error budget, then explain how budget burn could inform whether to add or reclaim resources.
  2. 7:20 They propose canarying a resource change, not just a new build. They explain that if more resources do not improve the service-level indicator, the cause may instead be a bad release.
  3. 9:45 They describe the division of work in their case study: developers set the service objective, while the platform tests its own allocation proposals and can keep or reverse a change based on measured results.
  4. 11:28 They say letting AI change production allocation directly did not work well for them, so they limited it to proposing changes that a production canary could verify.
  5. 13:25 They walk through their stack: Prometheus collects metrics, Argo CD deploys changes, Argo Rollouts runs canaries, and Knative is used in some cases rather than being required.
