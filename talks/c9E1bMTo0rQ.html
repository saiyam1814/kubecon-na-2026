Talk summary

Dilpreet Bindra argues that conformant Kubernetes clusters do not guarantee that applications will behave the same across environments. He introduces the Workload Conformance Working Group and describes VM API as a way to manage virtual machines through a common Kubernetes interface.

Watch this if:

Watch this if you want the distinction between Kubernetes cluster conformance, workload portability, and a common API for virtual machines.

Key points from the speaker

  1. 1:03 Bindra says cluster conformance does not guarantee that an application behaves consistently across infrastructure and configurations.
  2. 1:27 Bindra announces the Kubernetes Workload Conformance Working Group with SIG Apps and SIG Architecture, and says it will define and verify expected workload behavior.
  3. 2:30 Bindra argues virtual machines should be first-class Kubernetes resources and says declarative APIs should account for their distinct lifecycle and I/O needs.
  4. 3:08 Bindra uses Cluster API as a precedent and describes VM API as a provider-neutral interface for managing VMs without giving up hardware capabilities.
  5. 3:26 Bindra connects VM API to agent workloads that need isolation, state management, and I/O control, and says the project has joined the CNCF Sandbox.
