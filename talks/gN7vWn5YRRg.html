Talk summary

The speakers present manifest-based admission control, which loads admission webhooks and policies from files on the API server's disk so that they cannot be deleted through the Kubernetes API. They replay a made-up outage in a recorded demo and describe the feature's limits, reload behavior and release status.

Watch this if:

You operate Kubernetes control planes for other teams or customers and want guardrails that a cluster admin cannot delete.

Key points from the speaker

  1. 2:37 The speakers say a policy stored as an API object can be deleted like any other object, and that the API does not allow a policy that intercepts policies.
  2. 7:24 The speakers explain that policies are loaded from a directory on disk before the API server serves anything, the same idea as static pods.
  3. 8:55 The speakers say the feature gate was alpha in Kubernetes 1.36 and is beta and on by default in 1.37.
  4. 13:49 The speakers list the limits: no param refs, no service references, no service account tokens, and nothing that depends on the API.
  5. 16:46 The recorded demo starts on a kind cluster running Kubernetes 1.37, where the Helm upgrade, the webhook and the prune are denied.
