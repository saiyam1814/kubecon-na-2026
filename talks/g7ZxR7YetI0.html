Talk summary

Members of the CNCF End User TAB and TOC act out how a fictional air-gapped warehouse's painful rollback becomes a shared problem across user groups, a TAG initiative they call rollback readiness, and possibly project maturity guidance. They invite attendees to bring their own problems and reference architectures to a user group or TAG.

Watch this if:

you want to know how a problem your team hits can travel through CNCF user groups, TAGs and the TOC to change what projects must show.

Key points from the speaker

  1. 0:35 Daniel Moch tells a fictional story of an air-gapped warehouse with 2,000 robots where a software update pulls in a dependency with a CVE, and rolling back takes longer than hoped because recovery steps were never written down.
  2. 3:07 Alolita Sharma says the End User Technical Advisory Board has heard similar recovery stories from other groups, and that reference architectures start by comparing real experiences before taking them to the TOC.
  3. 4:55 Brandt Keller explains how the Technical Oversight Committee uses user experiences across more than 200 projects at sandbox, incubation and graduation levels.
  4. 6:00 Brandt names a "rollback readiness" initiative to test the upgrade and rollback journey, and Marlow Warnicke says a pattern that proves useful could shape maturity guidance asking projects to show supported upgrade and rollback paths.
  5. 8:25 They invite attendees to bring their own problems to a CNCF user group or technical advisory group, point to a blog post on the revamped user groups, and ask for reference architectures.
