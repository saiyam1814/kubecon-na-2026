Talk summary

Lakmal Warusawithana, an OpenChoreo maintainer presenting alone because his co-speaker could not attend, reports what his team saw after exposing their developer platform to coding agents through two MCP servers. He says the agents reached correct results by inconsistent routes, and that short Agent Skills written like onboarding for a new teammate made repeatable tasks run more directly.

Watch this if:

you have put an MCP server in front of your platform and the agents get there but waste calls on the way.

Key points from the speaker

  1. 6:13 Warusawithana says repeating the same task gave different token counts, tool calls and run times, with agents trying the wrong tool first, looping on a failing call or skipping prerequisite steps.
  2. 10:26 He shows a skill from their repository and explains that only its name and description are loaded at first, so the description is written close to the user's intent and concepts and recipes are loaded on demand.
  3. 16:10 He says documentation-style skills diluted the agent's performance and API-reference skills changed nothing because the tool list already had that information, so they wrote skills the way they would onboard a new teammate.
  4. 20:17 He says results improved by removing content such as product positioning, duplicated API references, soft warnings and edge cases, leaving SKILL.md files of roughly 28 to 121 lines.
  5. 21:51 He says skills go stale as APIs and tools change, so the team treats them as code, updating them with every release and checking them in CI.
