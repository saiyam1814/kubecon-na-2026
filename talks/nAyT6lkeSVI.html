Talk summary

Adrian Ng explains why alert fatigue grew at Verkada and shows the in-house SRE agent that replies to alerts in Slack with a root cause analysis and next steps. Rohan Sood details how it works across nine clusters, how they evaluate it, the incident mode they are building, and what they say keeps the cost near 33 cents per investigation.

Watch this if:

you are thinking of building your own alert-triage agent and want one team's design, evaluation approach and cost levers.

Key points from the speaker

  1. 6:29 Adrian says the agent handles about 4,700 alerts a month at roughly 30 cents each with a mean time to triage of about two minutes.
  2. 7:21 Rohan describes a serverless router that decides whether a Slack message is an alert and which of nine clusters owns it, then queues it for pods running an agent container, MCP sidecars and more than 80 tools.
  3. 13:37 Rohan says each team's Slack channel adds its own prompt to the base system prompt, so teams tune triage for their service by editing a markdown file.
  4. 15:00 Rohan says feedback buttons gave only about 100 clicks since April, so they run a sampled nightly replay eval that reruns alerts with a more powerful model plus live A/B tests of candidate builds.
  5. 25:45 Answering a cost question, Rohan says they keep a byte-stable prompt prefix of system prompt, channel prompt and tool schemas so most input tokens come from the cache.
