Talk summary

Shriya Chaitanya Kamat Tarcar argues that direct agent-to-agent links on Kubernetes grow quadratically and bring routing, security, observability and reliability problems. She proposes sending A2A traffic through a shared gateway such as agentgateway and shows a short example of one agent calling another through it.

Watch this if:

you are starting to run several AI agents on Kubernetes and want a five-minute case for putting a gateway between them.

Key points from the speaker

  1. 1:05 Tarcar says six agents have 15 possible direct links, 50 agents have 1,225 and 100 have nearly 5,000, so the number of links grows quadratically.
  2. 1:40 She compares this with microservices, where she says service-to-service communication is what broke at scale, and names routing, security, observability and reliability as the four challenges.
  3. 2:26 She proposes an A2A-aware gateway such as agentgateway, which she describes as built on the Kubernetes Gateway API, so that each agent connects to one hub.
  4. 3:38 She shows an A2A request going through agentgateway and points to gateway logs with the A2A method, the response and the completed task status.
  5. 4:10 She closes with three takeaways: avoid the N-squared trap, centralize A2A traffic, and build on open standards.
