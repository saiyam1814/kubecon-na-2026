Talk summary

Darian DeFalco describes how Transfix applies progressive delivery to deciding when an automated pull request can merge. He explains how shadow evaluations, per-PR test environments, and narrow, reversible grants keep the decision separate from the permission to act.

Watch this if:

You want to move from human review of every agent-written change to limited auto-merge based on observed outcomes.

Key points from the speaker

  1. 8:27 DeFalco describes how Transfix turns each task into a Kubernetes Job with a limited GitHub token and runs it only in staging.
  2. 10:57 DeFalco explains that in shadow mode the agent opens a pull request and an evaluator logs what it would do without acting on the decision.
  3. 12:12 DeFalco shows how Argo CD creates a staging namespace for a labeled pull request and removes it when the label is removed.
  4. 13:35 DeFalco says a grant covers a narrow class of changes and each new pull request still needs a passing test for that exact commit.
  5. 16:22 DeFalco describes how a reverted merge suspends automation for that repository and triggers a pull request to remove the grant.
