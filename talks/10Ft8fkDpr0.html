Talk summary

Kashif Khan and Sunnatillo Samadov, both Metal3 maintainers, present three additions to the bare metal provisioning project: multi-tenancy through host claims, failure domains that spread control plane nodes across racks, and top-of-rack switch port configuration. They show a short recorded demo of each and close with which release and feature gate each one sits behind.

Watch this if:

you run Kubernetes on bare metal and want several teams to share one hardware pool, rack-aware control planes, or switch ports configured from YAML.

Key points from the speaker

  1. 5:40 Kashif Khan names three gaps he says Metal3 had: teams sharing hardware meant handing out BMC passwords, nothing kept control planes off a single rack, and switch port VLANs were typed by hand.
  2. 6:46 Kashif Khan explains the multi-tenancy design: tenants create a HostClaim in their own namespace, and an admin-owned HostDeployPolicy in the pool namespace decides which namespaces may consume which hosts.
  3. 12:24 Kashif Khan explains failure domains: label each BareMetalHost with its rack, list the failure domains on the Metal3 cluster, and Cluster API then spreads control plane nodes across them.
  4. 17:43 Sunnatillo Samadov introduces the BareMetalSwitch and HostNetworkAttachment resources, which he says let Ironic set switch port mode and VLAN tags during provisioning and clean them up afterwards.
  5. 23:19 The speakers give the status: multi-tenancy is alpha behind a feature gate, failure domains are available in the Cluster API provider release they name, and switch configuration is behind a feature gate in the Bare Metal Operator.
