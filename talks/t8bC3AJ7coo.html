Talk summary

Three members of the Node Lifecycle Working Group describe two efforts: Specialized Lifecycle Management, which adds shared lifecycle conditions to nodes, and a declarative EvictionRequest API meant to replace one-shot API-initiated eviction. Filip Křepinský explains the requester and responder model and runs a live demo, and Lucy Sweet says Anthropic already uses eviction requests in production.

Watch this if:

you drain or upgrade nodes under stateful or long-running workloads and want to see how eviction is meant to become declarative and observable.

Key points from the speaker

  1. 3:52 Ryan Hallisey introduces node lifecycle conditions such as drain in progress and maintenance in progress, which he says merged as alpha in Kubernetes 1.37 to replace ad hoc node labels.
  2. 5:08 He names the open problem: anyone with permission can write these conditions, so two drains with different options can conflict, and the group is considering a new API to declare intent and serialize writers.
  3. 8:37 Lucy Sweet calls API-initiated eviction a point-and-shoot gun with a one-bit answer that cannot be observed until it happens, and says users build admission webhooks on top of it.
  4. 14:47 Filip Křepinský explains the responder contract: each responder reports a heartbeat within a deadline now set at 20 minutes, and one that stalls is skipped, ending with a fallback that calls the eviction API and respects PDBs.
  5. 25:38 Lucy Sweet says Anthropic uses the eviction request API in production and has issued millions of eviction requests, and that other companies have told the working group they use or plan to use it.
