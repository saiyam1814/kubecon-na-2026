Talk summary

Sara Qasmi of T-Systems shows measurements from LLM serving on two GPU server types, where she says the default Kubernetes device placement often lost bandwidth or added latency compared with hand-aligned devices. Alexander Kanevskiy of Intel explains why a NUMA number no longer describes modern CPU and PCI topology, and walks through newer Dynamic Resource Allocation features he says help express the alignment a workload needs.

Watch this if:

you place GPUs, NICs and CPUs for inference on Kubernetes and want measured examples of what device alignment changes.

Key points from the speaker

  1. 5:23 Qasmi reports that GPU and NIC pairs aligned on the same PCI root reached full RDMA bandwidth on one platform while other pairings got 38%, yet on the second platform NUMA alignment was enough.
  2. 6:50 She says the default claim picked the wrong GPU pair in five of five runs on a busy node, and that NCCL's own peer-to-peer default also limited bandwidth until it was changed.
  3. 10:08 She measures CPU to GPU round-trip latency and says default pods were 33% slower, with eight of ten landing on the wrong socket, which an NRI topology plugin corrected.
  4. 14:56 Kanevskiy argues that a NUMA number only maps to the memory controller's mode of operation and is now a virtual value that does not describe physical topology.
  5. 20:38 He presents list attributes and derived attributes in DRA as ways to describe topology and compare values across drivers, and warns that a claim with no overlapping solution leaves the pod unscheduled.
