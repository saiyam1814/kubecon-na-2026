Talk summary

Ning Liao and David Porter of Google and Evan Sheng of Anthropic present Hypercluster, a design they say splits the Kubernetes data plane into control nodes that each stand for a rack or slice of accelerators and locked-down runner hosts that run the pods. Sheng then walks through what he says Anthropic had to change to run inference on it, including service account tokens, DaemonSets, its custom scheduler and model download traffic.

Watch this if:

you run very large accelerator clusters and want to see how one design cuts node count and keeps model weights away from operators.

Key points from the speaker

  1. 7:29 Porter explains the split: a control node represents a topology domain such as a GPU rack or TPU slice, runners are the hosts with the accelerators, and only control nodes talk to the API server.
  2. 8:49 Porter describes the CRI proxy on the control node, which he says intercepts the kubelet's pod and container requests, forwards them to the right runner and reports aggregated runner health.
  3. 12:51 Porter walks through sealed mode: a runner sends a vTPM-backed attestation quote to an attestation service, and he says only then can the workload get the token for the keys that decrypt the model.
  4. 19:11 Sheng says service account tokens never reached pods on runners, so Google added a token service on every runner and Anthropic added a helper to each pod to fetch the credential.
  5. 22:21 Sheng says large model downloads were throttled by the control node's network card, so their applications now exchange addresses at startup and move high-bandwidth traffic to a secondary network.
