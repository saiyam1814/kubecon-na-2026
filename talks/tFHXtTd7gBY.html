Talk summary

Surya Seetharaman tours OVN-Kubernetes features, from egress IPs and network policies to user-defined networks, BGP integration, EVPN and virtual machine networking. She stresses that OVN-Kubernetes and Kube-OVN are separate CNCF Sandbox projects and says hardware offload to DPUs is a reason NVIDIA runs the project in production.

Watch this if:

you are choosing a Kubernetes network plugin and need tenant isolation, BGP or virtual machine networking.

Key points from the speaker

  1. 0:19 Seetharaman says OVN-Kubernetes and Kube-OVN are two separate CNCF Sandbox network plugins that both use OVN and OVS but differ heavily in architecture and features.
  2. 2:10 Seetharaman says user-defined networks let users create isolated layer 2 or layer 3 networks per tenant, which she says sets the project apart from other network plugins.
  3. 3:05 Seetharaman says a no-overlay mode uses FRR and a BGP underlay for pod-to-pod traffic instead of Geneve encapsulation, which she says increases throughput.
  4. 3:50 Seetharaman describes EVPN as an emerging feature that stretches tenant networks across Kubernetes clusters and to on-site networks that do not run Kubernetes.
  5. 4:38 Seetharaman says hardware offload moves OpenFlow and Open vSwitch processing to a DPU, and that NVIDIA uses OVN-Kubernetes in production because of it.
