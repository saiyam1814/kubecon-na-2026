Talk summary

Peter Jausovec and Eitan Yarmush of Solo.io, the two speakers heard in the recording, walk through the sandboxing approaches they tried for kagent and say each one still kept an idle agent's pod running or tied identity to the pod. They explain why kagent 1.0 was rebuilt on Agent Substrate, list five lessons from that work, and demo Claude Managed Agents sessions running in sandboxes on their own cluster.

Watch this if:

you are choosing how to sandbox AI agents on Kubernetes and want to hear what one team found lacking in pod-per-agent setups.

Key points from the speaker

  1. 3:40 Jausovec says they tried four things before Agent Substrate: their own pod-per-agent runtime, Anthropic's Sandbox Runtime, Agent Sandbox and NVIDIA's OpenShell, and that each solved only part of the problem.
  2. 9:08 Jausovec gives the reasons for Agent Substrate: idle agents are snapshotted to object storage and hold no compute, the Kubernetes API is off the hot path, restores take milliseconds, and actors are sandboxed with default-deny networking.
  3. 10:04 Yarmush tells how Solo started building an internal sandbox layer called Moat, then joined Google's Agent Substrate work instead, and says kagent 1.0 is now based entirely on Agent Substrate.
  4. 17:42 Yarmush starts the takeaways: isolation is table stakes and pause and resume is the hard part, every control must sit outside the agent, identity follows the actor, a suspended agent is stored data, and the sandbox runtime becomes a data format.
  5. 22:56 Demo: Jausovec creates two Claude Managed Agents sessions whose sandboxes run on his cluster, shows that one session cannot read the other's file, and shows a blocked request succeed after he applies an egress policy.
