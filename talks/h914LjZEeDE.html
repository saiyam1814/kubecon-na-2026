Talk summary

David Pech runs a hands-on tutorial in which attendees benchmark HTTP services in NGINX, Go, PHP and Java with k6 and watch how autoscaling reacts, first with the CPU-based Horizontal Pod Autoscaler and then with Knative scaling on concurrent requests. He walks through each round on a Grafana dashboard and describes the tuning he tried, including cases where he says his own improvement failed.

Watch this if:

you run HTTP services behind HPA or Knative and want to see, round by round, where autoscaling lags behind real traffic.

Key points from the speaker

  1. 10:11 The speaker lays out the lab: Argo CD, Istio, Knative and a Prometheus stack on a local k3d cluster or GitHub Codespaces, with k6 load tests run against services in several flavors.
  2. 29:15 In the NGINX round scaled on CPU, the speaker shows on the dashboard that pods stay at the maximum after the load falls and that latencies remain, and asks the room why.
  3. 36:23 The speaker explains Knative's panic window: when demand jumps well above the estimate the autoscaler enters panic mode and does not scale down during it.
  4. 1:03:46 For the Java round the speaker says slow startup limits how fast scaling can react, names GraalVM as one option, and shows a tuning attempt that he says failed completely.
  5. 1:06:13 In the scale-to-zero round the speaker points out that a workload at zero has no metrics, which he says makes alerting on it hard.
