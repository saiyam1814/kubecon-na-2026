Talk summary

Vinayak Goyal and Graham Helton say Kubernetes monitoring components may be granted more kubelet access than they need. They explain fine-grained authorization and recommend checking existing roles and vendor charts rather than assuming a cluster upgrade removes broad grants.

Watch this if:

You maintain Kubernetes monitoring agents and want to check whether their permissions match what they actually scrape.

Key points from the speaker

  1. 1:09 The speakers explain that the kubelet first establishes the caller's identity and then asks the Kubernetes API server whether the caller may access the requested resource.
  2. 4:15 The speakers warn that a role granted for a simple health check can also authorize far more sensitive kubelet operations.
  3. 9:30 The speakers say API server audit logs may show the authorization check for direct kubelet traffic without showing the underlying action.
  4. 13:44 The speakers explain why finer-grained kubelet permissions were added alongside the older proxy permission, rather than replacing it outright.
  5. 16:33 The speakers recommend reviewing roles for unnecessary proxy access, adopting narrower permissions or updated vendor charts, and considering network policies as another layer.
