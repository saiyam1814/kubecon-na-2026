Talk summary

Peter Jausovec, a kagent maintainer, says kagent 1.0 replaces the deployment and pod it used to create per agent with Agent Substrate workers, worker pools and actors. He says each actor is a sandboxed agent session with its own file system and identity, and that an egress gateway injects credentials so no secrets are stored inside actors.

Watch this if:

you run AI agents on Kubernetes and want to know what changed in kagent 1.0.

Key points from the speaker

  1. 0:17 Jausovec describes kagent as a CNCF project for running agents on Kubernetes, where agents, models, MCP tools and prompts are defined in YAML and applied like any other resource.
  2. 1:03 Jausovec says the biggest change in kagent 1.0 is the substrate runtime, which replaces the deployment and pod with workers, worker pools and actors.
  3. 1:17 Jausovec lists other 1.0 additions: standalone sandboxes, support for multiple harnesses that implement A2A, scheduled agent runs on a cron, and a UI refresh with shared chat sessions.
  4. 2:05 Jausovec explains that a worker is a pod and an actor is one agent session, and says thousands of sandboxed actors can run in a single worker.
  5. 2:29 Jausovec says each actor gets its own file system and cryptographic identity, and that the egress gateway swaps a placeholder for real credentials so no keys live inside actors.
