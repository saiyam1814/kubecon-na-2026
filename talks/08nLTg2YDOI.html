Talk summary

Jackie Maertens and Nilekh Chaudhari of Microsoft use a diagnostic agent that calls an MCP tool service against the Kubernetes API to show where a user's identity and permissions get lost between the agent and the cluster. They offer three assessment questions about identity, delegation and scoped authority, and demo three fixes in turn: least-privilege RBAC, tool policies at agentgateway, and passing the user's token to the gateway.

Watch this if:

you are putting an AI agent in front of your cluster and want a starting checklist for identity and permissions.

Key points from the speaker

  1. 2:48 Jackie describes two incidents, PocketOS and Replit, in which she says an agent deleted production data because it could do more than its task needed.
  2. 11:04 Jackie follows the identities in the example: Keycloak authenticates Alice, but the Kubernetes API sees only the tool service's service account, so the user sign-in does not travel with later calls.
  3. 13:17 Jackie gives three assessment questions: who the participants are, what authority they carry for someone else, and what each component can actually do.
  4. 16:22 In Nilekh's demo of the unsafe system, the agent deletes Alice's failing checkout service and Kubernetes permits it, because the user's identity stopped at the agent.
  5. 20:14 Nilekh adds agentgateway as a proxy between the agent and downstream systems, first to block the delete tool call and then to check Alice's token claims so she cannot read another team's logs.
