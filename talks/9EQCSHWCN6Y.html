Talk summary

Tim Killian describes how Snapchat moved reserved GPU capacity out of team clusters into capacity pool clusters, one per machine type, and exposes it back to customer clusters as virtual nodes built on Virtual Kubelet. He says Kueue handles quota, borrowing and preemption centrally, and reports that high priority jobs saw no longer waits while lower priority jobs waited less.

Watch this if:

scarce GPUs sit idle in one team's cluster while another team waits, and you want a design for sharing them across clusters.

Key points from the speaker

  1. 3:42 The speaker explains the decision to put each machine type in its own Kubernetes cluster and treat those clusters like cells, since everything does not fit in one cluster.
  2. 8:30 The speaker introduces Virtual Kubelet as the base for virtual nodes that stand in for remote capacity, so customers still see a normal node and a running pod.
  3. 9:56 The speaker says the team uses Kueue to decide at a granular level which workloads may land on a virtual node, with a fallback to local capacity when there is no quota.
  4. 11:36 The speaker names autoscaled inference as the hard case: HPA needs metrics from the metrics server, which has to get them from the nodes, including virtual ones.
  5. 14:52 The speaker reports the outcome: no increase in wait time for high priority jobs, a large decrease for lower priority jobs, and a cloud provider outage handled by cutting quotas.
