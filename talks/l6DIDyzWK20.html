Talk summary

Suvaansh Kumar of Guidewire Software describes how to measure the time a ManifestWork takes to travel from an Open Cluster Management hub to a managed cluster, and how to tell that it never arrived. He says the approach matches a timestamp logged on the hub with one logged by the work agent, the latter added in OCM v1.4 by Guidewire.

Watch this if:

you deploy through an OCM hub and want a simple way to measure delivery latency to managed clusters.

Key points from the speaker

  1. 0:26 Kumar says OCM is in its sixth year, is a CNCF incubating project and offers a hub-and-spoke model for deploying workloads to many clusters.
  2. 0:52 He says Guidewire used to deploy from CI/CD pipelines straight to managed clusters in different AWS regions and wants the same confidence once a hub sits in between.
  3. 2:09 He proposes an admission webhook on the hub that logs a timestamp with the ManifestWork name, managed cluster name and generation when a workload is applied.
  4. 2:34 He says the work agent on the managed cluster logs a second timestamp with the same keys when it observes the workload, a feature he says is in OCM v1.4 and was contributed by Guidewire.
  5. 3:24 He explains that if the second timestamp does not show up within a chosen timeout, the workload is treated as never having arrived.
