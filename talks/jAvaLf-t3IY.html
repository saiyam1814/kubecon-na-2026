Talk summary

Arthur Vardevanyan and Jennifer Weir describe how Ford checks GitOps changes from engineers, dependency automation, and coding agents. They explain how a Go-based validator traces affected overlays, checks Kubernetes semantics, and reports actionable findings in a single pull request comment.

Watch this if:

You review Kubernetes GitOps changes and want CI to catch plausible-looking YAML that would behave incorrectly in a cluster.

Key points from the speaker

  1. 6:23 The speakers describe replacing a multi-task pipeline with one Go binary and selecting files and overlays based on what the pull request changed.
  2. 8:58 The speakers distinguish checks on raw YAML from semantic checks on rendered overlays, after earlier syntax and lint gates.
  3. 12:22 The speakers explain that the pipeline reads validation hooks from the main branch by default and requires maintainer approval to test a modified hook.
  4. 13:52 The speakers describe porting Kubernetes API server admission rules and checking their upstream implementations for drift.
  5. 17:59 The speakers show a pull request report that groups the findings and includes the CLI command an engineer can use to reproduce the run locally.
