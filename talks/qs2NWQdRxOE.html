Talk summary

Marek Pelka and David Gohberg describe how monday.com gives coding agents isolated environments on its shared staging cluster so the agents can check their changes against real dependencies. They say the approach uses mirrord for request routing, database branching and per-agent queue splitting, and that it now also serves developers and non-technical users.

Watch this if:

You let coding agents open pull requests and want them to test changes against a real shared environment.

Key points from the speaker

  1. 1:26 Marek Pelka says agents at monday.com merged 22,000 pull requests in three months, 80% with no human touch, and frames the question of how to trust them.
  2. 3:54 He compares lightweight mocked environments with full copies of monday.com, which he says took about 30 minutes to provision and were expensive.
  3. 6:54 David Gohberg explains request-level isolation on the shared staging environment, labelling agent requests with OpenTelemetry baggage headers.
  4. 9:59 He describes using mirrord to run a changed service locally in the agent runtime while the cluster routes the agent's requests to it.
  5. 12:11 He covers shared resources: database branching, per-agent splitting of message queues, and case-by-case handling of external API side effects.
