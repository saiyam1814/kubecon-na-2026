Talk summary

The speaker describes an agent platform on Istio ambient in which agents and tools get workload identities and each user's token travels with a request, so third-party tools are called on behalf of that user. He argues that without mesh authorization policies the prompt is the only guardrail, and that the mesh, not the model, should be the security boundary.

Watch this if:

You are building an agent platform and need tool calls to carry the real user's identity, not a shared service account.

Key points from the speaker

  1. 0:18 The speaker names prompt injection, user impersonation and secret leakage as the three red flags of the agent identity problem.
  2. 0:57 He says that without workload identities in the mesh, a triage agent can reach every other agent and every tool.
  3. 2:09 He says third-party tools reached through service accounts log only the service account, so the audit trail does not show which user an agent acted for.
  4. 2:48 He describes the platform: Istio ambient with peer authentication and authorization policies, kagent and kmcp managing agents and tools with SPIFFE identities, and agentgateway checking user tokens.
  5. 4:52 He walks through the flow in which a token is minted at login, an Argo workflow sends the event and token to agentgateway, and the chosen agent calls the tool through an MCP server, REST API or CLI.
