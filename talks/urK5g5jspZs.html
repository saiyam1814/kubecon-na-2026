Talk summary

The SIG etcd maintainers give project updates, describe the RangeStream feature and dependency cleanup in etcd 3.7, and outline performance work planned for 3.8 such as non-blocking defragmentation, an index rewrite and compression. They also report on the etcd-operator's move away from StatefulSets and take audience questions about operator maturity and compression.

Watch this if:

you run etcd or large Kubernetes control planes and want to hear from the maintainers what 3.7 changed and what 3.8 is aiming for.

Key points from the speaker

  1. 2:34 Ivan Valdes Castillo says the project aims to support at least the latest three minor versions and gives the current patch levels of 3.5, 3.6 and 3.7.
  2. 6:28 Jeffrey Ying explains that RangeStream splits a very large range request into chunks sized by bytes instead of key count, which he says keeps etcd memory use more consistent.
  3. 9:06 Ying says RangeStream with concurrent decoding gave about two to three times the throughput for watch cache initialization, and that both are on by default in Kubernetes 1.37 and etcd 3.7.
  4. 15:33 Marek Siarkowicz says non-blocking defragmentation has landed for 3.8 and does most of its work in the background instead of locking the database for tens of seconds.
  5. 18:10 Nont says the etcd-operator stopped using StatefulSets and now manages pods directly, because StatefulSets got in the way of recovering from partial and full cluster failures.
