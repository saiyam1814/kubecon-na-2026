Talk summary

Jing Chen and Mert Toslali present a loop that uses agents and a CPU simulator to explore changes to llm-d, then tests candidates on GPUs before proposing them upstream. They describe a configuration mismatch that invalidated one benchmark run and report contributing three policies to the llm-d router.

Watch this if:

you tune LLM inference and want a way to narrow policy candidates before testing them on GPUs.

Key points from the speaker

  1. 3:20 Toslali introduces BLIS as a CPU-based simulator for rapidly trying policies for distributed inference before spending GPU time.
  2. 4:09 He describes an agent harness that frames a hypothesis, designs experiments, and iterates on candidate algorithms in the simulator.
  3. 6:19 Chen explains that simulation can suggest the direction of a performance change, but that hardware tests are needed to measure its size.
  4. 9:03 She recalls finding that the simulator and llm-d used different time units for saturation detection, forcing the team to discard and rerun a benchmark.
  5. 11:56 The speakers report contributing three router policies upstream after taking them from simulator experiments to real-cluster validation.
