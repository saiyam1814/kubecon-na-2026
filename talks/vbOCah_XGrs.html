Talk summary

Youmin Han and Zhuo Zhi describe why traffic splitting did not give LinkedIn the coverage it needed for cluster infrastructure releases. They show how the team combined namespace-scoped canaries, synthetic workloads, and Argo CD validation gates before promoting changes to production.

Watch this if:

You need to validate critical Kubernetes components that cannot be canaried by shifting a percentage of user traffic.

Key points from the speaker

  1. 9:39 The speakers say random traffic sampling missed GPU and job combinations and could not safely stage changes such as a shared database migration.
  2. 10:28 The speakers explain how dedicated canary instances run in the production cluster while a separate namespace directs only synthetic workloads to the new versions.
  3. 17:36 The speakers show how the Kubernetes API server matches a namespace label against webhook selectors so each pod goes through the canary or the stable admission webhook, not both.
  4. 21:30 The speakers describe using Argo CD PostSync hooks to run functional validation jobs once the canary resources are synced and healthy.
  5. 23:34 The speakers describe running the full GPU and CPU validation suites in canaries before the pipeline promotes changes to production clusters one at a time.
